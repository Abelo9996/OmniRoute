## TL;DR — OmniRoute が実際に集約する無料推論枠はどれくらいですか？

これらの数値は、カタログ全体にわたる個別のサードパーティアカウントと利用資格条件を示しています。OmniRoute 自体がこの予算を付与するわけではありません。必要なアカウントまたは認証情報を取得し、対象プロバイダーを接続して、その制限を遵守する必要があります。実際に利用可能な容量はこれより少ない場合があり、対象となるルートがない新規インストールではゼロになることもあります。`tos: avoid` と指定されたプロバイダーは、デフォルトでは自動ルーティングから除外されます。

**2026-10-08 確認済み:** [Cerebras](https://www.cerebras.ai/pricing) は、支払い方法の登録が必要で30日後に期限切れとなる、1回限りの $5 プロモーションクレジットを提供しています。[Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) はプロジェクト、モデル、ティアごとのレート制限を公開していますが、月間の主要集計値には引き続き含まれていません。

| 指標                                      | トークン / 月 | 意味                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **文書化された継続的付与量（定常時）**    | **~1.62B**    | 無料枠の**プール**（モデルごとのカタログ）で、各共有プールは**1回のみ**集計されます。`/api/free-tier/summary` とダッシュボードの「無料枠予算」ページが使用するライブデータソースです。**この数値を使用してください。**                                                                                                     |
| **+ 登録クレジットを含む初月**            | **~2.22B**    | 定常時の量 + 1回限りの登録クレジット（Z.AI 20M、DeepSeek 5M、…）で、アカウントごとに重複排除されています。**初月のみ**で、繰り返し付与されません。                                                                                                                                                                         |
| **+ 恒久無料、公開上限なし**              | _定量化不能_  | `siliconflow`、`glm-cn`（GLM-4-Flash）、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud` — 実際に継続利用でき、レートまたは同時実行数の制限はありますが、**集計可能なトークン上限はありません**。一覧には掲載しますが、合計には含めません（`RPM×24/7` で算出するような水増しは採用しません）。 |
| **+ デポジットによるロック解除分**        | **+~24M**     | OpenRouter に1回限りの **$10** をチャージすると、無料プールが1日50リクエストから1000リクエストに増加します。定常時の数値を水増ししないよう、個別に報告しています。                                                                                                                                                         |
| **+ 地域別の本人確認が必要な分**          | **+~6M**      | `modelscope`（Alibaba Cloud との連携 + 中国本土での実名認証）。実際に繰り返し付与されるクォータであり、`gatedRecurringTokens` / `gatedProviders` およびダッシュボードに表示されます。主要集計値には決して含めません。地域別の本人確認を行うことで +~6M を利用できます。                                                    |
| 理論上の上限（全レート制限、24時間365日） | ~10B          | すべてのプロバイダーのレート制限を、継続利用した場合として外挿した合計です。**保証値ではありません** — 主要な数値として掲げないでください。                                                                                                                                                                                |

**誠実な要約:** _OmniRoute は、35の無料枠プール全体で、文書化された無料トークンを**月間約1.62B**集約します（登録クレジットを含めると初月は最大約2.22B）。さらに、恒久無料で上限のない多数のプロバイダーも利用でき、RTK + Caveman 圧縮（トークンを15～95%削減）によって、その利用可能量をさらに引き延ばせます。_

> **前回の約1.94Bから減少した理由。** 2026-06-17の更新は実態に即した修正であり、損失ではありません。`gemini` はプール単位で重複排除されるようになりました（以前は各Flashバリアントを個別にカウントして水増しされていました。462M → 60M）。`cloudflare-ai` は実際の10k-Neurons/dayに修正されました（122M → 30M）。`doubao` は継続枠ではなく1回限りのサインアップクレジットに再分類され、終了したティア（`chutes`/`phind`/`kluster`）は削除されました。一方で、`llm7`（正しくは5M/day → 150M）と新しい無料プロバイダー（Kilo、OpenCode Zen、Z.AI GLM-Flash）により、減少分の一部は相殺されています。
>
> **v3.8.42でさらに約1.37Bへ修正：** `longcat` は無料プレビュー終了後、150M/moの継続付与から1回限りの10Mサインアップクレジットへ再分類されました。同じ透明性の原則に基づくものであり、誤って削除されたプロバイダーはありません。
>
> **Felo Web廃止後の2026-08-26に更新：** Felo Webは、GPL由来の来歴およびライセンスが保留中であるため除外されています。当時、ソースでは38個のプールキーが報告されていました。プール数はライブでCIによるゲートが設定されています（上記の数値が`computeFreeModelTotals()`からずれると、`check:docs-counts`がビルドを失敗させます）。
>
> **2026-09-02にプロバイダー各社のページを基に再監査**（出典：`open-sse/config/freeModelCatalog.data.ts`内の、再監査された各エントリの横にある`// evidence:`コメント）：`gemini`と`ollama-cloud`はトークン数を公開しなくなりました（Googleは2025-12-23にモデル別の無料枠テーブルを削除し、OllamaのFreeプランは「starter usage credits」とされています）。そのため現在は**上限なし**として記載され、合計には一切含まれません（−80M）。`groq`には、5つの**モデル別**200K-TPD上限（各6M、+15M）があり、廃止された3つのIDは削除されました。`nara`は1つの7M/dayバケットです（+60M、210M）。`mistral`の1Bはアカウントコンソールでのみ確認できます。Methodologyの_Evidence classes_を参照してください。
>
> **2026-09-03に修正（#11773）：** `cerebras`は、30M/moの継続付与（旧来のカード不要の1M tokens/dayトライアル）から、支払い方法を必要とする1回限りの$5サインアップクレジットへ再分類されました。LongCatと同じ透明性の原則に基づくものです。
>
> **さらにxKiroを追加（2026-09-03）：** 新しい`xkiro-free`プール（150M/mo）により、継続プールキーは35個になりました。Felo Webは、GPL由来の来歴およびライセンスが保留中であるため、引き続き除外されています。ソースが現在報告しているのは、**35個の継続プールキー**と**約1.62Bの安定供給量**です。これはライブでCIによるゲートが設定された数値です（`computeFreeModelTotals()`からずれると、`check:docs-counts`がビルドを失敗させます）。

**文書で確認できる**最大の貢献元：`mistral` 1.00B、`nara` 210M、`llm7` 150M、`xkiro` 150M、`groq` 30M（5つのモデル別上限）、`cloudflare-ai` 30M、`api-airforce` 24M。（`longcat`は除外されています。LongCat-2.0の10M付与枠は1回限りのKYC必須サインアップクレジットであり、毎月継続する予算ではありません。）

> ⚠️ 理論上の上限（約10B）は、**公開されたトークン上限がない**レート制限のみのプロバイダー（`tencent`、`siliconflow`、`nvidia`、`baidu`、`glm-cn`、`sparkdesk`）によって水増しされています。これらの数値は`RPM/TPM × 24/7 × 30d`で算出されますが、単一アカウントが継続的に達成できるものではない理論上の最大値です。そのため、信頼できる数値からは**除外**されています（代わりに「permanently free, no cap」の行に表示）。競合他社による数十億規模という主張が信頼できないのも、これと同じ水増しが原因です。

## 2026-10-15 Bytez と Nous の修正

[Bytez の請求情報](https://docs.bytez.com/model-api/docs/billing)では、Free プランで利用できるオープンモデルは
パラメーター数 7B までに制限されています。70B と 72B のエントリは、購入クレジットによる
ロック解除が必要なため削除されました。Mistral-7B は引き続き `recurring-credit` です。クレジットは
4週間ごとに更新されますが、課金は推論秒単位であり、トークン許容量は公開されていません。
不確かな数量を表すため、トークンカウンターはゼロとし、根拠のない 1M トークンという推定値を
置き換えました。これは、無料クレジットがゼロであることを意味しません。Nous の変更については、
以下のプロバイダー注記で詳しく説明しています。

## 2つのレジーム — 集計と判定

OmniRoute は、意図的に異なるソースを参照する2つのレジームを通じて、「無料か？」という問いに答えます。

| レジーム        | 信頼できる情報源                                                                                                                                                               | 対象                                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| **集計 / 表示** | 解決済みカタログ — 出荷時のベースラインに Radar フィードを重ねたもの（`getRadarCatalog`）                                                                                      | 無料枠の合計、予算カード、ダッシュボード                                                                                               |
| **判定**        | 出荷時のカタログのみ（`open-sse/config/freeModelCatalog.data.ts` の `FREE_MODEL_BUDGETS`）とローカルヒューリスティクス（`:free` サフィックス、価格がゼロ、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` のすべての利用箇所：モデルのインポート、`auto/*` ルーティング、`GET /v1/models`、ブラウザのプレビュー |

フィードが利用可能であれば、集計はいつでも改善できます。一方、判定はリリース成果物に固定されるため、ブラウザとサーバーで同一の結果となり、オフラインで再現でき、データベースなしでテストできます。ブラウザのプレビューとサーバーのインポートが異なるソースを参照すると、プレビューとクリック時の実際の動作が一致しなくなります。そのため、この分離は意図的に維持されています。

## 方法論と注意事項

- 数値は、**2026-06-17** 時点で各プロバイダーが文書化している無料枠の上限に基づき、ウェブ調査によって収集した**上限推定値**です。無料枠は常に変更されるため、数値に依存する前に再確認してください。
- **各エントリが実際に保証する内容。** エントリごとの信頼度評価はなく、API からも提供されません。上記のすべての数値は、明示されていない同一水準の推定値として扱ってください。ただし、推測ではなく手作業でキュレーションされた2つの事実は別です。44件のエントリには独立して文書化されたハードストップがあり（そのうち39件は xKiro の行で、すべて同じ1日あたりの割り当てを共有）、13件のエントリにはプロンプトの学習利用に関する開示があります。`hardStopGuaranteed` は、無料割り当てを超過した際に暗黙的に課金を開始するのではなく、リクエストを拒否するとプロバイダー自身の規約に明記されている場合にのみ設定され、情報源はエントリの隣のコメントに記載されます。既定で `true` に設定されることはなく、誰も検証していないエントリでは未設定のままです。したがって、ハードストップフラグがないことは「確認されていない」という意味であり、「課金されることが分かっている」という意味ではありません。**STRICT モード**（オプトインの `freeAccessPolicy=strict` ルーティングガード）は、このフラグを持つエントリのみを信頼します。それ以外の無料枠はすべて `no-hard-stop` として除外されます（`open-sse/services/autoCombo/strictZeroCostFilter.ts` を参照）。ガードがプールをフィルタリングすると、運用者向けログには除外数と、そのうち `no-hard-stop` が占める割合の両方が記録されます。
- `estMonthlyFreeTokens` = 毎月繰り返し付与されるトークンのみ。**登録時に一度だけ付与されるクレジットは繰り返し付与されない**ため、0として数えます。廃止された無料枠も0です。
- 1日あたりのトークン上限 → `monthly = daily × 30`。RPD のみが文書化されている場合 → `RPD × 約800出力トークン × 30`。RPM/TPM のみで1日あたりの上限がない場合 → **上限なし**（以下を参照）。
- **恒久的に無料だが、公開されたトークン上限がないもの**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：これらは、レートまたは同時実行数の制限付きで実際に繰り返し利用できる無料アクセスです。これらを `recurring-uncapped` に分類し、**合計には決して含めません**。`RPM × 24/7 × 30d` と掛け合わせると、非現実的な上限値になるためです（このような水増しは採用しません）。存在を把握できるよう、一覧には掲載しています。
- **入金による上限引き上げ：** 一度だけ少額を入金すると、無料割り当てが恒久的に増える仕組みです（OpenRouter：$10 → 1000 req/day ≈ +24M/mo）。通常時の主要数値には含めず、別の数値として報告します。
- **利用資格によって制限される割り当て**（`eligibilityGate: "regional-identity"`）：地域に紐づく本人確認（現在は中国本土の実名認証）を完了した後にのみ利用可能となる、実在する継続的な割り当てです。同じプール重複排除ルールを用いて別の数値（`gatedRecurringTokens`）として集計し、通常時の主要数値には決して含めません。レジーム（`freeType`）は変更されないため、ルーティングも変更されません。
- **エビデンスの分類。** ルール：カタログ内の数値には、そのエントリの隣にある `// evidence:` コメントで情報源を記載します。分類は `public-page`（誰でも閲覧できるプロバイダーのページ）、`api-public`（プロバイダーの認証不要エンドポイント。例：router.bynara.id にある NaraRouter の公開プランエンドポイント）、または `console-verified <date> por <who>`（数値がアカウントコンソール内でのみ確認できる場合。コメントには、誰がいつ確認したか、および上限の存在を示す公開ページを記録）です。現在の状況：2026-09-02 に再監査された5つのブロック（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）には、このコメントがあります。2026-09-02 の再監査より前から存在するエントリは、更新されるまで以前の調査結果を引き継ぎます。エビデンスコメントのない**新規または変更された**数値はバグです。現在、コンソールで検証されているのは `mistral` のみです。

## 当社の数値が他のアグリゲーターより小さい理由

この分野で示される「1か月あたりの無料トークン」の数値の多くは、モデルごとに表示された枠を合計したものです。当社は意図的にそのような計算をしていません。

- **各共有プールは1回だけ数えます。** Mistralの無料プランは、組織ごとに月間10億トークンの枠が1つ提供されるものです。これを5つのモデルに分けて記載しても、50億トークンになるわけではありません。モデルごとに合計すると、当社のカタログも **約74億**（2026-09-03に再計算。この数値はCIによる検証対象ではありません。カタログが変更されるたびに再計測してください）となりますが、見出しでは **約14.7億** としています。これは、各プロバイダーで1つずつアカウントを持つユーザーが実際に利用できる量だからです。
- **日次上限は換算しますが、レート制限は換算しません。** 文書化された1日あたりのトークン上限は `× 30`、文書化された1日あたりのリクエスト上限は `RPD × 約800トークン × 30` として換算します。1分あたりのリクエスト数しか公開していないプロバイダーについては月間数値を算出せず、_上限なし_ と記載して合計には含めません。レート制限を24時間365日利用する前提で掛け算するような水増しは行いません。
- **地域限定の本人確認が必要なクォータは別枠で表示します**（`+地域限定の本人確認により約600万`）。ほとんどの読者は利用できないためです。
- **サインアップクレジットは初月限定**であり、定常的な数値に混ぜず、2つ目の数値として報告します。
- **この数値はCIによって検証されます。** `npm run check:docs-counts` はカタログから合計を再計算し、このファイル、README、または予算カードの数値にずれがある場合はビルドを失敗させます。

## OpenCode Free: クライアント契約の制限 (#14313)

キーレスの `opencode` プロバイダー（公開 `https://opencode.ai/zen/v1`）は、OpenCode クライアント契約に一致しないリクエストをすべて **403 `FreeTierError`** と _「OpenCode の無料枠は OpenCode 内からのみ使用できます」_ という文言で拒否します。これはリクエスト単位の拒否（同じリクエスト形式であれば、どのアカウントでも同じ判定）であり、モデルの禁止や接続のクールダウンではありません。OmniRoute はこれを `project_route_error` に分類し、モデルのロックアウト／クールダウンを省略し、（合成 `noauth` パスでは）短い TTL の間、自動コンボの再選択を一時停止します。空でないツールリスト、`stream: true`、および OpenCode のセッション／UA ヘッダー（`opencodeFreeTierContract.ts`）を含むリクエストを送信してください。そうでなければ 403 が返されます。

## 用語集

| 用語                   | 意味                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| **RPM / RPD / RPH**    | 1分 / 1日 / 1時間あたりのリクエスト数                                                     |
| **TPM / TPD**          | 1分 / 1日あたりのトークン数                                                               |
| **明示された割り当て** | プロバイダーが明示的な1日 / 1か月あたりのトークン上限を公開しているもの（根拠のある予算） |
| **理論上の上限**       | `rate-limit × 24/7 × 30d` — 割り当てられた予算ではなく、最大値                            |
| **Neuron**             | Cloudflareのコンピューティング単位（約1出力トークン）                                     |
