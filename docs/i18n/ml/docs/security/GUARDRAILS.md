> **അവസാനം അപ്ഡേറ്റ് ചെയ്തത്:** 2026-08-29 — v3.8.51 (വീഡിയോ ബ്രിഡ്ജ് ട്രാൻസ്ക്രിപ്റ്റ് പ്രൂവനെൻസ് കോളർ-പ്രഖ്യാപിച്ചതാണ്,
> ഇതുവരെ സെർവർ-പരിശോധിച്ചിട്ടില്ല — #11661 അനുസരിച്ച് വ്യക്തമാക്കിയത്)

OmniRoute-നും അപ്സ്ട്രീം പ്രൊവൈഡർമാർക്കും ഇടയിലുള്ള അതിർത്തിയിൽ സുരക്ഷ, നയം, ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ ഗാർഡ്റെയിലുകൾ നടപ്പിലാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും അഭ്യർത്ഥന പേലോഡുകളും (`preCall`) അപ്സ്ട്രീം പ്രതികരണങ്ങളും (`postCall`) പരിശോധിക്കാൻ (ഓപ്ഷണലായി നിരസിക്കുകയോ, രൂപാന്തരപ്പെടുത്തുകയോ, വ്യാഖ്യാനിക്കുകയോ ചെയ്യാം) കഴിയും.

സിസ്റ്റം **ഫെയിൽ-ഓപ്പൺ** ആണ്: ഒരു ഗാർഡ്റെയിൽ പ്രവർത്തിക്കുമ്പോൾ പിശക് സംഭവിച്ചാൽ, രജിസ്ട്രി പിശക് രേഖപ്പെടുത്തുകയും അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിന് പകരം അടുത്ത ഗാർഡ്റെയിലുമായി മുന്നോട്ട് പോകുകയും ചെയ്യുന്നു. തടയുന്നത് ഒരു വ്യക്തമായ തീരുമാനമാണ് (`block: true`), ഒരിക്കലും ഒരു അപകടമല്ല.

## ബിൽറ്റ്-ഇൻ സുരക്ഷാ നിയന്ത്രണങ്ങൾ

ഇംപോർട്ട് ചെയ്യുമ്പോൾ രജിസ്ട്രി മുൻഗണനാക്രമത്തിൽ ആറ് സുരക്ഷാ നിയന്ത്രണങ്ങൾ സ്വയമേവ ലോഡ് ചെയ്യുന്നു
(`registry.ts` → `registerDefaultGuardrails()` കാണുക):

| മുൻഗണന | പേര്                | ഘട്ടം(ങ്ങൾ)    | ഫയൽ                   |
| ------ | ------------------- | -------------- | --------------------- |
| `5`    | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`    | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`    | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`   | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`   | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`   | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

കുറഞ്ഞ മുൻഗണനാ നമ്പറുകളുള്ളവ **ആദ്യം** പ്രവർത്തിക്കുന്നു.

### വിഷൻ ബ്രിഡ്ജ് (`visionBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-1

**വിഷൻ പിന്തുണയില്ലാത്ത മോഡലുകളെ** ലക്ഷ്യമിടുന്ന, ചിത്രങ്ങൾ ഉൾക്കൊള്ളുന്ന അഭ്യർത്ഥനകളെ തടഞ്ഞുപിടിച്ച്, മുഴുവൻ അഭ്യർത്ഥനയും വിഷൻ പിന്തുണയുള്ള മോഡലിലേക്ക് തിരിച്ചുവിടുകയോ അപ്സ്ട്രീം കോളിനു മുമ്പ് കോൺഫിഗർ ചെയ്യാവുന്ന വിഷൻ മോഡൽ സൃഷ്ടിച്ച വാചക വിവരണങ്ങൾകൊണ്ട് ചിത്രഭാഗങ്ങൾ മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നു. ഇതുവഴി ടെക്സ്റ്റ്-മാത്രം പ്രൊവൈഡർമാർക്ക് മൾട്ടിമോഡൽ പേലോഡുകൾ സുതാര്യമായി കൈകാര്യം ചെയ്യാനാകും.

പ്രവാഹം:

1. ലക്ഷ്യ മോഡൽ ഇതിനകം വിഷനെ പിന്തുണയ്ക്കുന്നുവെങ്കിൽ ഒഴിവാക്കുക (അത് നിർബന്ധിത ബ്രിഡ്ജ് പട്ടികയായ `isVisionBridgeForcedModel`-ൽ ഉൾപ്പെട്ടിട്ടില്ലെങ്കിൽ).
2. `extractImageParts(messages)` വഴി ചിത്രഭാഗങ്ങൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുക
   (`visionBridgeHelpers.ts`); ഇത് `open-sse/utils/mediaParts.ts`-ലെ **ഏകീകൃത മീഡിയ
   ഡിറ്റക്ടറായ** `detectMediaParts()`-ലേക്ക് ചുമതല കൈമാറുന്നു — കോംബോ കോംപാറ്റിബിലിറ്റി ഫിൽട്ടറുമായി പങ്കിടുന്ന
   ഏക ആധികാരിക ഉറവിടമാണിത്.
   `replaceImageParts`-ന് തിരികെ ചേർക്കാനാകുന്ന രൂപങ്ങളിലെ ടോപ്പ്-ലെവൽ ഭാഗങ്ങൾക്കു മാത്രമാണ്
   എക്സ്ട്രാക്ഷൻ അനുവദിച്ചിട്ടുള്ളത് (extract↔replace കരാർ): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, Responses API `input_image`. നെസ്റ്റഡ് പൊരുത്തങ്ങളും
   ഇൻഡിക്കേറ്റർ-മാത്രമുള്ള രൂപങ്ങളും കോംബോ ഫിൽട്ടറിനുള്ളവയാണ്; അവ ഒരിക്കലും എക്സ്ട്രാക്റ്റ് ചെയ്യില്ല.
   ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. `resolveVisionBridgeRuntimeSettings()` വഴി റൺടൈം കോൺഫിഗ് നിർണ്ണയിക്കുക
   (`src/shared/constants/modalityBridgeDefaults.ts`): പുതിയ `modalityBridge*`
   സജ്ജീകരണ കീകൾക്ക് മുൻഗണനയുണ്ട്; പഴയ `visionBridge*` കീകൾ **ഒരു സൈക്കിളിനുള്ള
   ഫാൾബാക്കായി** തുടരും (റോൾബാക്ക് വിൻഡോ). ബ്രിഡ്ജ് പ്രവർത്തനരഹിതമാണെങ്കിൽ ഏതെങ്കിലും
   മീഡിയ ട്രാവേഴ്സലിനു മുമ്പുതന്നെ ഒഴിവാക്കുക.
4. മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`, താഴെയുള്ള പട്ടിക കാണുക)
   തിരിച്ചുവിടണോ വിവരിക്കണോ എന്ന് തീരുമാനിക്കുന്നു. തിരിച്ചുവിടൽ, `model` മാത്രം
   മാറ്റിയ `modifiedPayload`-ഉം `{ rerouted, fromModel, toModel, imagesKept }` എന്ന മെറ്റയും തിരികെ നൽകുന്നു.
5. വിവരണ പാത: ചിത്രങ്ങളുടെ എണ്ണം `maxImages`-ൽ പരിമിതപ്പെടുത്തുക, ടാസ്ക്-അവെയർ പ്രോംപ്റ്റ് തയ്യാറാക്കുക,
   വിവരണ കാഷ് പരിശോധിക്കുക, വിഷൻ മോഡലിനെ **സമാന്തരമായി**
   (`Promise.allSettled`) വിളിക്കുക, തുടർന്ന് അവയുടെ സ്ഥാനത്ത് `[Image N]: <description>` വാചകഭാഗങ്ങൾ
   ചേർക്കുക. വിവരണം പരാജയപ്പെട്ടാൽ `null` ലഭിക്കുകയും യഥാർത്ഥ ചിത്രഭാഗം
   **നിലനിർത്തുകയും** ചെയ്യും (#4012) — എന്നാൽ കോംബോ വിവരണ പാതയിൽ എല്ലാ
   വിവരണങ്ങളും പരാജയപ്പെടുകയും അപ്സ്ട്രീമിന് വിഷൻ പിന്തുണയില്ലെന്ന് സ്ഥിരീകരിക്കപ്പെടുകയും ചെയ്താൽ,
   പകരം `(unavailable — no vision-capable provider connected)` എന്ന സ്റ്റബ് നൽകും (#8430).
6. `modifiedPayload` + മെറ്റ (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) തിരികെ നൽകുക.

| `reroute`  |           | തിരിച്ചുവിടൽ നിർബന്ധമാക്കുക: ക്രെഡൻഷ്യലുകളുള്ള മോഡൽ നിലനിർത്തുന്നതിനുള്ള ഗാർഡ് മറികടക്കപ്പെടുന്നു. തിരിച്ചുവിടൽ-**ലക്ഷ്യത്തിനുള്ള** ക്രെഡൻഷ്യൽ ഗാർഡ് അപ്പോഴും ബാധകമാണ് — ഉപയോഗയോഗ്യമായ വിഷൻ ലക്ഷ്യം ലഭ്യമല്ലെങ്കിൽ, അസംസ്കൃത ചിത്രങ്ങൾ ടെക്സ്റ്റ്-മാത്രം ബാക്കെൻഡിൽ ഒരിക്കലും എത്താതിരിക്കാൻ അഭ്യർത്ഥന വിവരണ പാതയിലേക്ക് മാറുന്നു (#8430). |

നിർബന്ധിത മോഡുകൾ, ഓട്ടോ ഹ്യൂറിസ്റ്റിക് പ്രവർത്തിക്കുന്നതിന് **മുമ്പുതന്നെ** ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു; `auto`-യുടെ പ്രവർത്തനം
PR-1-ന് മുമ്പുള്ള സുരക്ഷാ നിയന്ത്രണവുമായി ബൈറ്റ് തലത്തിൽ സമാനമാണ്.

#### API കീയുടെ പരിധി (`visionBridgeKeyScope.ts`)

കോളറുടെ API കീ `allowedConnections`, ക്വോട്ട പൂളുകൾ
(`allowedQuotas`) അല്ലെങ്കിൽ മോഡലുകൾ (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`) എന്നിവ പരിമിതപ്പെടുത്തുമ്പോൾ, ആ കീയ്ക്ക്
ഉപയോഗിക്കാവുന്ന കണക്ഷനുകളിൽ നിന്ന്, കീയ്ക്ക് ഉപയോഗിക്കാവുന്ന തിരിച്ചുവിടൽ, വിവരണ മോഡലുകൾ മാത്രമേ ബ്രിഡ്ജ്
തിരഞ്ഞെടുക്കൂ. തുടർന്ന് വിവരണ കോൾ എപ്പോഴും
`x-omniroute-self-loop-key-id` ഹെഡറോടുകൂടിയ OmniRoute സെൽഫ്-ലൂപ്പിലൂടെയാണ് പോകുന്നത്; അതുവഴി സ്വീകരിക്കുന്ന ചാറ്റ് അഭ്യർത്ഥന
ആ കീയുടെ കണക്ഷൻ, മോഡൽ നയങ്ങൾ വീണ്ടും നടപ്പാക്കുന്നു. `enforceApiKeyPolicy()`
ആ ഹെഡറിനെ സെൽഫ്-ലൂപ്പ് ബെയററിനൊപ്പം മാത്രമേ അംഗീകരിക്കൂ; അതിനാൽ അതിന് ആക്സസ്
കൂടുതൽ പരിമിതപ്പെടുത്താൻ മാത്രമേ കഴിയൂ, കൂടാതെ പരിഹരിക്കാനാകാത്ത id നിരസിക്കപ്പെടും.

കീയ്ക്ക് ഒരു വിഷൻ മോഡലും അനുവദനീയമല്ലെങ്കിൽ, വിവരണ പാത ഇടപെടാതെ മാറിനിൽക്കുകയും
അഭ്യർത്ഥന മാറ്റമില്ലാതെ കടന്നുപോകുകയും ചെയ്യും; ഇത് പ്രവർത്തനരഹിതമാക്കിയ
സുരക്ഷാ നിയന്ത്രണത്തിന്റെ അതേ fail-open പ്രവർത്തനമാണ് (മെറ്റ `{ skipped: true, reason: "no_permitted_vision_model" }`).
കീ ഇല്ലാത്ത അഭ്യർത്ഥനകളും ഇത്തരം നിയന്ത്രണങ്ങളില്ലാത്ത കീകളും മുമ്പത്തെപ്പോലെതന്നെ
പ്രവർത്തിക്കും.

#### ടാസ്ക്-അവെയർ വിവരണ പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

സ്ഥിരസ്ഥിതി **true** ആണ്. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) അടിസ്ഥാന
വിവരണ പ്രോംപ്റ്റിലേക്ക് **അവസാന ഉപയോക്തൃ സന്ദേശത്തിന്റെ** ടെക്സ്റ്റ് (500 അക്ഷരങ്ങളായി
ചുരുക്കിയത്) ചേർക്കുന്നു; ഇതിലൂടെ വിവരണം ഉപയോക്താവ് യഥാർത്ഥത്തിൽ ചോദിച്ച കാര്യത്തിലേക്ക്
നയിക്കപ്പെടുകയും (codex-vision-proxy പാറ്റേൺ), ദൃശ്യമാകുന്ന ടെക്സ്റ്റ് പകർത്തിയെഴുതാൻ
വിഷൻ മോഡലിനോട് ആവശ്യപ്പെടുകയും ചെയ്യുന്നു. ഫ്ലാഗ് ഓഫായിരിക്കുമ്പോൾ — അല്ലെങ്കിൽ ഉപയോക്തൃ
ടെക്സ്റ്റ് ഇല്ലെങ്കിൽ — അടിസ്ഥാന പ്രോംപ്റ്റ് മാറ്റമില്ലാതെ ഉപയോഗിക്കുന്നു.

ഡിസ്ക്രൈബ് സെൽഫ്-ലൂപ്പിന്റെ സ്വന്തം OpenAI-അനുയോജ്യമായ അഭ്യർത്ഥന
(`visionBridgeHelpers.ts`-ലെ `callVisionModelSingle()`) എല്ലായ്പ്പോഴും
`image_url.detail: "high"` അഭ്യർത്ഥിക്കുന്നു — യാതൊരു ക്ലയന്റ് സിഗ്നലിനെയും
ആശ്രയിക്കാതെ, എല്ലാ കോളർമാർക്കും/പ്രൊവൈഡർമാർക്കും വ്യവസ്ഥകളില്ലാതെ. ഈ പ്രോംപ്റ്റ്
ആവശ്യപ്പെടുന്ന ടെക്സ്റ്റ്-ട്രാൻസ്ക്രിപ്ഷൻ ടാസ്കിന് ലോ-ഡീറ്റെയിൽ സാംപ്ലിങ് OCR കൃത്യത
കുറയ്ക്കുന്നതിനാൽ, യഥാർത്ഥ ഇൻബൗണ്ട് അഭ്യർത്ഥന ഉപയോഗിച്ച ഡീറ്റെയിൽ ലെവൽ എന്തായാലും
ഡിസ്ക്രൈബ് കോൾ തന്നെ എല്ലായ്പ്പോഴും ഉയർന്ന ഡീറ്റെയിൽ ആവശ്യപ്പെടുന്നു. ഇത് ആന്തരിക
ഡിസ്ക്രൈബ് അഭ്യർത്ഥനയുടെ ബോഡിയെ മാത്രമേ ബാധിക്കൂ; പ്രാഥമിക അഭ്യർത്ഥനയിൽ കോളറുടെ
സ്വന്തം `image_url.detail` OmniRoute എങ്ങനെ ഫോർവേഡ് ചെയ്യുന്നു എന്നതിൽ മാറ്റമുണ്ടാകില്ല —
ആ സ്ഥിരസ്ഥിതി പ്രത്യേകം പ്രയോഗിക്കപ്പെടുന്നത്, കണ്ടെത്തിയ OpenCode ക്ലയന്റുകൾക്കു മാത്രം,
`defaultImageDetail()`-ൽ (`open-sse/handlers/chatCore/upstreamBody.ts`) ആണ്.
ഡിസ്ക്രൈബ് സെൽഫ്-ലൂപ്പിന്റെ Anthropic വയർ-ഫോർമാറ്റ് ബ്രാഞ്ചിൽ `detail` ഫീൽഡ് ഇല്ല;
അതിനാൽ ഏതെങ്കിലും സ്ഥിരസ്ഥിതി അതിനെ ബാധിക്കില്ല.

#### ഡിസ്ക്രൈബ് ഔട്ട്പുട്ട് പരിധി (`modalityBridgeVisionMaxChars`)

| കീ                             | സ്ഥിരസ്ഥിതി | പരിധി                    |
| ------------------------------ | ----------- | ------------------------ |
| `modalityBridgeVisionMaxChars` | `0`         | `0` അല്ലെങ്കിൽ 100–50000 |

`0` (സ്ഥിരസ്ഥിതി) എന്നത് **പരിധിയില്ല** എന്നാണ് — `callVisionModel()` നൽകുന്ന
വിവരണം മാറ്റം വരുത്താതെ കടത്തിവിടുന്നു, അതുവഴി നിലവിലുള്ള പെരുമാറ്റം നിലനിർത്തുന്നു.
100–50000 പരിധിയിലുള്ള ഏതൊരു മൂല്യവും വിവരണത്തെ `[Image N]: <description>`
എന്ന രൂപത്തിൽ തിരികെ ചേർക്കുന്നതിന് മുമ്പ് `…` പ്രത്യയം ചേർത്ത് ചുരുക്കുന്നു
(`src/lib/guardrails/visionBridge.ts`-ലെ `VisionBridgeGuardrail.preCall()`).
ഡൗൺസ്ട്രീം മോഡലിന് പൂർണ്ണ ട്രാൻസ്ക്രിപ്ഷൻ ആവശ്യമുള്ള, ധാരാളം വിശദാംശങ്ങളുള്ള OCR
ടാസ്കുകൾക്കായി ഇത് ഉയർത്തുക; കൂടുതൽ വാചാലമായ വിഷൻ മോഡലുകളുടെ ടോക്കൺ ഉപയോഗം
പരിമിതപ്പെടുത്താൻ ഇത് കുറയ്ക്കുക. ഡാഷ്ബോർഡ് ഫീൽഡ് Vision ടാബിലെ Advanced പാനലിലാണ്
(`ModalityBridgeVisionTab.tsx`-ലെ `modality-bridge-max-chars`); വ്യക്തമായി നൽകിയ
`0` മാറ്റാതെ നിലനിർത്തിക്കൊണ്ട്, 1-നും 99-നും ഇടയിലുള്ള ഏത് മൂല്യവും ഇത് ഏറ്റവും
കുറഞ്ഞ പരിധിയായ 100-ലേക്ക് ഉയർത്തുന്നു — `0` എന്നത് കേവലം "സജ്ജമാക്കിയിട്ടില്ല"
എന്ന സ്ഥിരസ്ഥിതി മാത്രമല്ല, സ്വതന്ത്രമായി സാധുവായ ഒരു Zod മൂല്യമാണ്
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`).

#### ഡിസ്ക്രൈബ് കാഷ് (`modalityBridge/bridgeCache.ts`)

ഡിസ്ക്രൈബ് ഔട്ട്പുട്ടുകൾക്കായുള്ള ഇൻ-മെമ്മറി LRU + TTL കാഷ്; മുഴുവൻ പ്രോസസിലുമായി
പങ്കിടുന്നു. കീ = `sha256(imageRef + composedPrompt + configuredBridgeModel)`,
ലെങ്ത്-പ്രിഫിക്സ് ഫ്രെയിമിങ്ങോടുകൂടി (ഫീൽഡ് അതിർത്തികളിൽ കൂട്ടിയിടികളില്ല). മോഡൽ
ഘടകം **കോൺഫിഗർ ചെയ്ത** ബ്രിഡ്ജ് മോഡലാണ്, യഥാർത്ഥത്തിൽ മറുപടി നൽകിയ മോഡലല്ല —
`callVisionModel` ആന്തരികമായി ഫാൾബാക്ക് ചെയ്തേക്കാം; ഓരോ ശ്രമത്തിനനുസരിച്ച് കീ
നൽകുന്നത് കാഷിനെ വിഘടിപ്പിക്കും. പരാജയപ്പെട്ട ഡിസ്ക്രൈബുകൾ ഒരിക്കലും കാഷ് ചെയ്യില്ല.
ക്രമീകരണങ്ങൾ:

| കീ                              | സ്ഥിരസ്ഥിതി | പരിധി   |
| ------------------------------- | ----------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`      | —       |
| `modalityBridgeCacheTtlMinutes` | `60`        | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`       | 10–5000 |

ട്രാൻസ്ക്രൈബ് ചെയ്യപ്പെടുകയും തിരഞ്ഞെടുത്ത ചാറ്റ് മോഡൽ ടെക്സ്റ്റ് ട്രാൻസ്ക്രിപ്റ്റുകളുമായി തുടരുകയും ചെയ്യുന്നു.

ഫ്ലോ:

1. `getResolvedModelCapabilities()` വഴി `supportsAudio` റിസോൾവ് ചെയ്യുക. വ്യക്തമായി നൽകിയ
   പ്രൊവൈഡർ-രജിസ്ട്രി മെറ്റാഡാറ്റയ്ക്ക് മുൻഗണന ലഭിക്കും, തുടർന്ന് സ്റ്റാറ്റിക് മോഡൽ മെറ്റാഡാറ്റയ്ക്കും, പിന്നെ സിങ്ക് ചെയ്ത
   `modalities_input`-നും. `audio` ഇല്ലാത്ത പ്രഖ്യാപിത ഇൻപുട്ട് ലിസ്റ്റ് `false` ആണ്;
   ശേഷിക്കുന്ന ശേഷി-തെളിവൊന്നുമില്ലെങ്കിൽ `null` ആണ്. `false`, `null` എന്നിവ രണ്ടും
   കൺസർവേറ്റീവ് ബ്രിഡ്ജ് സജീവമാക്കുന്നു, അതേസമയം `true` അതിനെ ബൈപാസ് ചെയ്യുന്നു.
2. `modalityBridgeAudio*` ക്രമീകരണങ്ങൾ റിസോൾവ് ചെയ്ത്, പങ്കിട്ട `detectMediaParts()`
   ഡിറ്റക്ടർ വഴി എല്ലാ സന്ദേശങ്ങളിൽനിന്നും സ്പ്ലൈസ് ചെയ്യാവുന്ന ടോപ്പ്-ലെവൽ
   ഓഡിയോ ഭാഗങ്ങൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുക. പിന്തുണയ്ക്കുന്ന വയർ ഷേപ്പുകൾ OpenAI `input_audio`, `audio_url`,
   `source.media_type: "audio/*"` എന്നിവയാണ്. റൂട്ടിങ്ങിനായി നെസ്റ്റഡ് ഓഡിയോ കണ്ടെത്തുമെങ്കിലും
   സ്പ്ലൈസ് പാത്ത് അത് നീക്കം ചെയ്യില്ല. പ്രവർത്തനം `modalityBridgeAudioMaxClips` കൊണ്ട് പരിമിതപ്പെടുത്തിയിരിക്കുന്നു;
   പിന്നീടുള്ള ഭാഗങ്ങൾ മാറ്റമില്ലാതെ തുടരുന്നു.
3. കോൺഫിഗർ ചെയ്ത `provider/model` മാനിക്കുക, അല്ലെങ്കിൽ സ്ഥിരമായ കാറ്റലോഗ് ക്രമത്തിൽ
   `AUDIO_TRANSCRIPTION_PROVIDERS`-ലൂടെ സഞ്ചരിച്ച് ഉപയോഗിക്കാവുന്ന സജീവ പ്രൊവൈഡർ ക്രെഡൻഷ്യലുള്ള ആദ്യ
   മോഡൽ തിരഞ്ഞെടുക്കാൻ `selectAudioBridgeModel()`-നെ അനുവദിക്കുക.
4. `callAudioTranscription()` base64/data-URI ഓഡിയോയെ ഒരു മൾട്ടിപാർട്ട്
   `file` ആക്കി പരിവർത്തനം ചെയ്യുന്നു, അല്ലെങ്കിൽ DNS പിന്നിങ്ങും 25 MB പരിധിയുമുള്ള പബ്ലിക്-മാത്രം ഔട്ട്ബൗണ്ട്
   ഗാർഡിലൂടെ റിമോട്ട് `audio_url` ഡൗൺലോഡ് ചെയ്യുന്നു. തുടർന്ന് `resolveSelfLoopBearer()` ഉപയോഗിച്ച്
   ഓതന്റിക്കേറ്റ് ചെയ്ത നിലയിൽ, പ്രാദേശിക `/v1/audio/transcriptions` സെൽഫ്-ലൂപ്പിലേക്ക് ഫയലും തിരഞ്ഞെടുത്ത
   മോഡലും POST ചെയ്യുന്നു. നിലവിലുള്ള ട്രാൻസ്ക്രിപ്ഷൻ റൂട്ട് സാധാരണ
   ക്രെഡൻഷ്യൽ ലുക്കപ്പ്, കൂൾഡൗൺ/റേറ്റ്-ലിമിറ്റ് കൈകാര്യം ചെയ്യൽ, പ്രൊവൈഡർ ഡിസ്പാച്ച് എന്നിവ നിർവഹിക്കുന്നു.
5. വിജയകരമായ കോളുകൾ അവയുടെ ഭാഗങ്ങളെ `[Audio N]: <transcript>` ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു. കോളുകൾ
   `Promise.allSettled` ഉപയോഗിച്ച് പ്രവർത്തിക്കുന്നു: ഒരു വ്യക്തിഗത പരാജയം ആ യഥാർത്ഥ
   ഓഡിയോ ഭാഗം നിലനിർത്തുന്നു (#4012 കരാർ). എല്ലാ കോളുകളും പരാജയപ്പെടുകയും ലക്ഷ്യത്തിന്
   `supportsAudio === false` എന്ന് തെളിയിക്കപ്പെടുകയും ചെയ്താൽ, ഭാഗങ്ങൾ
   `[Audio N]: (unavailable — no STT provider connected)` ആയി മാറുന്നു (#8430 കരാർ). അജ്ഞാത
   ലക്ഷ്യത്തിന് (`null`), എല്ലാം പരാജയപ്പെട്ട ഫലം മാറ്റമില്ലാതെ തുടരുന്നു. ഉപയോഗിക്കാവുന്ന STT ക്രെഡൻഷ്യലില്ലാത്ത,
   ടെക്സ്റ്റ്-മാത്രമെന്ന് തെളിയിക്കപ്പെട്ട ലക്ഷ്യത്തിന് നെറ്റ്വർക്ക് കോൾ നടത്താതെ തന്നെ അതേ വ്യക്തമായ
   സ്റ്റബ് ലഭിക്കുന്നു.

വിജയകരമായ ട്രാൻസ്ക്രിപ്റ്റുകൾ പ്രോസസ്-വ്യാപകമായ Modality Bridge LRU/TTL കാഷ് ഉപയോഗിക്കുന്നു.
കീ ഓഡിയോ റഫറൻസ്, സ്ഥിരമായ `audio-transcription` ഓപ്പറേഷൻ
ലേബൽ, തിരഞ്ഞെടുത്ത STT മോഡൽ എന്നിവ സംയോജിപ്പിക്കുന്നു; പരാജയങ്ങൾ ഒരിക്കലും കാഷ് ചെയ്യപ്പെടില്ല. ഓഡിയോ ശ്രമങ്ങൾ
പങ്കിട്ട `bridged`, `cacheHits`, `failures`, `lastUsedAt` കൗണ്ടറുകൾ അപ്ഡേറ്റ് ചെയ്യുന്നു.
പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങൾ
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` വഹിക്കുന്നു; മാറ്റമില്ലാത്ത
അഭ്യർത്ഥനകൾക്ക് Audio Bridge സെഗ്മെന്റ് ലഭിക്കില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-പിന്തുണയുള്ളതും Zod-വാലിഡേറ്റ് ചെയ്തതുമാണ്:

| കീ                            | ഡിഫോൾട്ട് | പരിധി                  |
| ----------------------------- | --------- | ---------------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —                      |
| `modalityBridgeAudioModel`    | `""`      | Auto അല്ലെങ്കിൽ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000            |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10                   |

പങ്കിട്ട കാഷ് ഇപ്പോഴും `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാണ് നിയന്ത്രിക്കുന്നത്.

### വീഡിയോ ബ്രിഡ്ജ് (`videoBridge.ts`, `videoBridgePipeline.ts`)

സ്വാഭാവിക വീഡിയോ പിന്തുണയുള്ളതായി അറിയപ്പെടാത്ത ഒരു ലക്ഷ്യത്തെ വിളിക്കുന്നതിന് മുമ്പ്, Chat Completions `messages`-ലും Responses
API `input`-ലുമുള്ള ടോപ്പ്-ലെവൽ വീഡിയോ ഭാഗങ്ങളെ ഇന്റർസെപ്റ്റ് ചെയ്യുന്നു.
പിന്തുണയ്ക്കുന്ന രൂപങ്ങൾ `input_video`, `video_url`, `video_source`, HTTPS URL-കൾ,
`data:video/*;base64,...` ഡാറ്റ URI-കൾ എന്നിവയാണ്. ടെക്സ്റ്റിലുള്ള സാധാരണ ഫയൽനാമങ്ങളെ
വീഡിയോയായി കണക്കാക്കില്ല.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) അഭ്യർത്ഥനയിലൂടെയുള്ള സഞ്ചാരം,
ശേഷി/നയ പരിശോധന, ഓരോ അഭ്യർത്ഥനയ്ക്കുമുള്ള അഗ്രിഗേഷൻ, പ്രതികരണ പേലോഡ് എന്നിവ കൈകാര്യം ചെയ്യുന്നു.
ഓരോ വീഡിയോയ്ക്കുമുള്ള പ്രവർത്തനം — ലഭ്യമാക്കൽ, പൂർണ്ണ-ഫല കാഷ്, ഫ്രെയിം
ശ്രേണിയെ വിവരിക്കൽ (കോളർ പ്രഖ്യാപിച്ചിട്ടുള്ള ഏതെങ്കിലും ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റ് ഇതിൽ സംയോജിപ്പിക്കുന്നു),
ഓരോ ശ്രമത്തിനുമുള്ള മെട്രിക്കുകൾ/നിർത്തലാക്കൽ/വൃത്തിയാക്കൽ — `videoBridgePipeline.ts`-ലെ
`processVideoPart`-ന് പിന്നിൽ മറച്ചിരിക്കുന്നു; `preCall`-ന്റെ ലൂപ്പിനുള്ളിൽ ഓരോ വീഡിയോ ഭാഗത്തിനും
ഇത് ഒരിക്കൽ വിളിക്കപ്പെടുന്നു. ആ മൊഡ്യൂൾ വ്യക്തമായ പോർട്ട് അതിർത്തികളായ `VideoMediaBrokerPort`
(ബൈറ്റുകൾ ലഭ്യമാക്കുകയും സാമ്പിൾ ചെയ്ത ഫ്രെയിമുകൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുകയും ചെയ്യുന്നത്), `VideoAudioTranscriptionPort`
(കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റിനെ സാമ്പിൾ ചെയ്ത ക്യാപ്ഷനുകളുമായി സംയോജിപ്പിക്കുന്നത്),
`VideoDrilldownPort` (ഫ്രെയിം ഡ്രിൽ-ഡൗൺ പെർസിസ്റ്റൻസ് അതിർത്തി; ഇത് ഇതുവരെ
`processVideoPart`-ലേക്ക് ബന്ധിപ്പിച്ചിട്ടില്ല — നിലവിൽ പ്രത്യേക `/api/modality-bridge/video/drilldown`
റൂട്ട് മാത്രമാണ് ഡ്രിൽ-ഡൗൺ എൻട്രികൾ എഴുതുന്നത്) എന്നിവയും നിർവചിക്കുന്നു.

പൊതു `/v1` അഭ്യർത്ഥനാ പാത ഒരിക്കലും ഒരു സബ്പ്രോസസ് ഇംപോർട്ട് ചെയ്യുകയോ വിളിക്കുകയോ ചെയ്യുന്നില്ല. റിമോട്ട്
വീഡിയോകൾ 50 MiB പരിധിക്കുള്ളിൽ ഡൗൺലോഡ് ചെയ്യുന്നു; മോഡൽ/messages/ഫ്രെയിമിംഗ് എൻവലപ്പ്
50 MiB എന്ന പൊതു JSON അഭ്യർത്ഥനാ പ്രവേശന പരിധിക്കുള്ളിൽ നിലനിർത്തുന്നതിനായി ഇൻലൈൻ base64 വീഡിയോകൾക്ക്
ഓരോ വീഡിയോയ്ക്കും ഡീകോഡ് ചെയ്ത വലുപ്പത്തിൽ സൂക്ഷ്മമായ 36 MiB പരിധിയുണ്ട്. അലോക്കേഷനുമുമ്പ് ഇൻലൈൻ
നീളവും ഡീകോഡ് ചെയ്ത വലുപ്പത്തിന്റെ കണക്കുകളും പരിശോധിക്കുന്നു. പ്രാരംഭ റിമോട്ട് URL-ലും ഓരോ റീഡയറക്ടിലും
HTTPS നിർബന്ധമാണ്; ഇതിനായി DNS പിന്നിംഗോടുകൂടിയ നിലവിലുള്ള പബ്ലിക്-ഒൺലി ഔട്ട്ബൗണ്ട് ഗാർഡ് ഉപയോഗിക്കുന്നു.
തുടർന്ന് ബൈറ്റുകൾ കൃത്യമായ ആന്തരിക `POST /api/modality-bridge/video/extract` ബ്രോക്കർ അതിർത്തി
കടക്കുന്നു. ആ റൂട്ട് `LOCAL_ONLY`യും `SPAWN_CAPABLE`യും ആണ്; ഓരോ പ്രോസസിനും ഓതന്റിക്കേറ്റ് ചെയ്ത,
വിശ്വസനീയമായ ലൂപ്പ്ബാക്ക് അഭ്യർത്ഥനകൾ മാത്രമേ അത് സ്വീകരിക്കൂ; URL, ഫയൽസിസ്റ്റം പാത, എക്സിക്യൂട്ടബിൾ,

ഘടനാപരമായ മൂല്യങ്ങൾ നിർണിതമായ സാമ്പിളിംഗ് തെളിവുകളാണ്, അർത്ഥപരമായ വീഡിയോ ഗ്രഹണമല്ല. അവ വിഷയങ്ങൾ, പ്രവൃത്തികൾ, ക്യാപ്ഷനുകൾ, സംസാരം, അല്ലെങ്കിൽ ഉപയോക്തൃ ഉദ്ദേശ്യം എന്നിവ അനുമാനിക്കുന്നില്ല. സീൻ, ഫ്രീസ് അതിരുകൾ സെഗ്മെന്റുകൾ രൂപപ്പെടുത്തുന്നു; ഫ്രീസ് കവറേജ്, ബ്ലർ, എക്സ്പോഷർ, സ്പേഷ്യൽ വിശദാംശം, ടെംപറൽ മാറ്റം എന്നിവ നിലവിലുള്ള 1–16 ഫ്രെയിം ബജറ്റ് എങ്ങനെ അനുവദിക്കപ്പെടുന്നു എന്നതിനെ മാത്രമേ സ്വാധീനിക്കൂ. പൂർണ്ണമായി നിശ്ചലമായ ഒരു സെഗ്മെന്റ് ഒരു ഫ്രെയിമായി പരിമിതപ്പെടുത്തപ്പെടും, അതേസമയം നിശ്ചലമല്ലാത്ത സെഗ്മെന്റുകൾ ശേഷിക്കുന്ന ബജറ്റിനായി മത്സരിക്കും. അതിരുകളുടെ എണ്ണം ഫ്രെയിമുകളുടെ എണ്ണത്തേക്കാൾ കൂടുതലാകുമ്പോൾ, ടൈംലൈനിലുടനീളമുള്ള ഏകീകൃത കവറേജ് നിലനിർത്തുന്നതിനാൽ തുടക്കത്തിലെ വേഗത്തിലുള്ള കട്ടുകൾക്ക് അവസാനത്തിലുള്ള ദൈർഘ്യമേറിയ സെഗ്മെന്റിനെ മറയ്ക്കാനാവില്ല. ഒരു ഫ്രീസ് അതിരിന്റെ 1-സെക്കൻഡ് വിശകലന റെസല്യൂഷനിലുള്ള സീൻ അതിരുകൾ ഏകീകരിക്കപ്പെടുന്നു.

ലഭ്യമല്ലാത്ത ഫിൽട്ടറുകൾ, തെറ്റായ രൂപത്തിലുള്ളതോ ശൂന്യമായതോ ആയ തെളിവുകൾ, ഡിറ്റക്ടർ പിശക്, അല്ലെങ്കിൽ പരിധിയുള്ള മുൻകൂർ വിശകലന ടൈംഔട്ട് എന്നിവ സംഭവിച്ചാൽ, കൃത്യമായ ഏകീകൃത മിഡ്പോയിന്റ് നയത്തിലേക്ക് ഫെയിൽ-ഓപ്പൺ ചെയ്യും. കോളർ അബോർട്ടോ ബ്രോക്കർ ഡെഡ്ലൈനോ ഫെയിൽ-ഓപ്പൺ ചെയ്യില്ല: അത് പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന സബ്പ്രോസസ് അവസാനിപ്പിക്കുകയും, തുടർന്നുള്ള ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുകയും, സ്വകാര്യ താൽക്കാലിക ട്രീ `finally`-യിൽ നീക്കം ചെയ്യുകയും ചെയ്യും.

`scripts/perf/video-bridge-fu07-eval.ts`, ഡീഡ്യൂപ്ലിക്കേഷനുശേഷമുള്ള ക്യാപ്ഷൻ-കോൾ ലാഭം, സാന്ദ്ര-ചലന ബജറ്റ് അലോക്കേഷൻ, ബ്ലർ/എക്സ്പോഷർ/SI-TI തെളിവുകൾ, ദൈർഘ്യമേറിയ അവസാന ഭാഗത്തോടുകൂടിയ വേഗത്തിലുള്ള കട്ടുകൾ, ക്രമേണയുള്ള ഫേഡ് മൂലമുള്ള ഫാൾസ് പോസിറ്റീവുകൾ എന്നിവയ്ക്കായി നിർണിതമായ യഥാർത്ഥ FFmpeg ഫിക്സ്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് മുൻകൂർ വിശകലനത്തിന്റെ വാൾ സമയം രേഖപ്പെടുത്തുകയും, `/usr/bin/time` ലഭ്യമായിടത്ത് ചൈൽഡ് CPU, പീക്ക് RSS എന്നിവയും രേഖപ്പെടുത്തുകയും ചെയ്യുന്നു. ഇതിന്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഓറക്കിളുകൾ മാത്രമാണ്. ഈ ഹാർനെസിന് അംഗീകൃത എൻഡ്പോയിന്റോ സ്ഥിരപ്പെടുത്തിയ ജഡ്ജോ ഇല്ലാത്തതിനാൽ യഥാർത്ഥ ക്യാപ്ഷൻ-മോഡൽ ഗുണനിലവാരം `HOLD` ആയി തുടരും. `--caption-cost-per-call-usd` വ്യക്തമായ പോസിറ്റീവ് ഓരോ-കോളിനുമുള്ള ചെലവ് കണക്ക് നൽകാത്തപക്ഷം സാമ്പത്തിക ലാഭവും `HOLD` ആയി തുടരും; സ്ക്രിപ്റ്റ് ഈ ഫലങ്ങളിൽ ഒന്നും കൃത്രിമമായി സൃഷ്ടിക്കില്ല.

ഓരോ ഫ്രെയിമും 4 MiB ആയി, എല്ലാ റോ ഫ്രെയിമുകളും ചേർന്ന് 23 MiB ആയി, സീരിയലൈസ് ചെയ്ത ബ്രോക്കർ പ്രതികരണം 32 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി `finally`-യിൽ നീക്കം ചെയ്യപ്പെടുന്നു. OmniRoute-ൽ FFmpeg ഉൾപ്പെടുത്തിയിട്ടില്ല, കൂടാതെ ഇഷ്ടാനുസൃത എക്സിക്യൂട്ടബിൾ പാത്ത് അത് സ്വീകരിക്കുകയുമില്ല. ക്യാപ്ഷനിംഗിന് മുമ്പ്, ബ്രിഡ്ജ് ഒരു യാഥാസ്ഥിതിക വിഷ്വൽ ഡീഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG-ഉം 16×16 ഗ്രേസ്കെയിൽ ബഫറാക്കി ചുരുക്കുകയും, അവസാനം നിലനിർത്തിയ ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുകയും ചെയ്യുന്നു. ഒരു ഫ്രെയിമിന് മുകളിലുള്ള അഭ്യർത്ഥിത ക്യാപ്ഷൻ ബജറ്റിനായി, എക്സ്ട്രാക്ഷൻ ആ ബജറ്റിന്റെ പരമാവധി ഇരട്ടി വരെ, എന്നാൽ ഒരിക്കലും 16 ഫ്രെയിമിൽ കൂടുതലല്ലാത്ത, പരിധിയുള്ള ഒരു കാൻഡിഡേറ്റ് പൂൾ നൽകുന്നു. അഭ്യർത്ഥിച്ച പരിധി ഡീഡ്യൂപ്ലിക്കേഷനുശേഷം മാത്രമേ പ്രയോഗിക്കൂ; ബജറ്റ് കുറഞ്ഞത് രണ്ടായിരിക്കുമ്പോൾ അന്തിമ തിന്നിംഗിൽ ആദ്യം തിരഞ്ഞെടുത്തതും അവസാനം തിരഞ്ഞെടുത്തതുമായ കാൻഡിഡേറ്റുകൾ സംരക്ഷിക്കപ്പെടും. പതിപ്പിട്ട
`grayscale-16x16-mean-cells-v2` നയം, ശരാശരി ലൂമ ഡെൽറ്റയിലും നോർമലൈസ് ചെയ്ത ഡെൽറ്റ കുറഞ്ഞത് 0.05 ആയ തമ്പ്നെയിൽ സെല്ലുകളുടെ അനുപാതത്തിലും വലുതായത് ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് 0.04 എന്ന സ്ഥിരാങ്കമാണ്; റൺടൈം ക്രമീകരണമായി പുറത്തുകൊടുക്കുന്നതിനുപകരം പ്രവചനക്ഷമതയ്ക്കായി അത് തിരഞ്ഞെടുത്തിരിക്കുന്നു. ശരാശരി മാത്രം അടിസ്ഥാനമാക്കിയുള്ള താരതമ്യം മറച്ചുവെക്കാനിടയുള്ള ചെറിയ ചലനങ്ങളും ദൃശ്യമായ ടെക്സ്റ്റ് മാറ്റങ്ങളും ഈ രണ്ടാമത്തെ ഹൈ-കോൺട്രാസ്റ്റ് സിഗ്നൽ സംരക്ഷിക്കുന്നു. കംപാരേറ്റർ അല്ലെങ്കിൽ ഡീകോഡർ പിശകുകൾ ഫെയിൽ-ഓപ്പൺ ചെയ്ത് കവറേജ് നിലനിർത്തുന്നു. ഔട്ട്പുട്ട് മെറ്റാഡേറ്റ, എക്സ്ട്രാക്റ്റ് ചെയ്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, ഒഴിവാക്കിയ വിഷ്വൽ ഡ്യൂപ്ലിക്കേറ്റുകൾ എന്നിവയെ വേർതിരിക്കുന്നു.

വ്യക്തമായി അടയാളപ്പെടുത്തിയ ഒരു വീഡിയോ ഭാഗത്തിന് ടൈംസ്റ്റാമ്പോടുകൂടിയ കോൺടാക്റ്റ് ഷീറ്റ് അഭ്യർത്ഥിക്കാം. ബ്രിഡ്ജ് പരമാവധി 4 കോളവും 16 ഫ്രെയിമുമുള്ള JPEG ഗ്രിഡ് നിർമ്മിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിന്റെ ഉറവിട ടൈംസ്റ്റാമ്പ് ഹൈ-കോൺട്രാസ്റ്റ് അടിഭാഗ ബാൻഡിൽ പതിപ്പിക്കുന്നു; അതേ ടൈംസ്റ്റാമ്പുകൾ ഡൗൺസ്ട്രീം ബന്ധപ്പെടുത്തലിനും ഓഡിറ്റിനുമായി ടെക്സ്റ്റ് മെറ്റാഡേറ്റയിലും നിലനിർത്തുന്നു. പൂർണ്ണമായ JPEG 32 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. `sharp`-ന് ഗ്രിഡ് ഡീകോഡ് ചെയ്യാനോ കമ്പോസ് ചെയ്യാനോ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് വ്യക്തിഗത JPEG ഫ്രെയിമുകളിലേക്ക് ഫാൾബാക്ക് ചെയ്യും; ക്ലയന്റ് അബോർട്ട് ഷീറ്റ് പ്രവർത്തനത്തിലൂടെ തുടർന്നും പ്രൊപ്പഗേറ്റ് ചെയ്യും.

പ്രൊമോഷൻ തെളിവുകൾ സിന്തറ്റിക് കോംപോസിഷൻ മൈക്രോബെഞ്ച്മാർക്കിൽനിന്ന് ഉദ്ദേശപൂർവം വേർതിരിച്ചിരിക്കുന്നു. `scripts/perf/video-bridge-contact-sheet-eval.ts`, യഥാർത്ഥ OpenAI-അനുയോജ്യമായ വിഷൻ മോഡലുകൾക്കായി സ്കീമ-പതിപ്പിട്ട A/B ഹാർനെസ് നിർവചിക്കുന്നു. പ്രൊവൈഡർ റിപ്പോർട്ട് ചെയ്യുന്ന ടോക്കണുകൾ, എൻഡ്-ടു-എൻഡ് വാൾ ലേറ്റൻസി (ഷീറ്റ് കോംപോസിഷൻ ഉൾപ്പെടെ), മോഡൽ-കോൾ എണ്ണം, മാനിഫെസ്റ്റ് നിർവചിച്ച വസ്തുത നിലനിർത്തൽ എന്നിവ ഇത് അളക്കുന്നു. റോ മോഡൽ പ്രതികരണങ്ങൾ റിപ്പോർട്ടിൽ എഴുതപ്പെടുന്നില്ല; SHA-256 ഡൈജസ്റ്റുകളും പൊരുത്തപ്പെട്ട വസ്തുതാ ID-കളും മാത്രമാണ് നിലനിർത്തുന്നത്. `--execute-real` പാസ് ചെയ്യുകയും `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ കോൺഫിഗർ ചെയ്യുകയും ചെയ്തിട്ടില്ലെങ്കിൽ, ഹാർനെസ് നെറ്റ്വർക്ക് കോളോ പണമടച്ചുള്ള മോഡൽ കോളോ നടത്തില്ല. അത്തരത്തിലുള്ള വ്യക്തമായ യഥാർത്ഥ റൺ ഇല്ലെങ്കിൽ, അതിന്റെ മെഷീൻ വായിക്കാവുന്ന വിധിനിർണയം `HOLD` ആയി തുടരും; സിന്തറ്റിക് പേലോഡ്/കോൾ-എണ്ണ അളവുകൾ മാത്രം പ്രൊമോഷൻ തെളിവുകളല്ല.

കോളർമാർക്ക്, ഇതിനകം വിന്യസിച്ച ടെക്സ്റ്റ് കൈവശമുണ്ടെങ്കിൽ, പിന്തുണയ്ക്കുന്ന ഒരു വീഡിയോ ഭാഗത്തേക്ക് ഐച്ഛികമായ `transcript.cues` അറേ ചേർക്കാം. ഓരോ ക്യൂവിലും `text`, പരിശോധിച്ച ദൈർഘ്യത്തിനുള്ളിലുള്ള പരിമിതമായ `start`/`end` ഇടവേള, അനുവദനീയ പട്ടികയിലുള്ള `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ ഉണ്ടായിരിക്കണം; `confidence`-ന്റെ ഡിഫോൾട്ട് `1` ആണ്, അത് `0`-നും `1`-നും ഇടയിൽ തന്നെ തുടരണം. കൃത്യമായി ഒരേപോലുള്ള ഡ്യൂപ്ലിക്കേറ്റ് ക്യൂകൾ ഏകീകരിക്കപ്പെടുന്നു. OmniRoute ഈ മെറ്റാഡേറ്റയിൽനിന്ന് ഒരിക്കലും ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കില്ല: സാധൂകരിച്ച ക്യൂകൾ ഉറവിടം, കോൺഫിഡൻസ്, ഇടവേള എന്നിവയോടൊപ്പം വിവരിച്ച ഫലത്തിലേക്ക് പകർത്തുകയും ഫ്രെയിം ക്യാപ്ഷനുകൾക്കൊപ്പം വിശ്വസിക്കാനാകാത്ത നിരീക്ഷണങ്ങളായി റെൻഡർ ചെയ്യുകയും ചെയ്യുന്നു. അസാധുവായതോ പരിധിക്ക് പുറത്തുള്ളതോ ഉറവിടസാക്ഷ്യമില്ലാത്തതോ ആയ ടെക്സ്റ്റ് ക്യാപ്ഷൻ സ്ട്രീമിൽ കലർത്തുന്നതിനുപകരം നിരസിക്കപ്പെടുന്നു. സ്വയം അവകാശപ്പെടുന്ന `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബലുകൾ ഉൾപ്പെടെ, രണ്ട് അഭ്യർത്ഥന-ബോഡി ട്രാൻസ്ക്രിപ്റ്റ് ചാനലുകളും നൽകിയ പ്രൊവനൻസ് `client` ആയി നോർമലൈസ് ചെയ്യുന്നു. സെർവറിന്റെ ഉടമസ്ഥതയിലുള്ള അഡാപ്റ്ററിന് മാത്രമേ കോഡ്-മാത്രമായ `trustedSource` ആർഗ്യുമെന്റിലൂടെ ആ വിശ്വസനീയ ലേബലുകൾ നൽകാനാകൂ; അഭ്യർത്ഥനയിലെ ഒരു JSON ഫീൽഡിനും ആ ആർഗ്യുമെന്റിൽ എത്താനാവില്ല. പ്രൊവനൻസ് എന്തായാലും, ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് വിശ്വസിക്കാനാകാത്ത, മീഡിയയിൽനിന്ന് ഉരുത്തിരിഞ്ഞ ഉള്ളടക്കമായി തുടരും; അത് ഒരിക്കലും ഓതറൈസേഷൻ നിർണയിക്കരുത്.

original part-നെ സ്ഥിരമായ `[Video description:` prefix ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു; അത്

നിലനിർത്തുന്നു; വ്യത്യസ്ത frames വ്യത്യസ്ത models ഉപയോഗിച്ച് നിർമ്മിച്ചപ്പോൾ bridge
`mixed` എന്ന് റിപ്പോർട്ട് ചെയ്യുന്നു. അഭ്യർത്ഥിച്ച routing plan ആയി വീണ്ടും label ചെയ്യുന്നതിനുപകരം
cache hit ആ producer identity വീണ്ടും ഉപയോഗിക്കുന്നു. Whole-video result

model, sampling policy, frame count, semantic analysis mode, normalized focus hint-ന്റെ SHA-256
fingerprint, focus window, `transcript`,
`audioTranscript`, contact-sheet flag — അതിനാൽ ഈ

പിന്തുണയ്ക്കുന്ന എല്ലാ video part-ുകളും guardrail extract ചെയ്യുന്നു, എന്നാൽ

`GET /api/modality-bridge/video/runtime`-ന് ഓതന്റിക്കേഷനോ റൺടൈം പരിശോധനയോ നടത്തുന്നതിന് മുമ്പ്,
വിശ്വസനീയമായി സ്റ്റാമ്പ് ചെയ്ത ലൂപ്പ്ബാക്ക് ലോക്കാലിറ്റി ആവശ്യമാണ്; തുടർന്ന് മാനേജ്മെന്റ്
ഓതന്റിക്കേഷനും ആവശ്യമാണ്. ഇത് `available`, ശുദ്ധീകരിച്ച FFmpeg/ffprobe പതിപ്പുകൾ, റൺടൈം ലഭ്യമല്ലാത്തപ്പോൾ
ഒരു സ്ഥിരമായ കാരണം എന്നിവ മാത്രമേ മടക്കി നൽകൂ. ആന്തരിക എക്സ്ട്രാക്ഷൻ എൻഡ്പോയിന്റ്
ഒരു പൊതു അപ്ലോഡ് API അല്ല: ക്യൂ സാച്ചുറേഷൻ `503`-ഉം `Retry-After`-ഉം മടക്കുന്നു, കോളർ
വിച്ഛേദിച്ചാൽ `499` മടക്കുന്നു, സ്ഥിരമായ ബ്രോക്കർ സമയപരിധി `504` മടക്കുന്നു. പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങൾ,
Vision അല്ലെങ്കിൽ Audio സെഗ്മെന്റുകൾ നീക്കം ചെയ്യാതെ, കേന്ദ്ര
`x-omniroute-modality-bridge` ഹെഡറിലേക്ക് `video->text;model=<visionModel>;parts=<videos>` ചേർക്കുന്നു.

### PII മാസ്കർ (`piiMasker.ts`)

**രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു.

- **`preCall`** പേലോഡ് ക്ലോൺ ചെയ്യുന്നു, `system`, `messages`, `input`, `prompt`
  (സാധാരണ സ്ട്രിംഗ് ഇനങ്ങൾ ഉൾപ്പെടെ) എന്നിവയിലൂടെ സഞ്ചരിക്കുകയും, സ്ട്രിംഗ് `content`/`text`
  ഫീൽഡുകളിൽ (`@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള) `processPII()` പ്രയോഗിക്കുകയും ചെയ്യുന്നു.
  `PII_REDACTION_ENABLED=true` ആയിരിക്കുമ്പോൾ, കണ്ടെത്തിയ PII ഔട്ട്ബൗണ്ട്
  പേലോഡിൽ തിരുത്തിമറയ്ക്കപ്പെടുന്നു. ഇത് `INPUT_SANITIZER_MODE`-ൽ നിന്ന് സ്വതന്ത്രമാണ് (അത്
  പ്രോംപ്റ്റ്-ഇഞ്ചക്ഷൻ നയം മാത്രമാണ് നിയന്ത്രിക്കുന്നത്). തിരുത്തിമറയ്ക്കൽ ഓഫായിരിക്കുമ്പോൾ, ഉള്ളടക്കം
  മാറ്റിയെഴുതാതെ കോൾ കണ്ടെത്തലുകളുടെ എണ്ണം രേഖപ്പെടുത്തുന്നു.
- **`postCall`** പ്രതികരണത്തെ ഡീപ്-ക്ലോൺ ചെയ്യുന്നു, `sanitizePIIResponse()`-ഉം
  Responses-API-ആകൃതി മാസ്കറും (`maskResponsesOutput` — `output_text`,
  `output[].content[].text` എന്നിവ ഉൾക്കൊള്ളുന്നു) പ്രവർത്തിപ്പിക്കുന്നു. എന്തെങ്കിലും തിരുത്തിമറയ്ക്കൽ സംഭവിച്ചാൽ,
  പരിഷ്കരിച്ച പ്രതികരണം യഥാർത്ഥ പ്രതികരണത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.

ഗാർഡ്റെയിൽ ഒരിക്കലും തടയുന്നില്ല; അത് അനോട്ടേറ്റ് (`meta.detections`,
`meta.redacted`) ചെയ്യുകയോ മാറ്റിയെഴുതുകയോ മാത്രം ചെയ്യുന്നു.

### പ്രോംപ്റ്റ് ഇഞ്ചക്ഷൻ (`promptInjection.ts`)

ഉപയോക്താവ് നൽകിയ ഉള്ളടക്കത്തിലെ ആക്രമണാത്മക ഘടനകൾ കണ്ടെത്തുകയും കോൺഫിഗർ ചെയ്ത
നയം നടപ്പിലാക്കുകയും ചെയ്യുന്നു. എൻവയോൺമെന്റ് വേരിയബിളുകളും കൺസ്ട്രക്റ്റർ
ഓപ്ഷനുകളുമാണ് പ്രവർത്തനം നിയന്ത്രിക്കുന്നത്:

| ക്രമീകരണം              | എൻവ് വേരിയബിൾ                                                                                          | ഡിഫോൾട്ട് | പ്രഭാവം                                                                                                                                                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------ | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| പ്രവർത്തനക്ഷമമാക്കിയത് | `INPUT_SANITIZER_ENABLED`                                                                              | `true`    | `false` ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ തുടർനടപടികൾ ഒഴിവാക്കി ഉടൻ മടങ്ങുന്നു.                                                                                                                                                                  |
| മോഡ്                   | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                        | `warn`    | ഇഞ്ചക്ഷൻ നയം: `block`, `warn`, അല്ലെങ്കിൽ `log`. (പിന്നോട്ടുള്ള അനുയോജ്യതയ്ക്കായി `redact` സ്വീകരിക്കുമെങ്കിലും, അത് ഇഞ്ചക്ഷൻ ടെക്സ്റ്റ് നീക്കം ചെയ്യുന്നില്ല; റിക്വസ്റ്റ് PII മാറ്റിയെഴുത്ത് `PII_REDACTION_ENABLED` നിയന്ത്രിക്കുന്നു.) |
| തടയൽ പരിധി             | `blockThreshold` ഓപ്ഷൻ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (അപരനാമം `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`    | തടയാൻ ആവശ്യമായ ഏറ്റവും കുറഞ്ഞ തീവ്രത. ഡിഫോൾട്ടായി Medium നിരീക്ഷണത്തിന് മാത്രമുള്ളതാണ്.                                                                                                                                                   |

**മോഡ് മുൻഗണന** (`getMode`): കോളർ `options.mode` →
`INJECTION_GUARD_MODE` **DB ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (Dashboard → Settings →
Feature Flags) → `INJECTION_GUARD_MODE` എൻവ് → `INPUT_SANITIZER_MODE` എൻവ് →
`warn`. അതിനാൽ ഡാഷ്ബോർഡ് ഓവർറൈഡിന് എൻവ് വേരിയബിളുകളേക്കാൾ മുൻഗണനയുണ്ട്, അതുകൊണ്ട് Feature
Flags UI പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഗാർഡിനെ തത്സമയം നിയന്ത്രിക്കുന്നു (പുനരാരംഭം ആവശ്യമില്ല). DB റീഡ് പരാജയ-സുരക്ഷിതമാണ്:
അതിൽ പിശക് സംഭവിച്ചാൽ, ഗാർഡ് എൻവ് അടിസ്ഥാനമാക്കിയുള്ള പ്രവർത്തനത്തിലേക്ക് മടങ്ങുന്നു; കൂടാതെ
ഓവർറൈഡ് സജ്ജമാക്കിയിട്ടില്ലെങ്കിൽ, പ്രവർത്തനം എൻവ്-മാത്രം റെസല്യൂഷനോട് സമാനമായിരിക്കും.

കണ്ടെത്തൽ ഉറവിടങ്ങൾ:

1. `@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള `sanitizeRequest()` (പൈപ്പ്ലൈനിലെ
   മറ്റ് ഇടങ്ങളിലും ഉപയോഗിക്കുന്ന പങ്കിട്ട ഡിറ്റക്ടർ സെറ്റ്).
2. ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (നിലവിൽ `system_override_inline`,
   `markdown_system_block`; രണ്ടിനും `high` തീവ്രത).
3. കൺസ്ട്രക്റ്റർ ഓപ്ഷനുകൾ വഴി നൽകുന്ന ഐച്ഛിക `customPatterns` (സ്ട്രിംഗുകൾ, റെഗെക്സ്,
   അല്ലെങ്കിൽ `{ name, pattern, severity }` റെക്കോർഡുകൾ).

`mode === "block"` **ആയിരിക്കുകയും** കുറഞ്ഞത് ഒരു കണ്ടെത്തലെങ്കിലും തീവ്രതാ
പരിധി പാലിക്കുകയും ചെയ്യുമ്പോൾ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` മടക്കിനൽകുന്നു. `warn`/`log` മോഡുകളിൽ ഗാർഡ്റെയിൽ ലോഗ്
ചെയ്യുമെങ്കിലും കോൾ അനുവദിക്കുന്നു. രജിസ്ട്രിയിലൂടെ കടന്നുപോകാതെ പ്രോംപ്റ്റുകൾ
വിലയിരുത്തേണ്ട കോളർമാർക്കായി പങ്കിട്ട ഹെൽപ്പറായ `evaluatePromptInjection()`-ഉം എക്സ്പോർട്ട്
ചെയ്യുന്നു.

**സ്കാൻ പരിധി (v3.8.20):** സംയോജിപ്പിച്ച പ്രോംപ്റ്റ് ടെക്സ്റ്റിന്റെ **ആദ്യത്തെ 16 KB** മാത്രമാണ്
ഡിറ്റക്ടർ പരിശോധിക്കുന്നത് — `src/shared/utils/inputSanitizer.ts`-ൽ
`MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ). പാറ്റേൺ ലൂപ്പ് പ്രവർത്തിപ്പിക്കുന്നതിന്
മുമ്പ് `detectInjection()`-ഉം `evaluatePromptInjection()`-ഉം
`slice(0, MAX_INJECTION_SCAN_BYTES)` പ്രയോഗിക്കുന്നു. ഇൻജക്ഷൻ നിർദ്ദേശങ്ങൾ ഇൻപുട്ടിന്റെ
തുടക്കത്തിനടുത്താണ് വരുന്നത്, അതിനാൽ കണ്ടെത്തലിന്റെ ശക്തി കുറയ്ക്കാതെ, നൂറുകണക്കിന്-KB
പേലോഡുകളിലെ regex CPU/GC ഉപയോഗത്തിന് ഇത് പരിധി നിശ്ചയിക്കുന്നു (കാണുക:
#3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്കർ (`credentialMasker.ts`)

ഡിഫോൾട്ട് ചെയിനിൽ അവസാനം (മുൻഗണന `95`) **രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു. ഔട്ട്ബൗണ്ട്
പേലോഡിൽ (സന്ദേശ ഉള്ളടക്കം, ടൂൾ-കോൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ ഫലങ്ങൾ) **കൂടാതെ** പ്രൊവൈഡർ
പ്രതികരണത്തിലും കാണപ്പെടുന്ന അറിയപ്പെടുന്ന API-key / secret-token പാറ്റേണുകൾ മറയ്ക്കുന്നു.
അതിനാൽ ഒരു പ്രോംപ്റ്റിൽ ഒട്ടിച്ച ക്രെഡൻഷ്യലോ (അല്ലെങ്കിൽ ഒരു ടൂൾ ഫലം തിരികെ
പ്രതിധ്വനിപ്പിക്കുന്നതോ) അപ്സ്ട്രീം പ്രൊവൈഡറിലേക്കോ ക്ലയന്റിലേക്കോ ചോരുകയില്ല.

- **വ്യക്തമായി പ്രവർത്തനക്ഷമമാക്കിയാൽ മാത്രം**, PII റിഡാക്ഷനിലെ അതേ രീതി (Hard Rule #20-നോട്
  അനുബന്ധം): `settings.credentialRedactionEnabled === true` **അല്ലെങ്കിൽ**
  `CREDENTIAL_REDACTION_ENABLED=true` അല്ലെങ്കിൽ പ്രവർത്തനരഹിതമായിരിക്കും. ഇത് ഓഫ്
  ആയിരിക്കുമ്പോൾ ഗാർഡ്റെയിൽ യാതൊരു പ്രവർത്തനവും നടത്തില്ല — അത് ഒരിക്കലും ബ്ലോക്ക്
  ചെയ്യുകയോ മാറ്റിയെഴുതുകയോ ഇല്ല.
- `redactCredentials()` മുഴുവൻ പേലോഡ്/പ്രതികരണ ട്രീയിലൂടെയും (`walkValue()`,
  പ്രോട്ടോടൈപ്പ്-പൊല്യൂഷനിൽനിന്ന് സുരക്ഷിതം, `WeakSet` മുഖേന സൈക്കിൾ-സുരക്ഷിതം) സഞ്ചരിച്ച്
  പൊരുത്തങ്ങളെ `[REDACTED:<type>]` പ്ലേസ്ഹോൾഡർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു; യഥാർത്ഥത്തിൽ
  മാറ്റം വന്ന ബ്രാഞ്ചുകൾ മാത്രം ക്ലോൺ ചെയ്യുന്നു.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ടോക്കണുകൾ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square), ക്ലൗഡ്
  കീകൾ (AWS access key, Twilio, SendGrid, Mailgun), പ്രൈവറ്റ് കീകൾ / JWT-കൾ,
  ക്രെഡൻഷ്യലുകൾ ഉൾക്കൊള്ളുന്ന കണക്ഷൻ സ്ട്രിങ്ങുകൾ (`mongodb://user:pass@...` മുതലായവ), കൂടാതെ
  പൊതുവായ `Authorization`/`x-api-key`/`api-key`/`apikey` ഹെഡർ-വാല്യു
  പാറ്റേൺ എന്നിവ ഉൾക്കൊള്ളുന്നു. ഹെഡറിന്റെ രൂപത്തിലുള്ള കീകൾ (`authorization`, `x-api-key`, `api-key`,
  `apikey`) പൊതുവായ ടെക്സ്റ്റ് regex വഴിയല്ല, ഘടനാപരമായാണ് (വാല്യു മാത്രം; `Bearer `/`Basic `
  പോലുള്ള സ്കീം പ്രിഫിക്സ് നിലനിർത്തുന്നു) മറയ്ക്കുന്നത്.
- ഗാർഡ്റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുന്നില്ല; അത് മാറ്റിയെഴുതുകയും (`modifiedPayload` /
  `modifiedResponse`) അനോട്ടേറ്റ് ചെയ്യുകയും (`meta.credentialsRedacted`, `meta.count`) മാത്രമാണ്
  ചെയ്യുന്നത്.

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (base.ts)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true short-circuits the chain
  message?: string; // തടയുമ്പോൾ ഇത് ദൃശ്യമാകും
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന മാറ്റിയെഴുതാൻ preCall തിരികെ നൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം മാറ്റിയെഴുതാൻ postCall തിരികെ നൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ഒരു ഗാർഡ്റെയിൽ "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നത് ``void`, `{}`, അല്ലെങ്കിൽ `{ block: false }`തിരികെ നൽകിക്കൊണ്ടാണ്.`modifiedPayload`/`modifiedResponse`തിരികെ നൽകുന്നത്, താഴെയുള്ള ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.`signal?: AbortSignal` കോളർ ലൈഫ്സൈക്കിളിനെ ഗാർഡ്റെയിലുകളിലേക്ക് എത്തിക്കുന്നു. ഒരു അഭ്യർത്ഥന റദ്ദാക്കൽ എന്നത് മനഃപൂർവമായ ഒരു ഫെയിൽ-ഓപ്പൺ അപവാദമാണ്: മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തിക്കുന്നത് നിർത്തുകയും, അസംസ്കൃത മീഡിയയെ പിന്തുണയ്ക്കാത്ത ഒരു ലക്ഷ്യസ്ഥാനത്തേക്ക് പുനഃസ്ഥാപിക്കാതെ വൃത്തിയാക്കുകയും ചെയ്യുന്നു.

## രജിസ്ട്രി (registry.ts)

സിംഗിൾട്ടൺ `guardrailRegistry` താഴെ പറയുന്നവ നൽകുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ സാധാരണമാക്കിയ പേര് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു) കൂടാതെ ആരോഹണ ക്രമത്തിൽ `priority` അനുസരിച്ച് വീണ്ടും ക്രമീകരിക്കുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് സഹായികൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, `modifiedPayload` വഴി പേലോഡിനെ കടത്തിവിടുന്നു, കൂടാതെ ആദ്യത്തെ `block: true` വരുമ്പോൾ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ ഭാഗത്തും ഇതേ പ്രവാഹം.
- `resetGuardrailsForTests({ registerDefaults })` — നിലവിലെ അവസ്ഥ മായ്ക്കുന്നു കൂടാതെ വൃത്തിയുള്ള ടെസ്റ്റ് ഐസൊലേഷനായി ഡിഫോൾട്ടുകൾ ഓപ്ഷണലായി വീണ്ടും രജിസ്റ്റർ ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` തിരികെ നൽകുന്നു, ഇവിടെ `results` എന്നത് `GuardrailExecutionResult` റെക്കോർഡുകളുടെ ഒരു നിരയാണ്, അതിൽ ഓരോ ഗാർഡ്റെയിലിനുമുള്ള `blocked`, `skipped`, `modified`, `error`, `meta` ഫീൽഡുകൾ ഉൾപ്പെടുന്നു, ഇത് ട്രേസിംഗിന് ഉപയോഗപ്രദമാണ്.

### ഓരോ അഭ്യർത്ഥനയ്ക്കും ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കുന്നു

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` നിലവിലെ അഭ്യർത്ഥനയ്ക്കായി ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ ഡ്യൂപ്ലിക്കേഷൻ ഒഴിവാക്കിയ ഒരു ലിസ്റ്റ് ശേഖരിക്കുന്നു. ഉറവിടങ്ങൾ (എല്ലാം ഓപ്ഷണൽ, എല്ലാം ലയിപ്പിച്ചത്):

- `apiKeyInfo.disabledGuardrails`
- അഭ്യർത്ഥന ബോഡി `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
- അഭ്യർത്ഥന ബോഡി `metadata.disabledGuardrails`
- ഹെഡർ `x-omniroute-disabled-guardrails` (അല്ലെങ്കിൽ പഴയ `x-disabled-guardrails`)

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ നിരകളോ കോമയാൽ വേർതിരിച്ച സ്ട്രിംഗോ ആകാം; പേരുകൾ ലോവർകേസ് കെബാബ്-കേസിലേക്ക് സാധാരണമാക്കുന്നു (`pii_masker` → `pii-masker`). ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു, ഇത് പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകളെ ഒഴിവാക്കുന്നു (`results`-ൽ `skipped: true`).

## എക്സിക്യൂഷൻ ഓർഡർ

`src/sse/handlers/chat.ts`, `open-sse/handlers/chatCore.ts` എന്നിവയിലൂടെ ഒഴുകുന്ന ഓരോ അഭ്യർത്ഥനയ്ക്കും:

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽ നിന്ന് സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ഗാർഡ്റെയിലുകൾ ആരോഹണ മുൻഗണനാ ക്രമത്തിൽ പ്രവർത്തിപ്പിക്കുന്നു:
   - പ്രവർത്തനരഹിതമാക്കിയ ഗാർഡ്റെയിലുകൾ `skipped` എന്ന് രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall` `modifiedPayload` വഴി പേലോഡ് മാറ്റിയെഴുതിയേക്കാം.
   - ആദ്യത്തെ `block: true` ചെയിൻ ചുരുക്കുകയും ഹാൻഡ്ലർ ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം നൽകുകയും ചെയ്യുന്നു.
3. (സാധ്യതയുള്ള മാറ്റിയെഴുതിയ) പേലോഡ് കോംബോ റൂട്ടിംഗിലേക്കും അപ്സ്ട്രീം ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. പ്രതികരണം കൂട്ടിച്ചേർത്ത ശേഷം, `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിൽ അതേ ചെയിൻ പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` അപ്സ്ട്രീം പ്രതികരണം ഒഴിവാക്കുന്നു.

തെറ്റ് വരുത്തുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും `logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു, പക്ഷേ ചെയിൻ തുടരുന്നു — രൂപകൽപ്പന പ്രകാരം ഫെയിൽ-ഓപ്പൺ.

## കോൺഫിഗറേഷൻ

ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | പ്രഭാവം                                                                                                             |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | കണ്ടെത്തൽ പൂർണ്ണമായും പ്രവർത്തനരഹിതമാക്കാൻ `false` എന്ന് സജ്ജമാക്കുക.                                               |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ പോളിസി: `warn`, `block`, അല്ലെങ്കിൽ `log`. പഴയ മൂല്യം `redact` ഇൻജക്ഷൻ ടെക്സ്റ്റ് മാറ്റിയെഴുതുന്നില്ല.      |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ ഗാർഡിനായുള്ള മോഡ്; എൻവയോൺമെന്റ് വേരിയബിളുകളെ **അസാധുവാക്കുന്ന** ഒരു DB ഫീച്ചർ ഫ്ലാഗ് കൂടിയാണിത് (DB > ENV). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (സ്ഥിരസ്ഥിതി), `medium`, അല്ലെങ്കിൽ `low`.                  |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` എന്നതിന്റെ പഴയ പേര്.                                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആയിരിക്കുമ്പോൾ, അഭ്യർത്ഥന PII റെഡാക്ട് ചെയ്യപ്പെടുന്നു (ഇൻജക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രമായി).                 |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ഡൗൺസ്ട്രീം) | പ്രതികരണ-വശത്തുള്ള മാസ്കർ സ്വഭാവം നിയന്ത്രിക്കുന്നു.                                                                |

മോഡാലിറ്റി ബ്രിഡ്ജ് ഗാർഡ്റെയിലുകൾ DB-ബാക്ക്ഡ് സെറ്റിംഗ്സ് സ്റ്റോറിൽ നിന്ന് (`getSettings()`) റൺടൈം കോൺഫിഗറേഷൻ വായിക്കുന്നു, എൻവയോൺമെന്റ് വേരിയബിളുകളിൽ നിന്നല്ല. വിഷന്റെ പ്രാഥമിക കീകൾ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാണ്. പഴയ `visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്ത വൺ-സൈക്കിൾ റീഡ് ഫാൾബാക്കായി മാത്രമേ സ്വീകരിക്കുകയുള്ളൂ; ഡാഷ്ബോർഡ് റൈറ്റുകൾ പ്രാഥമിക കീകൾ ഉപയോഗിക്കുന്നു. സ്ഥിരസ്ഥിതികളും ഫാൾബാക്ക് റെസല്യൂവറും `src/shared/constants/modalityBridgeDefaults.ts` എന്നതിലാണ്, പഴയ സ്ഥിരാങ്കങ്ങൾ `src/shared/constants/visionBridgeDefaults.ts` എന്നതിൽ നിലനിർത്തുന്നു.

ഓഡിയോ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. മോഡാലിറ്റി ബ്രിഡ്ജ് സ്കീമയോടൊപ്പം ഈ കീകൾ അവതരിപ്പിച്ചതിനാൽ ഓഡിയോയ്ക്ക് പഴയ-കീ ഫാൾബാക്ക് ഇല്ല.

വീഡിയോ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, `modalityBridgeVideoTimeout` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. FFmpeg/ffprobe ഓപ്ഷണൽ ഓപ്പറേഷണൽ ഡിപൻഡൻസികളും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും മോഡൽ ചെലവും വർദ്ധിപ്പിക്കുന്നതിനാൽ ഇത് സ്ഥിരസ്ഥിതിയായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു.

## കസ്റ്റം ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1.  `BaseGuardrail` വികസിപ്പിച്ച് `src/lib/guardrails/myGuardrail.ts` ഉണ്ടാക്കുക.
2.  `preCall`, `postCall` എന്നിവ നടപ്പിലാക്കുക.
3.  ഇറക്കുമതി ചെയ്യുന്ന സമയത്ത് ( `registerDefaultGuardrails` ൽ നിന്ന് പുഷ് ചെയ്യുക) അല്ലെങ്കിൽ റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — രജിസ്ട്രി, അതേ സാധാരണവൽക്കരിച്ച പേരുള്ള മുൻ ഗാർഡ്റെയിലിനെ മാറ്റിസ്ഥാപിക്കും.
4.  `tests/unit/` ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ: `tests/unit/guardrails-registry.test.ts`, `tests/unit/prompt-injection-guard.test.ts`, `tests/unit/guardrails/visionBridge.test.ts`).

## പരിശോധന

അറിയപ്പെടുന്ന അവസ്ഥയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക. ശൂന്യമായ ഒരു രജിസ്ട്രിയിൽ നിന്ന് ആരംഭിച്ച്, പരിശോധനയിലുള്ള ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ ചെയ്യാൻ `{ registerDefaults: false }` നൽകുക. വിഷൻ ബ്രിഡ്ജ് ഡിപൻഡൻസി ഇൻജക്ഷൻ (`deps.getSettings`, `deps.callVisionModel`) സ്വീകരിക്കുന്നു; ഓഡിയോ ബ്രിഡ്ജ് ക്രമീകരണങ്ങൾ, കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുക്കൽ, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കായി സമാനമായ സീമുകൾ നൽകുന്നു. അതിനാൽ, ഡാറ്റാബേസ് അല്ലെങ്കിൽ നെറ്റ്വർക്ക് ആക്സസ് ഇല്ലാതെ തന്നെ ടെസ്റ്റുകൾക്ക് രണ്ട് ഫ്ലോകളും പ്രവർത്തിപ്പിക്കാൻ കഴിയും.

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജ് & റെഡ്-ടീം (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഇൻജക്ഷൻ-ഗാർഡ് (`createInjectionGuard` / `withInjectionGuard`) ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളെയും ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE` നെ മാനിക്കുന്നു (സ്ഥിരസ്ഥിതി `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` തിരികെ നൽകുന്നു).

| തരം             | റൂട്ടുകൾ                                                                                                                                      | സ്ഥിരസ്ഥിതി മോഡ് |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| Text (existing) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                       | warn             |
| Generative      | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn             |
| Data            | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                               | warn             |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയെ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (രാത്രികാല, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` ആയിരിക്കുമ്പോൾ ഓരോ റൂട്ടും OWASP-LLM കോർപ്പസിനെ തടയുന്നുവെന്ന് promptfoo സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ പ്രവർത്തിപ്പിക്കുന്നു (രഹസ്യമില്ലാതെ ഒഴിവാക്കുന്നു). സ്ഥിരതയ്ക്കായി `moderations` ഉൾപ്പെടുത്തിയിട്ടുണ്ട് — ബ്ലോക്ക്-മോഡിലുള്ള ഓപ്പറേറ്റർമാർക്ക് `resolveDisabledGuardrails` വഴി ഇതിനെ ഒഴിവാക്കാം.

രാത്രികാല വർക്ക്ഫ്ലോ (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ ഡിസ്പാച്ച്) ന് രണ്ട് ജോലികളുണ്ട്:

- **`promptfoo-guard` (തടയുന്നത്)** — `INJECTION_GUARD_MODE=block` ഉപയോഗിച്ച് `promptfoo eval -c promptfooconfig.yaml` പ്രവർത്തിപ്പിക്കുന്നു. ഓരോ പ്രതികൂല സാഹചര്യവും (ഉദാഹരണത്തിന്, "മുമ്പത്തെ എല്ലാ നിർദ്ദേശങ്ങളും അവഗണിക്കുക...", DAN-ശൈലിയിലുള്ള ജയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശക)** — ഒരു പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പ്രൊവൈഡർ രഹസ്യം (`PROMPTFOO_PROVIDER_KEY`) വഴി നിയന്ത്രിക്കപ്പെടുന്നു; ഇത് ഭംഗിയായി ഒഴിവാക്കുകയും `|| true` എന്ന് ചേർക്കുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടാതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`) കവറേജ് എല്ലാ പ്രോംപ്റ്റ്-ഉൾക്കൊള്ളുന്ന `/v1` റൂട്ടുകളിലും വ്യാപിക്കുന്നു; പ്രോംപ്റ്റ് ടെക്സ്റ്റ് `src/shared/utils/inputSanitizer.ts` ലെ `extractMessageContents()` വഴി `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയിൽ നിന്ന് വലിച്ചെടുക്കുന്നു.
