> کلیدهای runtime که رفتار OmniRoute را **بدون استقرار مجدد** تغییر میدهند.
> تمام فلگهای فهرستشده در اینجا در
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> تعریف شدهاند — منبع واحد حقیقت. داشبورد و REST API هر دو از
> آن فایل میخوانند، بنابراین جدول زیر بهگونهای تولید شده است که دقیقاً بهصورت 1:1 با آن مطابقت داشته باشد.

## فلگهای قابلیت چیستند

فلگ قابلیت یک کلید نامگذاریشده (از نوع boolean یا enum) است که مقدار آن را میتوان در
runtime تغییر داد و در پایگاه داده ذخیره کرد، بدون اینکه نیاز به استقرار مجدد فرایند باشد. هر
فلگ با یک `FeatureFlagDefinition` توصیف میشود که شامل `key`، `label`،
`description`، `category`، `defaultValue`، `type` و راهنمای `requiresRestart` است.

### ترتیب تعیین مقدار

**مقدار مؤثر** یک فلگ توسط
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) و با ترتیب
اولویت زیر تعیین میشود (بالاترین اولویت برنده است):

1. **بازنویسی DB** — مقداری که در جدول `key_value` و در فضای نام
   `feature_flags` ذخیره شده است (از طریق داشبورد یا REST API تنظیم میشود).
2. **متغیر محیطی** — `process.env[<KEY>]`، در صورتی که تنظیم شده و خالی نباشد.
3. **مقدار پیشفرض تعریف** — مقدار `defaultValue` از `featureFlagDefinitions.ts`.

یک فلگ boolean زمانی **فعال** در نظر گرفته میشود که مقدار مؤثر آن `"true"`،
`"1"` یا `"yes"` باشد (`isFeatureFlagEnabled()` را ببینید).

> [!NOTE]
> بیشتر فلگها همچنین یک متغیر محیطی متناظر با **همان نام** دارند
> که در [`ENVIRONMENT.md`](./ENVIRONMENT.md) مستند شده است. بازنویسی DB فلگ
> نسبت به آن متغیر محیطی اولویت دارد. فلگی با
> `requiresRestart: true` بلافاصله ذخیره میشود، اما فقط هنگام راهاندازی
> فرایند دوباره خوانده میشود — تغییر آن، بنر **«راهاندازی مجدد سرور»** را در داشبورد نمایش میدهد.

## فهرست فلگها

۸۶ فلگ در ۶ دسته. **پیشفرض**، مقدار پیشفرض تعریف است — مقداری که وقتی نه بازنویسی در DB و نه متغیر محیطی وجود داشته باشد، استفاده میشود.

## تغییر وضعیت پرچمها

### داشبورد

به **داشبورد ← تنظیمات ← پرچمهای ویژگی** (`/dashboard/settings/feature-flags`) بروید. گرید
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
از موارد زیر پشتیبانی میکند:

- **جستجو** بر اساس کلید یا توضیحات، و **فیلتر** بر اساس دستهبندی (به علاوه یک نمای ترکیبی **نیاز به راهاندازی مجدد**).
- یک **تغییر وضعیت (toggle)** برای پرچمهای بولی و یک **منوی کشویی (dropdown)** برای پرچمهای شمارشی
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- یک **نشان منبع** برای هر پرچم — `DB`، `ENV`، یا `DEF` — که نشان میدهد مقدار مؤثر از کجا آمده است.
- یک دکمه **بازنشانی (Reset)** (فقط برای پرچمهای با منبع `DB` نمایش داده میشود) برای حذف بازنویسی،
  و یک دکمه **بازنشانی همه بازنویسیها (Reset All Overrides)** در پایین.
- یک بنر **راهاندازی مجدد سرور (Restart Server)** هنگام تغییر پرچمی که `requiresRestart` است.

### API REST

تمام عملیات از طریق یک مسیر واحد انجام میشود:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
هر متد نیاز به یک نشست داشبورد احراز هویت شده دارد (در غیر این صورت `401`).

#### `GET /api/settings/feature-flags`

هر پرچم را با مقدار مؤثر، منبع و خلاصهای از آن برمیگرداند.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... همه ۷۷ پرچم
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

یک بازنویسی واحد را تنظیم یا حذف میکند. بدنه: `{ key: string; value?: string }`.
حذف `value` بازنویسی را حذف میکند (و مقدار محیطی / پیشفرض را بازیابی میکند).

```bash
# یک بازنویسی DB را تنظیم کنید
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# بازنویسی را حذف کنید (بدون "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

پاسخ، `effectiveValue`/`source` جدید، `previousValue`/
`previousSource` قبلی، و `requiresRestart` را بازتاب میدهد. کلیدهای ناشناخته و مقادیر شمارشی خارج از محدوده
با `400` رد میشوند.

#### `DELETE /api/settings/feature-flags`

**تمام** بازنویسیهای DB را یکباره پاک میکند و هر پرچم را به مقدار محیطی / پیشفرض خود بازمیگرداند. `{ cleared: <count>, message: "..." }` را برمیگرداند.

> [!NOTE]
> پرچمهایی که `requiresRestart: true` دارند، تنها پس از بارگذاری مجدد فرآیند اعمال میشوند.
> جریان راهاندازی مجدد داشبورد، `POST /api/restart` را فراخوانی میکند و سپس
> `GET /api/health/ping` را تا زمانی که سرور دوباره فعال شود، نظرسنجی میکند.

## جایگزین اضطراری بودجه

`OMNIROUTE_EMERGENCY_FALLBACK` (دستهٔ `runtime`، مقدار پیشفرض `true`) مسیر
جایگزین رایگان اضطراری را در
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
کنترل میکند. هنگامی که فعال باشد، درخواستهایی که بودجهٔ خود را به پایان
رساندهاند، بهجای شکست کامل، به یک ارائهدهنده/مدل جایگزین رایگان هدایت
میشوند. برای غیرفعال کردن این رفتار و شکست خوردن درخواستهایی که بودجهشان
تمام شده است، آن را — از طریق کلید داشبورد، بازنویسی DB یا متغیر محیطی
`OMNIROUTE_EMERGENCY_FALLBACK` — روی `false` (یا `0`) تنظیم کنید. (در PRهای
#3741 / #3752 بهصورت یک کلید داشبورد ارائه شده است.)

پاسخی که توسط این جایگزین ارائه میشود، دارای هدر
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` است؛
بنابراین، کلاینت بدون مقایسهٔ `X-OmniRoute-Provider` با درخواست خود میتواند
تشخیص دهد که درخواست دوباره مسیریابی شده است. این هدر در هیچ پاسخ دیگری وجود
ندارد.
