تفرض الحواجز (Guardrails) السلامة والسياسة وتحويلات المحتوى عند الحدود
بين OmniRoute ومقدمي الخدمة المصدر. يمكن لكل حاجز فحص (ورفض أو تحويل أو إضافة تعليق اختياريًا) حمولات الطلبات (`preCall`)
واستجابات المصدر (`postCall`).

النظام **مفتوح عند الفشل (fail-open)**: إذا ألقى حاجز خطأ أثناء التنفيذ، فإن السجل
يسجل الخطأ ويستمر مع الحاجز التالي بدلاً من إفشال الطلب.
المنع هو قرار صريح (`block: true`)، وليس حادثًا أبدًا.

## حواجز الحماية المضمّنة

يحمّل السجل تلقائيًا ستة حواجز حماية بترتيب الأولوية عند الاستيراد
(راجع `registry.ts` → `registerDefaultGuardrails()`):

| الأولوية | الاسم               | المرحلة/المراحل | الملف                 |
| -------- | ------------------- | --------------- | --------------------- |
| `5`      | `vision-bridge`     | `preCall`       | `visionBridge.ts`     |
| `6`      | `audio-bridge`      | `preCall`       | `audioBridge.ts`      |
| `7`      | `video-bridge`      | `preCall`       | `videoBridge.ts`      |

### جسر الرؤية (`visionBridge.ts`) — جسر الأنماط PR-1

يعترض الطلبات التي تحتوي على صور والموجّهة إلى **نماذج لا تدعم الرؤية**، ثم
يعيد توجيه الطلب بأكمله إلى نموذج يدعم الرؤية، أو يستبدل أجزاء الصور
بأوصاف نصية ينتجها نموذج رؤية قابل للتهيئة قبل إجراء الاستدعاء إلى الخدمة
المنبع. يتيح ذلك لموفّري النماذج النصية فقط التعامل بشفافية مع
الحمولات متعددة الأنماط.

التدفق:

1. التخطي إذا كان النموذج المستهدف يدعم الرؤية بالفعل (ما لم يكن مدرجًا في
   قائمة فرض استخدام الجسر `isVisionBridgeForcedModel`).
2. استخراج أجزاء الصور عبر `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`)، التي تفوّض المهمة إلى **كاشف الوسائط
   الموحّد** `detectMediaParts()` في `open-sse/utils/mediaParts.ts` — وهو
   المصدر الوحيد للحقيقة والمشترك مع مرشح توافق التجميعات.
   يقتصر الاستخراج، وفق قائمة سماح، على الأجزاء ذات المستوى الأعلى وبالأشكال
   التي يمكن لـ `replaceImageParts` إعادة إدراجها (عقد الاستخراج↔الاستبدال):
   `image_url` في OpenAI، و`source.type:"base64"` بترميز base64 في Anthropic،
   و`source.type:"url"` في Anthropic، و`input_image` في Responses API. أما
   النتائج المتداخلة والأشكال التي تقتصر على مؤشرات، فهي مواد لمرشح التجميعات
   ولا تُستخرج أبدًا. يتم التخطي إذا لم يُعثر على أي منها.
3. تحديد إعدادات وقت التشغيل عبر `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): تكون الأولوية لمفاتيح
   الإعدادات الجديدة `modalityBridge*`؛ وتظل مفاتيح `visionBridge*` القديمة
   **خيارًا احتياطيًا لدورة واحدة** (نافذة التراجع). يتم التخطي قبل أي استعراض
   للوسائط عندما يكون الجسر معطّلًا.
4. يحدد منتقي الوضع (`modalityBridgeVisionMode`، راجع الجدول أدناه) ما إذا
   كان سيُعاد التوجيه أم سيُنشأ وصف. تُرجع إعادة التوجيه `modifiedPayload`
   مع تبديل `model` فقط، إلى جانب البيانات الوصفية
   `{ rerouted, fromModel, toModel, imagesKept }`.
5. مسار الوصف: يقيّد عدد الصور عند `maxImages`، ويُنشئ الموجّه المدرك للمهمة،
   ويراجع ذاكرة التخزين المؤقت للأوصاف، ويستدعي نموذج الرؤية **بالتوازي**
   (`Promise.allSettled`)، ثم يحقن أجزاء نصية بالصيغة
   `[الصورة N]: <الوصف>` مكانها. يُنتج فشل الوصف `null` مع **الاحتفاظ**
   بجزء الصورة الأصلي (#4012) — باستثناء مسار وصف التجميعات عندما تفشل
   جميع عمليات الوصف، إذ تتلقى الخدمة المنبع التي تأكد عدم دعمها للرؤية
   عنصرًا نائبًا `(غير متاح — لا يوجد موفّر يدعم الرؤية متصل)` بدلًا منه
   (#8430).
6. إرجاع `modifiedPayload` + البيانات الوصفية (`imagesProcessed`،
   `descriptions`، `processingTimeMs`، `visionModel`).

#### منتقي الوضع (`modalityBridgeVisionMode`)

| الوضع      | الافتراضي | السلوك                                                                                                                                                                                                                                                           |
| ---------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔         | خوارزمية الكشف القديمة، من دون تغيير (#6640/#7204): تُعاد توجيه النماذج غير المجمّعة/نماذج `auto/` إلى أفضل نموذج رؤية، ما لم يكن لدى النموذج الأصلي بيانات اعتماد قابلة للاستخدام (وعندها يُنشأ وصف)؛ أما أهداف التجميعات فتُنشئ وصفًا دائمًا.                  |
| `describe` |           | إنشاء وصف دائمًا — يتم تخطي كتلة إعادة التوجيه بالكامل؛ ويظل النموذج الذي اختاره المستخدم هو من يجيب دائمًا.                                                                                                                                                     |
| `reroute`  |           | فرض إعادة التوجيه: يتم تجاوز حاجز الاحتفاظ بالنموذج ذي بيانات الاعتماد. ويظل حاجز بيانات اعتماد **هدف** إعادة التوجيه ساريًا — فعندما لا يتوفر هدف رؤية قابل للاستخدام، ينتقل الطلب إلى إنشاء الوصف كي لا تصل الصور الخام أبدًا إلى خدمة خلفية نصية فقط (#8430). |

تختصر الأوضاع المفروضة المسار **قبل** تشغيل خوارزمية الكشف التلقائي؛ ويكون
سلوك `auto` مطابقًا على مستوى البايتات لحاجز الحماية السابق لـ PR-1.

#### نطاق مفتاح API (`visionBridgeKeyScope.ts`)

عندما يقيّد مفتاح API الخاص بالمتصل `allowedConnections`، أو مجموعات الحصص
(`allowedQuotas`)، أو النماذج (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`)، لا يختار الجسر
إلا نماذج إعادة التوجيه والوصف التي يسمح المفتاح باستخدامها، وعبر الاتصالات
التي يسمح المفتاح باستخدامها. بعد ذلك، يمر استدعاء الوصف دائمًا عبر الحلقة
الذاتية لـ OmniRoute مع ترويسة `x-omniroute-self-loop-key-id`، بحيث يفرض طلب
المحادثة المستقبِل سياسة الاتصالات والنماذج الخاصة بذلك المفتاح مرة أخرى.
لا يعتد `enforceApiKeyPolicy()` بهذه الترويسة إلا مع رمز الحامل الخاص بالحلقة
الذاتية، ولذلك لا يمكنه إلا تضييق نطاق الوصول، ويُرفض أي معرّف يتعذر العثور
عليه.

إذا لم يكن مسموحًا للمفتاح باستخدام أي نموذج رؤية، يتنحى مسار الوصف ويمر
الطلب من دون تغيير، وهو سلوك السماح عند الفشل نفسه المتبع عند تعطيل حاجز
الحماية (البيانات الوصفية
`{ skipped: true, reason: "no_permitted_vision_model" }`).
وتتصرف الطلبات التي لا تحتوي على مفتاح، والمفاتيح التي لا تتضمن هذه القيود،
تمامًا كما كانت من قبل.

#### موجّه الوصف المدرك للمهمة (`modalityBridgeVisionTaskAware`)

القيمة الافتراضية هي **true**. تُلحق `composeVisionPrompt()` (`visionBridgeHelpers.ts`)
نص **آخر رسالة للمستخدم** (مقتطعًا إلى 500 حرف) بموجّه الوصف الأساسي،
مما يوجّه الوصف نحو ما طلبه المستخدم فعليًا
(نمط codex-vision-proxy)، ويطلب من نموذج الرؤية نسخ النص المرئي.
عند تعطيل العلامة — أو في حال عدم وجود نص للمستخدم — يُستخدم الموجّه الأساسي دون تغيير.

يطلب طلب حلقة الوصف الذاتية المتوافق مع OpenAI (`callVisionModelSingle()`
في `visionBridgeHelpers.ts`) دائمًا `image_url.detail: "high"` —
دون أي شرط، لكل مستدعٍ/موفّر، ومن دون ربط ذلك بأي إشارة من العميل.
يؤدي أخذ العينات منخفضة التفاصيل إلى تدهور دقة OCR في مهمة نسخ النص تحديدًا
التي يطلبها هذا الموجّه، ولذلك يطلب استدعاء الوصف نفسه دائمًا تفاصيل عالية،
بغض النظر عن مستوى التفاصيل المستخدم في الطلب الوارد الأصلي. يؤثر هذا
فقط في متن طلب الوصف الداخلي؛ ولا يغيّر طريقة تمرير OmniRoute لقيمة
`image_url.detail` الخاصة بالمستدعي في الطلب الأساسي — إذ تُطبّق تلك القيمة
الافتراضية بصورة منفصلة، ولعملاء OpenCode المكتشفين فقط، في
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`). لا يحتوي
فرع تنسيق Anthropic السلكي في حلقة الوصف الذاتية على حقل `detail`
ولا يتأثر بأي من القيمتين الافتراضيتين.

#### الحد الأقصى لمخرجات الوصف (`modalityBridgeVisionMaxChars`)

| المفتاح                        | القيمة الافتراضية | النطاق           |
| ------------------------------ | ----------------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`               | `0` أو 100–50000 |

تعني `0` (القيمة الافتراضية) **عدم وجود حد أقصى** — إذ يُمرّر الوصف الذي
تعيده `callVisionModel()` دون تعديل، مع الحفاظ على السلوك الحالي.
تؤدي أي قيمة ضمن النطاق 100–50000 إلى اقتطاع الوصف مع إضافة اللاحقة
`…` قبل إدراجه مجددًا بصيغة `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` في `src/lib/guardrails/visionBridge.ts`).
ارفع هذه القيمة لمهام OCR كثيفة التفاصيل التي يحتاج فيها النموذج اللاحق
إلى النسخ الكامل؛ وخفّضها لضبط استهلاك الرموز مع نماذج الرؤية كثيرة الإسهاب.
يوجد حقل لوحة المعلومات في لوحة Advanced ضمن علامة التبويب Vision
(`modality-bridge-max-chars` في `ModalityBridgeVisionTab.tsx`)، ويضبط أي
قيمة بين 1 و99 صعودًا إلى الحد الأدنى 100، مع ترك القيمة الصريحة `0`
دون مساس — فالقيمة `0` هي قيمة Zod صالحة بحد ذاتها
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`)، وليست مجرد
قيمة افتراضية بمعنى "غير معيّنة".

#### ذاكرة الوصف المؤقتة (`modalityBridge/bridgeCache.ts`)

ذاكرة LRU + TTL مؤقتة داخل الذاكرة لمخرجات الوصف، مشتركة على مستوى العملية بأكملها.
المفتاح = `sha256(imageRef + composedPrompt + configuredBridgeModel)` مع
تأطير يعتمد على بادئة الطول (من دون تصادمات عند حدود الحقول). مكوّن النموذج هو
نموذج الجسر **المُعَدّ**، وليس النموذج الذي قدّم الإجابة فعليًا —
فقد تنفّذ `callVisionModel` رجوعًا احتياطيًا داخليًا، وسيؤدي إنشاء مفتاح لكل
محاولة إلى تجزئة ذاكرة التخزين المؤقت. لا تُخزّن عمليات الوصف الفاشلة مطلقًا. الإعدادات:

| المفتاح                         | القيمة الافتراضية | النطاق  |
| ------------------------------- | ----------------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`            | —       |
| `modalityBridgeCacheTtlMinutes` | `60`              | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`             | 10–5000 |

#### تسوية الصور البعيدة (وصف الحلقة الذاتية/جلب base64)

عندما يجلب الجسر صورة **بعيدة** بنفسه — سواء لاستدعاء وصف Anthropic الذاتي
أو لتحويل claude-wire-format إلى base64
(`ensureBase64ImagesForClaudeWire`)، وكلاهما عبر
`fetchRemoteImageAsDataUri()` في `visionBridgeHelpers.ts` — يُمرَّر معرّف URI
للبيانات الناتج عبر `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) قبل تضمينه في طلب نموذج الرؤية.
تُخفّض أبعاد الصور كبيرة الحجم إلى **2048px للضلع الأطول** (بما يتوافق
مع حد تغيير الحجم الذي تطبّقه OpenAI/Anthropic بالفعل من جهة الخادم)، مما
يقلل حجم بايتات الرفع وزمن الاستجابة من دون تغيير ما يراه نموذج الرؤية.
تستخدم عملية تغيير الحجم `sharp`، ويُحمّل عبر استيراد ديناميكي: على منصة
يفشل فيها تحميل ملفه الثنائي الأصلي، فإن `normalizeDataUri()` **لا تطرح استثناءً مطلقًا**
— بل تعود إلى تمرير البايتات الأصلية كما هي، بحيث يظل مسار الوصف/التحويل
إلى base64 عاملًا دائمًا. كما تُمرّر البايتات التي لا تمثل صورة (أي جلب لم يُرجع
صورة قابلة لفك الترميز) دون تغيير. تقتصر هذه التسوية على الصور التي يجلبها
الجسر لاستدعائه الذاتي — ولا تُطبّق مطلقًا على حمولة التمرير الخام الخاصة
بالمستدعي، بما يتوافق مع مبدأ عدم التعديل إلا بالاشتراك الصريح (القاعدة الصارمة رقم 20).

#### مخطط الإعدادات + الترحيل

تخضع مفاتيح `modalityBridge*` الجديدة للتحقق عبر Zod في `updateSettingsSchema`
(`src/shared/validation/settingsSchemas.ts`): وهي `modalityBridgeVisionEnabled`،
`modalityBridgeVisionMode`، و`modalityBridgeVisionModel`،
و`modalityBridgeVisionTaskAware`، و`modalityBridgeVisionPrompt`،
و`modalityBridgeVisionTimeout`، و`modalityBridgeVisionMaxImages`،
و`modalityBridgeVisionMaxChars`، وثلاثية `modalityBridgeCache*`، ومجموعة
`modalityBridgeAudio*` التي يستخدمها Audio Bridge. ينسخ الترحيل
`141_modality_bridge_settings.sql` قيم `visionBridge*` القديمة الموجودة
إلى المفاتيح الجديدة المطابقة (بصورة متكررة آمنة، ومن دون الكتابة فوق أي
قيمة `modalityBridge*` عيّنها المشغّل)؛ وتظل المفاتيح القديمة مقبولة كخيار
قراءة احتياطي خلال دورة إصدار واحدة.

#### ترويسة الشفافية + الإحصاءات

تحمل الاستجابات المحوّلة عبر الوصف الترويسة
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(تُنشئها `buildModalityBridgeHeader()` في `modalityBridge/bridgeStats.ts`،
وتضيفها `withModalityBridgeHeader()` في `src/sse/handlers/chatHelpers.ts`).
لا تحصل الطلبات المعاد توجيهها على **أي** ترويسة — إذ لم تتغير الحمولة،
ويظهر تبديل النموذج بالفعل في حقل `model` ضمن متن الاستجابة.

يعيد `GET /api/modality-bridge/stats` (بمصادقة الإدارة، وبالمستوى نفسه الخاص بـ
`GET /api/settings`) العدّادات الموجودة في الذاكرة لكل نمط
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` لكل من `vision` و`audio` و
`video`. يستخدم `averageLatencyMs` القيمة `latencySamples` مقامًا له، وليس جميع
المحاولات؛ فالعملية التي لا تحتوي على قياس للتوقيت لا تنشئ عينة مصطنعة مدتها صفر
مللي ثانية. يظل `bridged` اسمًا مستعارًا متوافقًا مع الإصدارات السابقة للتحويلات
الناجحة؛ ولا تؤدي المحاولات الفاشلة إلى زيادته.
تُعاد تصفية العدّادات عند إعادة تشغيل العملية بحكم التصميم
(قياس عن بُعد، وليس محاسبة).

#### إعداد لوحة المعلومات

صفحة لوحة المعلومات المخصصة هي
`/dashboard/settings/modality-bridge`. وتحافظ علامات التبويب `Vision` و`Audio`
و`Video`، التي يمكن الوصول إليها عبر عنوان URL، على معاملات الاستعلام عند تبديل
قيمة `tab`.
تعرض علامة التبويب Vision التمكين، والوضع، واختيار النموذج (بما في ذلك الإعداد
الافتراضي التلقائي)، وصياغة المطالبات المدركة للمهمة، وحدود المهلة/الصورة/طول
الوصف/ذاكرة التخزين المؤقت المتقدمة، وعدّادات وقت التشغيل، وطلبًا نموذجيًا
محميًا. كما أن علامة التبويب Audio فعّالة أيضًا: فهي تعرض التمكين، ومنتقي نماذج
خاصًا بـ STT يتضمن Auto، وحدود المهلة/المدة القصوى للمقطع، وعدّادات الصوت،
واختبارًا نموذجيًا لـ `input_audio`. وتعمل علامة التبويب Video بالكامل: إذ تعرض
حالة وقت تشغيل FFmpeg/ffprobe — وهي إحدى أربع حالات صريحة لواجهة المستخدم
(`unknown` أثناء تنفيذ الفحص أو تعذر إكماله، و`restricted` عند استخدام مضيف
لوحة معلومات غير loopback حيث يتم تخطي الفحص من جهة العميل، و`unavailable` بعد
إجراء الفحص والتأكد من عدم توفره، أو `available` مع إصداري FFmpeg/ffprobe) —
وتحفظ إعدادات التمكين/النموذج/الإطارات/الفيديو/المهلة، وتصفّي منتقي النماذج ليعرض
النماذج القادرة على الرؤية، وتعرض عدّادات الفيديو.

أصبحت بطاقة Vision Bridge السابقة ضمن إعدادات AI رابط توافق إلى الصفحة الجديدة؛
ولم تعد تمتلك نسخة ثانية من النموذج. كما يربط Media Providers مساري عمل
Image-to-Text وSpeech-to-Text بعلامتي تبويب Modality Bridge المقابلتين دون إزالة
بيئة تجربة Speech-to-Text الحالية.

**تجاوز قبول الحلقة الذاتية:** عندما يُوجَّه استدعاء الوصف عبر الحلقة الذاتية
`/v1` الخاصة بـ OmniRoute (نموذج موفّر غير قياسي)، يرسل الطلب الفرعي
`x-omniroute-admission-bypass: internal` وتتم مصادقته باستخدام بيانات اعتماد
الحلقة الذاتية المحلولة — القيمة الحارسة المحلية `sk_omniroute` في الوضع المحلي،
أو مفتاح البيئة `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` الذي يضبطه المشغّل
(#1350)، بحيث تظل عمليات النشر التي تستخدم `REQUIRE_API_KEY=true` قادرة على
تنفيذ استدعاء الوصف. لا يُقبَل التجاوز إلا مع بيانات الاعتماد المطابقة تمامًا،
لذلك لا يمكن للعملاء الخارجيين استخدام الرأس لتخطي القبول.

توجد الإعدادات الافتراضية القديمة في
`src/shared/constants/visionBridgeDefaults.ts`؛ بينما توجد الإعدادات الافتراضية
الجديدة للوضع/الإدراك بالمهمة/ذاكرة التخزين المؤقت ومحلّل الإعدادات في
`src/shared/constants/modalityBridgeDefaults.ts`. يوفّر حاجز الحماية خيار المُنشئ
`deps` كي تتمكن الاختبارات من حقن تطبيقات زائفة لـ `getSettings` و
`callVisionModel`.

### جسر الصوت (`audioBridge.ts`) — Modality Bridge PR-3

يعترض طلبات الدردشة التي تحتوي على صوت قبل وصولها إلى هدف غير معروف بقبوله
لإدخال الصوت. وهو لا يعيد توجيه طلب الدردشة مطلقًا: إذ تُنسخ الأجزاء الصوتية
نصيًا عبر نقطة النهاية الحالية متعددة الأجزاء والمتوافقة مع OpenAI، ثم يتابع
نموذج الدردشة المختار باستخدام النصوص المنسوخة.

التدفق:

1. حلّ `supportsAudio` من خلال `getResolvedModelCapabilities()`. تكون الأولوية
   للبيانات الوصفية الصريحة لسجل الموفّرين، ثم للبيانات الوصفية الثابتة للنموذج،
   ثم لـ `modalities_input` المتزامنة. تكون قائمة الإدخال المعلنة التي لا تحتوي
   على `audio` مساوية لـ `false`؛ وإذا لم يوجد أي دليل على القدرة، تظل القيمة
   `null`. تقوم كلتا القيمتين `false` و`null` بتنشيط الجسر التحفظي، بينما تتجاوزه
   القيمة `true`.
2. حلّ إعدادات `modalityBridgeAudio*` واستخراج أجزاء الصوت القابلة للوصل على
   المستوى الأعلى من كل رسالة عبر الكاشف المشترك `detectMediaParts()`.
   أشكال النقل المدعومة هي `input_audio` و`audio_url` في OpenAI،
   و`source.media_type: "audio/*"`. يُكتشف الصوت المتداخل لأغراض التوجيه، لكنه
   لا يُزال عبر مسار الوصل. يُحدد العمل بحد أقصى قدره
   `modalityBridgeAudioMaxClips`؛ وتظل الأجزاء اللاحقة دون تغيير.
3. الالتزام بقيمة `provider/model` المضبوطة، أو السماح لـ
   `selectAudioBridgeModel()` باجتياز `AUDIO_TRANSCRIPTION_PROVIDERS` وفق ترتيب
   الفهرس الثابت واختيار أول نموذج يمتلك بيانات اعتماد موفّر نشطة وقابلة
   للاستخدام.
4. يحوّل `callAudioTranscription()` الصوت المشفر بصيغة base64 أو data-URI إلى
   `file` متعدد الأجزاء، أو ينزّل `audio_url` بعيدًا عبر حارس الاتصالات الصادرة
   العامة فقط، مع تثبيت DNS وحد أقصى يبلغ 25 MB. ثم يرسل الملف والنموذج المحدد
   باستخدام POST إلى الحلقة الذاتية المحلية `/v1/audio/transcriptions`، مع
   المصادقة بواسطة `resolveSelfLoopBearer()`. ينفّذ مسار النسخ النصي الحالي
   عملية البحث المعتادة عن بيانات الاعتماد، ومعالجة التهدئة/حدود المعدل، وإرسال
   الطلب إلى الموفّر.
5. تستبدل الاستدعاءات الناجحة أجزاءها بالنص
   `[Audio N]: <transcript>`. تُنفَّذ الاستدعاءات باستخدام
   `Promise.allSettled`: ويحافظ فشل منفرد على جزء الصوت الأصلي المقابل (عقد
   #4012). إذا فشلت جميع الاستدعاءات وثبت أن الهدف يحقق
   `supportsAudio === false`، تصبح الأجزاء
   `[Audio N]: (unavailable — no STT provider connected)` (عقد #8430). أما
   بالنسبة إلى هدف غير معروف (`null`)، فتظل النتيجة دون تغيير إذا فشلت جميع
   الاستدعاءات. ويتلقى الهدف الذي ثبت أنه يدعم النص فقط ولا يملك بيانات اعتماد
   STT قابلة للاستخدام العنصر النائب الصريح نفسه دون إصدار استدعاء شبكي.

تستخدم النصوص المنسوخة بنجاح ذاكرة التخزين المؤقت LRU/TTL الخاصة بـ Modality
Bridge على مستوى العملية بأكملها. يجمع المفتاح بين مرجع الصوت، وتسمية العملية
الثابتة `audio-transcription`، ونموذج STT المحدد؛ ولا تُخزَّن حالات الفشل مؤقتًا
أبدًا. تحدّث محاولات الصوت العدّادات المشتركة `bridged` و`cacheHits` و`failures`
و`lastUsedAt`.
تحمل الاستجابات المحوّلة
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`؛ ولا تتلقى
الطلبات التي لم تتغير مقطع Audio Bridge.

إعدادات وقت التشغيل مدعومة بقاعدة البيانات ويتم التحقق منها باستخدام Zod:

| المفتاح                       | القيمة الافتراضية | النطاق              |
| ----------------------------- | ----------------- | ------------------- |
| `modalityBridgeAudioEnabled`  | `true`            | —                   |
| `modalityBridgeAudioModel`    | `""`              | تلقائي أو معرّف STT |
| `modalityBridgeAudioTimeout`  | `60000`           | 1000–300000         |
| `modalityBridgeAudioMaxClips` | `3`               | 1–10                |

تظل ذاكرة التخزين المؤقت المشتركة خاضعة لتحكم `modalityBridgeCacheEnabled`،
و`modalityBridgeCacheTtlMinutes`، و`modalityBridgeCacheMaxEntries`.

### جسر الفيديو (`videoBridge.ts`، `videoBridgePipeline.ts`)

يعترض أجزاء الفيديو ذات المستوى الأعلى في `messages` الخاصة بـ Chat Completions وفي
`input` الخاصة بواجهة Responses API، وذلك قبل استدعاء وجهة لا يُعرف أنها تدعم الفيديو
دعمًا أصليًا. الأشكال المدعومة هي `input_video`، و`video_url`، و`video_source`، وعناوين
HTTPS URL، ومعرّفات URI للبيانات بالصيغة `data:video/*;base64,...`. لا تُعامل أسماء
الملفات المجردة الواردة في النص على أنها فيديو.

يتولى `VideoBridgeGuardrail.preCall` (`videoBridge.ts`) اجتياز الطلب، والتحقق من
الإمكانات/السياسة، والتجميع لكل طلب، وحمولة الاستجابة. أما العمل الخاص بكل فيديو —
جلبه، وذاكرة التخزين المؤقت للنتيجة الكاملة، ووصف تسلسل الإطارات (الذي يدمج أي نص
مفرغ للصوت يصرّح به المستدعي)، ومقاييس/إلغاء/تنظيف كل محاولة — فهو مخفي خلف
`processVideoPart` في `videoBridgePipeline.ts`، والذي يُستدعى مرة واحدة لكل جزء فيديو
داخل حلقة `preCall`. تُعرّف تلك الوحدة أيضًا حدود المنافذ الصريحة
`VideoMediaBrokerPort` (لجلب البايتات واستخراج الإطارات المُعيّنة)، و`VideoAudioTranscriptionPort`
(لدمج نص صوتي مفرغ يصرّح به المستدعي مع التعليقات التوضيحية للإطارات المُعيّنة)،
و`VideoDrilldownPort` (حد استمرارية التخزين للتعمق في الإطارات؛ ولم يُوصّل بعد
بـ `processVideoPart` — إذ إن المسار المنفصل `/api/modality-bridge/video/drilldown`
هو وحده الذي يكتب إدخالات التعمق حاليًا).

لا يستورد مسار الطلب العام `/v1` أي عملية فرعية ولا يستدعيها مطلقًا. تُنزّل
مقاطع الفيديو البعيدة ضمن حد يبلغ 50 MiB؛ أما مقاطع الفيديو المضمّنة بترميز base64
فلها حد متحفظ لكل فيديو قدره 36 MiB بعد فك الترميز، بحيث يمكن أن يظل غلاف
النموذج/الرسائل/التأطير ضمن حد قبول طلبات JSON العامة البالغ 50 MiB. يُتحقق من
الطول المضمّن وتقديرات الحجم بعد فك الترميز قبل تخصيص الذاكرة. يُشترط HTTPS في
عنوان URL البعيد الأولي وفي كل عملية إعادة توجيه، باستخدام آلية الحماية الحالية
للاتصالات الصادرة العامة فقط مع تثبيت DNS. تعبر البايتات بعد ذلك حد وسيط التخزين
الداخلي الدقيق `POST /api/modality-bridge/video/extract`. هذا المسار موسوم بكل من
`LOCAL_ONLY` و`SPAWN_CAPABLE`، ولا يقبل إلا طلبًا موثّقًا لكل عملية وواردًا من
واجهة استرجاع موثوقة، ولا يقبل مطلقًا عنوان URL أو مسار نظام ملفات أو ملفًا تنفيذيًا
أو قائمة وسائط. يفرض كل من مسار حجم جسم API وقارئ الجسم التزايدي في المعالج،
بشكل مستقل، حدًا أقصى قدره 50 MiB لمدخلات الوسيط. تنفّذ قائمته محدودة السعة عملية
استخراج واحدة في كل مرة، وتسمح بأربع مهام معلقة، وتضع حدًا أقصى للمدخلات المعلقة
قدره 100 MiB.

داخل الوسيط، يقرأ `ffprobe` ملفًا محليًا خاصًا؛ وتستبعد قائمة السماح الثابتة
للتنسيقات تنسيقات قوائم التشغيل والبيانات الوصفية. بالنسبة إلى حاويات عائلة MOV
المسموح بها، تظل مراجع بيانات MOV الخارجية معطلة افتراضيًا، ولا يفعّلها الأمر
الثابت. يستخدم كل من `ffprobe` و`ffmpeg` قائمة بروتوكولات مسموح بها تقتصر على
`file`، وخيط تنفيذ واحدًا، ومصفوفات وسائط ثابتة، ومن دون shell، مع حلّ الملفات
التنفيذية من `PATH`. لا تُعد تدفقات صور الأغلفة المرفقة مرشحة قابلة للتشغيل.
يجب أن تستوفي جميع التدفقات القابلة للتشغيل الحدود، ويُفضّل التدفق الافتراضي
الصريح قبل الرجوع الحتمي إلى التدفق ذي الفهرس الأدنى. تقتصر مقاطع الفيديو على
600 ثانية، و8,192 بكسل لكل بُعد، و33,554,432 بكسل مصدري. يأخذ FFmpeg عينات من
1–16 إطار JPEG عند نقاط المنتصف، ويصغّر الحافة الطويلة إلى 1,024 بكسل بحد أقصى
من دون تكبير المدخلات الأصغر، ولا يتلقى عنوان URL مطلقًا. تكون سياسة أخذ العينات
`uniform` افتراضيًا. تنفّذ السياستان الاختياريتان `scene_aware` و`segment_aware`
التجريبية تمريرة FFmpeg ثابتة إضافية واحدة على التدفق المحلي الذي تم التحقق منه
بالفعل، وتحددان طوابع زمنية محدودة للمشاهد عبر `showinfo`، ثم تعودان بصورة حتمية
إلى نقاط المنتصف المنتظمة نفسها عند فشل الكاشف، أو انتهاء المهلة، أو وجود مخرجات
مشوهة، أو وجود مجموعة مرشحين فارغة. يخصص وضع `segment_aware` عينات نقاط المنتصف
بالتناسب مع فواصل المشاهد التي تم التحقق منها؛ وترد أدناه تفاصيل أدلة وضع
`segment_aware` وسلوك الرجوع. يُطبّق الحد الصارم البالغ 16 إطارًا بعد الاختيار
في كل سياسة. عندما تكون ميزانية طلب `scene_aware` إطارًا واحدًا فقط، فإنه يستخدم
نقطة المنتصف المنتظمة للفيديو الكامل النشط أو لنافذة التركيز، ويبلغ عن
`policyEffective: uniform`؛ إذ لا يمكن لإطار مشهد واحد محدد الحفاظ على طرفي
النطاق الزمني. يمكن للمستدعي اختياريًا توفير نافذة تركيز محدودة (`start`/`end`
بالثواني)؛ فتُقيّد الحدود بمدة الوسائط، وتُرفض النوافذ المعكوسة أو غير المحدودة،
وتُنفذ جميع سياسات أخذ العينات داخل الفاصل المُطبّع فقط. تُدرج النافذة الناتجة
في بيانات أخذ العينات الوصفية وفي بادئة الوصف غير الموثوقة، حتى تتمكن النماذج
اللاحقة من تمييز مقتطف مركّز عن الخط الزمني الكامل.

تركيز التعليقات التوضيحية الدلالية إعداد منفصل وصريح. يحافظ وضع التحليل
الافتراضي `full` على مطالبة الإطار الحالية ولا يعيد توجيه نص الطلب إلى نموذج
التعليقات التوضيحية مطلقًا. في الوضع `focused`، لا يقرأ الجسر إلا أحدث
`text`/`input_text` غير فارغ أنشأه المستخدم من حاوية Chat أو Responses نفسها،
ويطبّعه إلى NFC، ويضغط محارف التحكم والمسافات البيضاء، ويقصره على 500 نقطة ترميز
Unicode. تؤدي النتيجة الفارغة إلى الرجوع إلى مطالبة `full` نفسها تمامًا. يُسلسل
التلميح القابل للاستخدام بتنسيق JSON داخل كتلة مخصصة لسياق مستخدم غير موثوق،
ولا يجوز له سوى إعطاء الأولوية للتفاصيل القابلة للملاحظة؛ ولا يمكنه تجاوز
التحذير المنفصل من اتباع التعليمات المرئية أو المسموعة في الوسائط. لا يستنتج
التركيز النصي `start`/`end` مطلقًا ولا يغيّر آلية أخذ العينات الزمنية.

#### FU-07 دليل المقاطع البنيوي

يستخدم `segment_aware` تمريرة تحليل مسبق واحدة محدودة على دفق الفيديو المحلي الذي تم التحقق منه بالفعل. تبدأ سلسلة المرشحات الثابتة بتغيير المقياس إلى عرض لا يتجاوز 320 بكسل، ثم تكتشف تغيّرات المشاهد والفترات المتجمدة، وبعد ذلك تأخذ عينة بمعدل إطار واحد في الثانية لقياس الضبابية، ومتوسط النصوع، والمعلومات المكانية/الزمنية. تقتصر التمريرة على 600 عينة بنيوية، وخيط FFmpeg/مرشح واحد، وقوائم السماح نفسها للبروتوكول `file` فقط وللحاويات، وحدّ قدره 1 MiB لمخرجات العملية، ومدة لا تتجاوز 30 ثانية ضمن الإلغاء/المهلة النهائية المشتركة للوسيط. وهي لا تقبل مطلقًا أمرًا أو مرشحًا أو مسارًا أو عنوان URL من الطلب.

القيم البنيوية هي أدلة أخذ عينات حتمية، وليست فهمًا دلاليًا للفيديو. وهي لا تستنتج الموضوعات أو الأفعال أو التسميات التوضيحية أو الكلام أو نية المستخدم. تشكّل حدود المشاهد والتجمد مقاطع؛ ولا تؤثر تغطية التجمد، والضبابية، والتعريض، والتفاصيل المكانية، والتغير الزمني إلا في كيفية تخصيص ميزانية الإطارات الحالية البالغة 1–16 إطارًا. يُحدَّد المقطع المتجمد بالكامل بإطار واحد كحد أقصى، بينما تتنافس المقاطع غير المتجمدة على الميزانية المتبقية. عندما يفوق عدد الحدود عدد الإطارات، يُحتفظ بتغطية موحّدة للخط الزمني كي لا تتمكن القطوع السريعة المبكرة من إخفاء مقطع ختامي طويل. تُدمج حدود المشاهد الواقعة ضمن دقة التحليل البالغة ثانية واحدة من حدود التجمد.

يؤدي غياب المرشحات، أو وجود أدلة مشوّهة/فارغة، أو حدوث خطأ في الكاشف، أو انتهاء مهلة التحليل المسبق المحدود إلى التراجع المتسامح إلى سياسة نقاط المنتصف الموحّدة نفسها تمامًا. أما إلغاء المتصل أو بلوغ المهلة النهائية للوسيط فلا يؤديان إلى تراجع متسامح: بل ينهيان العملية الفرعية قيد التنفيذ، ويمنعان استخراج الإطارات لاحقًا، وتُزال الشجرة المؤقتة الخاصة في `finally`.

ينشئ `scripts/perf/video-bridge-fu07-eval.ts` تجهيزات FFmpeg حقيقية وحتمية لقياس وفورات استدعاءات التسميات التوضيحية بعد إزالة التكرار، وتخصيص الميزانية للحركة الكثيفة، وأدلة الضبابية/التعريض/SI-TI، والقطوع السريعة ذات الذيل الطويل، والإيجابيات الكاذبة الناتجة عن التلاشي التدريجي. ويسجّل وقت التحليل المسبق الفعلي، وكذلك وقت CPU للعملية الفرعية وذروة RSS عندما يكون `/usr/bin/time` متاحًا. لا تمثل فحوصات الجودة فيه سوى مراجع بنيوية. تظل جودة نموذج التسميات التوضيحية الحقيقي عند `HOLD` لأن أداة الاختبار هذه لا تملك نقطة نهاية مصرّحًا بها أو مُقيّمًا مجمّدًا. كما تظل الوفورات المالية عند `HOLD` ما لم يوفّر `--caption-cost-per-call-usd` تقديرًا صريحًا وإيجابيًا للتكلفة لكل استدعاء؛ ولا يختلق البرنامج النصي أيًا من النتيجتين.

يقتصر حجم كل إطار على 4 MiB، وإجمالي الإطارات الخام مجتمعة على 23 MiB، واستجابة الوسيط المتسلسلة على 32 MiB. ويُزال دليل مؤقت خاص في `finally`. لا يضمّن OmniRoute برنامج FFmpeg ولا يقبل مسارًا مخصصًا للملف التنفيذي. قبل إنشاء التسميات التوضيحية، يطبّق الجسر تمريرة محافظة لإزالة التكرار البصري: يُختزل كل ملف JPEG إلى مخزن مؤقت رمادي بتنسيق 16×16، ولا يُقارن إلا بآخر إطار تم الاحتفاظ به. عندما تكون ميزانية التسميات التوضيحية المطلوبة أكبر من إطار واحد، يوفّر الاستخراج مجموعة مرشحين محدودة لا تتجاوز ضعف تلك الميزانية ولا تزيد مطلقًا على 16 إطارًا. ولا يُطبّق الحد الأقصى المطلوب إلا بعد إزالة التكرار، مع الحفاظ على أول وآخر مرشحين محددين أثناء التقليص النهائي عندما تكون الميزانية إطارين على الأقل. تستخدم السياسة ذات الإصدار
`grayscale-16x16-mean-cells-v2` القيمة الأكبر بين متوسط فرق النصوع ونسبة خلايا الصورة المصغرة التي يبلغ فرقها المطبّع 0.05 على الأقل. عتبة التكرار هي الثابت 0.04، وقد اختيرت لقابلية التنبؤ بدلًا من إتاحتها كإعداد وقت تشغيل. تحافظ إشارة التباين العالي الثانوية هذه على الحركة الصغيرة وتغيّرات النص المرئي التي قد تخفيها مقارنة تعتمد على المتوسط وحده. تتراجع أخطاء المقارن أو وحدة فك الترميز تراجعًا متسامحًا وتحافظ على التغطية. تفصل بيانات المخرجات الوصفية بين المرشحين المستخرجين، والإطارات المستخدمة بنجاح، والتكرارات البصرية المستبعدة.

يمكن لجزء فيديو معلَّم صراحةً أن يطلب لوحة مصغرات ذات طوابع زمنية. ينشئ الجسر شبكة JPEG من 16 إطارًا كحد أقصى وبعدد أعمدة لا يتجاوز 4. وتطبع كل خلية بحجم 512 بكسل الطابع الزمني لمصدرها داخل شريط سفلي عالي التباين، بينما تبقى الطوابع الزمنية نفسها في البيانات الوصفية النصية للربط والتدقيق في المراحل اللاحقة. يظل حجم ملف JPEG الكامل محدودًا بـ 32 MiB. إذا تعذر على `sharp` فك ترميز الشبكة أو تركيبها، يتراجع الجسر إلى إطارات JPEG الفردية؛ ويستمر تمرير إلغاء العميل عبر عملية إنشاء اللوحة.

تُفصل أدلة الترقية عمدًا عن الاختبار المصغّر الاصطناعي للتركيب. يعرّف `scripts/perf/video-bridge-contact-sheet-eval.ts` أداة اختبار A/B ذات مخطط محدد الإصدار لنماذج الرؤية الحقيقية المتوافقة مع OpenAI. وهي تقيس الرموز التي أبلغ عنها المزوّد، وزمن الاستجابة الفعلي من البداية إلى النهاية، بما في ذلك تركيب اللوحة، وعدد استدعاءات النموذج، والاحتفاظ بالحقائق المحددة في البيان. لا تُكتب استجابات النموذج الخام في التقرير؛ بل يُحتفظ فقط بملخصات SHA-256 ومعرّفات الحقائق المتطابقة. لا تجري أداة الاختبار أي استدعاء شبكي أو لنموذج مدفوع ما لم يُمرَّر `--execute-real` وتتم تهيئة `--model` و`OMNIROUTE_BASE_URL` و`OMNIROUTE_API_KEY`. ومن دون ذلك التشغيل الحقيقي الصريح، يظل حكمها القابل للقراءة آليًا عند `HOLD`؛ ولا تمثل قياسات الحمولة الاصطناعية/عدد الاستدعاءات وحدها دليلًا للترقية.

يمكن للمتصلين إرفاق مصفوفة `transcript.cues` اختيارية بجزء فيديو مدعوم عندما يكون لديهم بالفعل نص محاذى زمنيًا. يجب أن يتضمن كل مؤشر `text`، وفاصلًا زمنيًا محدودًا من `start`/`end` يقع ضمن المدة المستكشفة، وقيمة `source` مدرجة في قائمة السماح (`client` أو `embedded` أو `audio-bridge`)؛ وتكون قيمة `confidence` الافتراضية `1` ويجب أن تبقى بين `0` و`1`. تُدمج المؤشرات المتطابقة تمامًا. لا يبدأ OmniRoute مطلقًا عملية نسخ صوتي انطلاقًا من هذه البيانات الوصفية: تُنسخ المؤشرات التي تم التحقق منها إلى النتيجة الموصوفة مع المصدر والثقة والفاصل الزمني، وتُعرض كملاحظات غير موثوقة إلى جانب تسميات الإطارات التوضيحية. يُرفض النص غير الصالح أو الواقع خارج النطاق أو الخالي من معلومات المصدر بدلًا من مزجه مع دفق التسميات التوضيحية. تعمل قناتا النص المنسوخ في متن الطلب كلتاهما على تطبيع المصدر المقدَّم إلى `client`، بما في ذلك تسميات `embedded` أو `audio-bridge` المعلنة ذاتيًا. ولا يستطيع إسناد تلك التسميات الموثوقة عبر وسيطة `trustedSource` المتاحة في الشيفرة فقط سوى مهايئ يملكه الخادم؛ ولا يمكن لحقل JSON في الطلب الوصول إلى تلك الوسيطة. يظل نص النسخ محتوى غير موثوق مشتقًا من الوسائط، بصرف النظر عن مصدره، ويجب ألا يحدد التفويض مطلقًا.

قد يوفّر مستدعٍ متقدم مسار `audioTranscript` للفيديو نفسه؛
ويُعامل على أنه نص مقدَّم من العميل، لا كدليل على إجراء الخادم لعملية النسخ.
يشغّل موضع الدمج الملاحظات المرئية والصوتية ضمن
مهلة واحدة وإشارة إلغاء واحدة، ويرتبها على خط زمني مشترك، ويدمج
النسخ المتطابقة تمامًا، ويُبلغ عن نتيجة جزئية عندما ينجح جانب واحد فقط.
يؤدي `audioTranscript` غير الصالح إلى التراجع إلى تلك النتيجة الجزئية — إذ يُحتفظ
بالوصف المرئي ويسجّل الفرع الصوتي رمز فشل منقّحًا —
بدلًا من إفشال الفيديو بأكمله. يُحتفظ بتوافر كل فرع، وعلامة النتيجة الجزئية،
ورموز الفشل المنقّحة في النتيجة الموصوفة، وفي
بيانات حواجز الحماية الوصفية (`audioFusionRuns`/`audioFusionPartials`/
`audioFusionFailureCodes`)، وفي بيانات ذاكرة التخزين المؤقت للنتائج الوصفية، وفي عدادات الدمج
الخاصة بالجسر. لا يستدعي المسار الافتراضي لـ Video Bridge تحويل الكلام إلى نص،
ولا ينزّل نسخة وسائط ثانية؛ ومن دون ذلك المسار الصريح، يظل
مخصصًا للفيديو فقط.

**الاحتفاظ بالنص المنسوخ (#12150 P1).** ينطبق هذا تلقائيًا كلما قام
Video Bridge (الذي يتطلب الاشتراك بحد ذاته) بتصيير إشارة نص منسوخ — ولا توجد
علامة احتفاظ منفصلة. عندما يقوم طلب بتصيير أي إشارة نص منسوخ (سواء كانت
`transcript` معلنة من المستدعي أو `audioTranscript` مدمجة)، يضع حاجز الحماية عليها علامة
`videoBridgeObserved` وينشئ نسخة ظل منقّحة من وصف الفيديو —
وهي تصيير مطابق يُستبدل فيه النص الحر في متن كل إشارة بـ
`[redacted-video-transcript]`، ويُنشأ ذلك عبر استبدال حقل الإشارة المنظم
قبل تجميع السلسلة النصية (وليس مطلقًا عبر تحليل النص المسطح، بحيث لا يمكن لأي محتوى
في الإشارة — سواء كان عدائيًا أم عاديًا، بما في ذلك المتون التي تحتوي على `]` مثل
`[inaudible]`/`[music]` — أن يبقى). يستبدل متن الطلب المحفوظ في سجل الاستدعاء
كل جزء نصي مشتق من الفيديو بنسخة الظل المنقّحة تلك، مع المطابقة بحسب
تساوي المحتوى؛ وتُعاد قراءة مرساة `fullText` من حمولة حاجز الحماية المكتملة
قبل الاستدعاء، بحيث تستمر المطابقة في النجاح بعد أن تعيد حواجز حماية السلسلة اللاحقة
(أدوات إخفاء معلومات التعريف الشخصية وبيانات الاعتماد، بالأولويتين 10/95) كتابة نص الوصف في موضعه،
وبعد أن تعيد إضافة موجه النظام/التسليم/الذاكرة تشكيل مصفوفة الرسائل. يظل
المتن المرسل إلى النموذج في المنبع دون تغيير. كذلك لا يملأ الطلب المرصود
أي Memory دائمة (إذ يُتخطى الاستخراج المشتق من الطلب والاستجابة معًا)،
ولذلك لا يمكن لرد النموذج نفسه تكرار نص النسخ داخل Memory.

**حقول الفيديو الخام (#12430).** عندما يكون الجسر مفعّلًا ويكون دعم الفيديو الأصلي مجهولًا أو غير متوفر، فإن حقول `transcript`/`audioTranscript` المعرّفة تفعّل أيضًا `videoBridgeObserved`، حتى بعد فشل الوصف أو بلوغ حد `maxVideos`. تُحتسب القيم `null` والسلاسل النصية الفارغة؛ أما الحقول الغائبة والبيانات الوصفية غير المتعلقة بالفيديو فلا تُحتسب. تنقّح النسخ المحتفظ بها هذه الحقول أو تحذف الطلب، ويُتجاوز التخزين المؤقت/Memory.

في مسارات الرجوع تلك، تتحول إشارات المستدعي الصالحة إلى أجزاء `text`/`input_text`
مدعومة بدلًا من حقول المزوّد غير القياسية. يظل كلا المسارين المقدَّمين مع الطلب
ملاحظات `client` غير موثوقة، مع تحذير صريح بأن الفيديو
لم يُوصَف وأن الطوابع الزمنية لم تُتحقق بمقارنتها مع الوسائط. تنطبق الحدود الحالية البالغة
256 إشارة/64 KiB إجمالًا، إضافة إلى حدود كل إشارة، على المسارين مجتمعين؛
ويجب أن تقع الطوابع الزمنية ضمن سقف الوسيط البالغ 600 ثانية وأي نافذة تركيز
مقدَّمة. تُهمل المسارات غير الصالحة، ولا تُمرر كنص اعتباطي؛ ويمكن الاستمرار في استخدام
مسار شقيق صالح ما لم يُتجاوز حد الميزانية المشتركة بينهما. لا تضيف الحقول الفارغة/ذات القيمة `null`
أي نص. لا يضيف مسار الرجوع هذا أي جلب للوسائط أو نسخ لها.
تُزال حقول امتداد النص المنسوخ من حامل فيديو الرجوع ومن كائني
`video_url`/`source` الخاصين به. تظل قائمة السماح في واجهة OpenAI صارمة؛ وتظل حوامل
الفيديو ذات الدعم الأصلي المجهول متاحة، بينما تحتفظ الوجهات المعروفة بأنها نصية فقط بعلامات آمنة.
تحمي نسخ الظل المنقّحة والمنظمة نص النسخ الملحق، بينما يظل
طلب المستدعي الأصلي دون تغيير. تحتفظ الوجهات ذات الدعم الأصلي والجسور
المعطّلة بسلوك التجاوز الحالي.

تستخدم النسخ الإضافية المحتفظ بها إشارة الطلب المرصود نفسها. تستبدل
لقطة طلب العميل الخام السابقة لحاجز الحماية، والطلب المعلّق في الذاكرة، وسجل
الطلب المرفوض مبكرًا حقول النص المنسوخ في أجزاء الفيديو بصورة منظمة؛
وتُنقح الموجهات النصية التي تنشئها مراحل خط الأنابيب وتسليم السياق
عند وجهة حفظ متن الطلب. تجعل علامة `video_content_removed`
المحفوظة استمرار `previous_response_id` يفشل بصورة مغلقة بدلًا من إعادة بناء
نص أُهمل عمدًا. إذا فقد طلب مرصود
نسخة ظل التنقيح الخاصة بكل جزء قبل التسجيل، أو إذا فشلت مطابقة نسخة واحدة فقط من بين
عدة نسخ ظل للفيديو بعد تعديلات الطلب اللاحقة، يُحذف متن الطلب المحتفظ به
بالكامل بدلًا من الاحتفاظ بنص منسوخ منقّح جزئيًا.

بالنسبة إلى طلب مرصود، قد تقتبس استجابة النموذج أي جزء من
النص المنسوخ دون حدود إشارة منظمة. لذلك يُستبدل `responseBody`

(الذي قد يتضمن متون المنبع/العميل ومقاطع البث).
تتجاوز ذاكرات التخزين المؤقت الدلالية، والخاصة بالتكرار الآمن، وإعادة تشغيل الاستدلال
عمليات القراءة والكتابة لذلك الطلب. يظل طلب المزوّد والاستجابة
الظاهرة للعميل دون تغيير. تُصرّف بايتات إبقاء الاتصال المبكرة من المخزن المؤقت
عند حذف العنصر التفصيلي. لا يعرض تحذير EventStream غير المنسق في Kiro
إلا عدد بايتات الحمولة، ولا يعرض محتواها أو الخطأ الخام الصادر من محلل JSON مطلقًا.
لا يعني هذا الادعاء أن كل تشخيص غير ذي صلة صادر عن مزوّد/مكوّن إضافي قد خضع
للتدقيق؛ إذ يجري تتبع المراجعة الأوسع لوجهات الاحتفاظ في #11658.

تُعد دورة حياة `/api/modality-bridge/video/drilldown` الداخلية ركيزة تخزين مؤقت منفصلة، تعتمد على الاتصال الحلقي المحلي والمصادقة بالرمز المميز. وتتطلب كل عملية أيضًا معرّفًا أساسيًا مبهمًا للهوية. قبل تمكين أي مستدعٍ في بيئة الإنتاج، يجب عليه اشتقاق ذلك المعرّف من المستأجر المُصادَق عليه، ويجب ألّا يمرّر مطلقًا قيمة يختارها العميل. تربط مفاتيح التخزين المؤقت تلك الهوية بمعرّفات الجلسة ومرجع الفيديو الأساسية، ولا تخزّن سوى مفاتيحها المشتقة باستخدام SHA-256، كما تقصر عمليات القراءة والحذف على الهوية نفسها. يخزّن التخزين المؤقت بحد أقصى 16 إطار JPEG مشتقًا لكل إدخال، وتنتهي صلاحيتها بعد عشر دقائق، ويدعم عمليات قراءة محدودة باستخدام `start`/`end` أو الحذف الصريح للجلسة.

تقتصر كل هوية على 16 إدخالًا و64 MiB من بيانات JPEG الأساسية. وهذه الحدود مستقلة عن الحد الإجمالي البالغ 64 إدخالًا/256 MiB: فضغط حصة الهوية لا يُخلي سوى الإدخالات الأقل استخدامًا مؤخرًا الخاصة بتلك الهوية قبل النظر في الإخلاء العام وفق LRU. وتُزال الإدخالات منتهية الصلاحية من محاسبة الهوية والمحاسبة العامة عند حدوث نشاط في التخزين المؤقت، بينما لا يؤدي الإلغاء أو فشل التحقق إلى تثبيت استبدال جزئي.

يرفض التخزين المؤقت Base64 غير الأساسي، والحشو الزائد، والوسائط غير JPEG، وملفات JPEG المشوهة أو المبتورة، وملفات JPEG التي تنتج تحذيرًا أثناء فك ترميز `sharp` محدود للصورة كاملة. ويعيد ترميز كل صورة مقبولة بصيغة JPEG أساسية، ويشتق العرض والارتفاع من وحدات البايت المفكوكة بدلًا من الوثوق بحقول المستدعي، ويتخلص من أي وحدات بايت هجينة لاحقة بدلًا من الاحتفاظ بها. ولا تُحتسب ضمن كلتا الحصتين سوى الذاكرة المؤقتة المضغوطة الأساسية والمحدودة. يتضمن حد النقل عبر JSON الحمل الإضافي لـ Base64 ضمن سقف الإدخال المفكوك البالغ 32 MiB. ويسجّل كل اشتقاق مخزّن صيغة JPEG ودقتها المتحقق منهما، وسياسة أخذ العينات، وإصدار الاشتقاق، ووقت الإنشاء، وتجزئة المحتوى المحسوبة على الخادم، ومرجع الأصل المجزّأ، إلى جانب تجزئة محتوى الأصل المقدمة من المستدعي الموثوق. ويُتحقق من الإلغاء بين مراحل فك الترميز والتجزئة غير المتزامنة قبل التثبيت الذري في التخزين المؤقت.

لا تربط هذه الدفعة حتى الآن مُنتِجًا في بيئة الإنتاج بالمسار، ولا توفر اختيار متغيرات متعددة الدقة. ولذلك لا يضيف مسار طلب Video Bridge الشفاف أي عمل إضافي، بينما يظل اشتقاق الهوية المرتبط بالمستأجر ودورة حياة FU-08 الكاملة متعددة الدقة من أعمال المتابعة الصريحة بدلًا من توثيقهما كسلوك مكتمل.

تُنشأ تسميات توضيحية للإطارات بالتتابع باستخدام نموذج Video المُهيأ. ويرث تجاوز Video الفارغ إعداد Vision؛ وإذا كان كلاهما فارغًا، يحدد الموجّه التلقائي لـ Vision النموذج الفعّال القادر على معالجة الرؤية. تستبدل التسميات التوضيحية الناجحة الجزء الأصلي ببادئة ثابتة `[Video description:`، تشير أيضًا إلى أن النص ملاحظة غير موثوقة مشتقة من الوسائط، وتوجّه النماذج اللاحقة إلى عدم اتباع التعليمات الموجودة في الوسائط. تتضمن مفاتيح التخزين المؤقت لتسميات الإطارات وحدات بايت JPEG، والموجّه، والطابع الزمني، والنموذج الفعّال؛ ولا تُخزّن مؤقتًا سوى التسميات التوضيحية الناجحة. تحتفظ إدخالات التخزين المؤقت بنموذج المُنتِج الفعلي الناجح، بما في ذلك نموذج احتياطي؛ ويُبلغ الجسر بالقيمة `mixed` عندما تنتج نماذج مختلفة إطارات مختلفة. تعيد إصابة التخزين المؤقت استخدام هوية ذلك المُنتِج بدلًا من إعادة تصنيفها باعتبارها خطة التوجيه المطلوبة. يُفهرس التخزين المؤقت لنتيجة الفيديو الكامل بناءً على كل مُدخل يغيّر المخرجات — الموجّه، والنموذج الفعّال، وسياسة أخذ العينات، وعدد الإطارات، ووضع التحليل الدلالي، وبصمة SHA-256 لتلميح التركيز المُطبّع، ونافذة التركيز، و`transcript`، و`audioTranscript`، وعلامة ورقة الاتصال — ولذلك فإن تغيير أي من هذه الأبعاد يؤدي إلى إخفاق في إصابة التخزين المؤقت، وليس أبدًا إلى إعادة استخدام نتيجة قديمة. كما أن إصدار سياسة إزالة التكرار المرئي، والحد، والعدد المحدود للإطارات المرشحة، موضّحة صراحةً في مفتاح التخزين المؤقت للنتائج وبياناته الوصفية؛ وبالتالي لا يمكن لأي تغيير في السياسة إعادة استخدام وصف قديم للفيديو الكامل. تحتفظ البيانات الوصفية للإصدار v4 من التخزين المؤقت للنتائج بالوضع والبصمة، ولا تحتفظ مطلقًا بمهمة المستخدم الخام. تُبلغ البيانات الوصفية للحواجز الوقائية عن وضعي التحليل المطلوب والفعّال؛ فإذا طُلب الوضع `focused` من دون نص مستخدم صالح للاستخدام، فيُبلغ عن الوضع الفعّال باعتباره `full`.

يستخرج الحاجز الوقائي كل جزء فيديو مدعوم، لكنه لا يصف أكثر من `modalityBridgeVideoMaxVideos`. بالنسبة إلى هدف ثبت أن لديه `supportsVideo === false`، تتحول مقاطع الفيديو الفاشلة والمتجاوزة للحد إلى علامات نصية آمنة وصريحة، بحيث لا يبقى أي فيديو خام. وعندما تكون القدرة غير معروفة، تحتفظ تلك الأجزاء بحامل الفيديو الخاص بها؛ وتتبع أي نسخة نصية احتياطية التحويل النصي المحدود المذكور أعلاه. تتجاوز الأهداف التي لديها `supportsVideo === true` الجسر. تنتشر إشارة إلغاء طلب العميل عبر التنزيل، وقائمة انتظار الوسيط، والعمليات الفرعية، واستدعاءات إنشاء التسميات التوضيحية؛ وتؤدي عمليات الإلغاء إلى التوقف بين مقاطع الفيديو، ولا تسمح مطلقًا بالانفتاح عند الفشل وتمرير الوسائط الخام.

إعدادات وقت التشغيل مخزّنة في قاعدة البيانات ويُتحقق من صحتها باستخدام Zod:

| المفتاح                             | القيمة الافتراضية | النطاق / السلوك                                                                                         |
| ----------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`           | وقت تشغيل اختياري، ويتطلب تفعيلًا صريحًا                                                                |
| `modalityBridgeVideoAnalysisMode`   | `"full"`          | يحافظ `full` على التسميات التوضيحية العامة؛ ويستخدم `focused` سياقًا محدودًا وغير موثوق به لأحدث مستخدم |
| `modalityBridgeVideoModel`          | `""`              | يرث نموذج Vision Bridge                                                                                 |
| `modalityBridgeVideoFrameCount`     | `8`               | 1–16                                                                                                    |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"`       | `uniform` أو `scene_aware` أو `segment_aware` التناسبي؛ وعند فشل أداة الكشف، يتم الرجوع إلى `uniform`   |
| `modalityBridgeVideoMaxVideos`      | `1`               | 1–4                                                                                                     |
| `modalityBridgeVideoTimeout`        | `120000`          | 1000–120000 مللي ثانية                                                                                  |

تُقيّد قيم مهلة الفيديو القديمة المحفوظة التي تزيد عن 120 ثانية بالموعد النهائي
للوسيط؛ وتُرفض عمليات كتابة الإعدادات الجديدة التي تتجاوز هذا الحد.
يتطلب `GET /api/modality-bridge/video/runtime` موقعًا محليًا موثوقًا ومختومًا عبر الاسترجاع الحلقي
قبل المصادقة أو فحص وقت التشغيل، ثم يتطلب مصادقة
الإدارة. ولا يعيد سوى `available` وإصدارات FFmpeg/ffprobe المنقّحة وسببًا ثابتًا
عندما لا يكون وقت التشغيل متاحًا. نقطة نهاية الاستخراج الداخلية ليست
واجهة API عامة للرفع: يؤدي تشبع قائمة الانتظار إلى إرجاع `503` مع `Retry-After`، ويؤدي
انقطاع اتصال المستدعي إلى إرجاع `499`، ويؤدي الموعد النهائي الثابت للوسيط إلى إرجاع `504`. تضيف الاستجابات المحوّلة
`video->text;model=<visionModel>;parts=<videos>` إلى ترويسة
`x-omniroute-modality-bridge` المركزية دون إزالة مقاطع Vision أو Audio.

### أداة إخفاء معلومات التعريف الشخصية (`piiMasker.ts`)

تعمل في **كلتا** المرحلتين.

- **`preCall`** تنسخ الحمولة، وتتصفح `system` و`messages` و`input` و
  `prompt` (بما في ذلك عناصر السلاسل النصية العادية)، وتطبق `processPII()` (من
  `@/shared/utils/inputSanitizer`) على حقول `content`/`text` النصية. عندما تكون
  `PII_REDACTION_ENABLED=true`، تُحجب معلومات التعريف الشخصية المكتشفة في الحمولة
  الصادرة. وهذا مستقل عن `INPUT_SANITIZER_MODE` (الذي يتحكم فقط في
  سياسة حقن المطالبات). عندما يكون الحجب معطلًا، تسجل المكالمة أعداد حالات الاكتشاف
  دون إعادة كتابة المحتوى.
- **`postCall`** تنشئ نسخة عميقة من الاستجابة، وتشغّل `sanitizePIIResponse()` بالإضافة إلى
  أداة الإخفاء الخاصة ببنية Responses API (`maskResponsesOutput` — التي تغطي
  `output_text` و`output[].content[].text`). إذا حدث أي حجب،
  تحل الاستجابة المعدلة محل الأصلية.

لا يحظر حاجز الحماية الطلبات أبدًا؛ بل يضيف تعليقات توضيحية فقط (`meta.detections`،
`meta.redacted`) أو يعيد الكتابة.

### حقن المطالبات (`promptInjection.ts`)

يكتشف البنى العدائية في المحتوى المقدم من المستخدم ويفرض
السياسة المكوّنة. يُحدَّد السلوك بواسطة متغيرات البيئة وخيارات
المنشئ:

| الإعداد  | متغير البيئة                                                                                               | القيمة الافتراضية | التأثير                                                                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| التمكين  | `INPUT_SANITIZER_ENABLED`                                                                                  | `true`            | عندما تكون القيمة `false`، يتوقف حاجز الحماية مبكرًا.                                                                                                                                               |
| الوضع    | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                            | `warn`            | سياسة الحقن: `block` أو `warn` أو `log`. (تُقبل `redact` للتوافق مع الإصدارات السابقة، لكنها **لا** تزيل نص الحقن؛ وتتحكم `PII_REDACTION_ENABLED` في إعادة كتابة معلومات التعريف الشخصية في الطلب.) |
| حد الحظر | خيار `blockThreshold` / `INPUT_SANITIZER_BLOCK_THRESHOLD` (الاسم البديل `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`            | الحد الأدنى من الخطورة المطلوب للحظر. تُستخدم الخطورة المتوسطة للمراقبة فقط وفق الإعداد الافتراضي.                                                                                                  |

**أسبقية الوضع** (`getMode`): ‏`options.mode` الخاص بالمستدعي ←
تجاوز **علامة ميزة قاعدة البيانات** لـ `INJECTION_GUARD_MODE` (لوحة المعلومات ← الإعدادات ←
علامات الميزات) ← متغير البيئة `INJECTION_GUARD_MODE` ← متغير البيئة `INPUT_SANITIZER_MODE` ←
`warn`. لذلك، يتغلب تجاوز لوحة المعلومات على متغيرات البيئة، ومن ثم تتحكم واجهة
علامات الميزات في حاجز الحماية قيد التشغيل مباشرةً (من دون إعادة تشغيل). قراءة قاعدة البيانات آمنة عند الفشل:
إذا حدث خطأ، يعود حاجز الحماية إلى السلوك المستند إلى متغيرات البيئة، وعندما لا يكون هناك
تجاوز معين، يكون السلوك مطابقًا للمعالجة المعتمدة على متغيرات البيئة فقط.

مصادر الاكتشاف:

1. `sanitizeRequest()` من `@/shared/utils/inputSanitizer` (مجموعة أدوات الكشف المشتركة
   المستخدمة في مواضع أخرى من خط المعالجة).
2. `DEFAULT_GUARD_PATTERNS` المضمنة (حاليًا `system_override_inline` و
   `markdown_system_block`، وكلاهما بدرجة خطورة `high`).
3. أنماط `customPatterns` الاختيارية التي تُمرر عبر خيارات المنشئ (سلاسل نصية، أو تعبيرات نمطية،
   أو سجلات `{ name, pattern, severity }`).

عندما يكون `mode === "block"` **و** يستوفي اكتشاف واحد على الأقل حد الخطورة،
تُرجع `preCall` القيمة `{ block: true, message: "Request rejected:
suspicious content detected" }`. في وضعي `warn`/`log`، يسجّل حاجز الحماية الحدث
لكنه يسمح بالاستدعاء. كما تُصدَّر الدالة المساعدة المشتركة `evaluatePromptInjection()`
للمستدعين الذين يحتاجون إلى تقييم المطالبات دون المرور عبر السجل.

**حد الفحص (v3.8.20):** لا يفحص الكاشف سوى **أول 16 KB** من نص
المطالبة المدمج — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 بايت) في
`src/shared/utils/inputSanitizer.ts`. تنفّذ كل من `detectInjection()` و
`evaluatePromptInjection()` العملية `slice(0, MAX_INJECTION_SCAN_BYTES)` قبل تشغيل
حلقة الأنماط. تقع توجيهات الحقن بالقرب من بداية الإدخال، ولذلك يحد هذا من استهلاك
وحدة المعالجة المركزية/جامع البيانات المهملة بواسطة التعبيرات النمطية مع الحمولات التي يبلغ حجمها مئات
الكيلوبايت، دون إضعاف الاكتشاف (راجع #3932، #4041).

### أداة إخفاء بيانات الاعتماد (`credentialMasker.ts`)

تعمل في **كلتا** المرحلتين، وتأتي أخيرة في السلسلة الافتراضية (الأولوية `95`). تحجب
أنماط مفاتيح API / الرموز السرية المعروفة من الحمولة الصادرة (محتوى الرسالة،
ووسائط استدعاء الأدوات، ونتائج الأدوات) **وكذلك** من استجابة المزوّد، بحيث لا تتسرب
بيانات اعتماد ملصقة في مطالبة (أو يُعاد صداها في نتيجة أداة) إلى المزوّد الخارجي
أو مرة أخرى إلى العميل.

- **تعمل بالاشتراك الصريح فقط**، وفقًا للنهج نفسه المتبع في حجب معلومات تحديد الهوية الشخصية (بما يجاور القاعدة الصارمة رقم 20):
  تكون معطلة ما لم تكن `settings.credentialRedactionEnabled === true` **أو**
  `CREDENTIAL_REDACTION_ENABLED=true`. عند تعطيلها، لا ينفّذ حاجز الحماية أي إجراء —
  فهو لا يحظر ولا يعيد الكتابة مطلقًا.
- تجتاز `redactCredentials()` شجرة الحمولة/الاستجابة كاملةً (`walkValue()`،
  مع حماية من تلويث النموذج الأولي، وأمان من الدورات عبر `WeakSet`) وتستبدل التطابقات
  بعنصر نائب `[REDACTED:<type>]`، مع استنساخ الفروع التي تغيرت فعليًا فقط.
- تغطي `CREDENTIAL_PATTERNS` مفاتيح مزوّدي نماذج اللغة الكبيرة (OpenAI، OpenAI-proj،
  Anthropic، Google، Hugging Face، Replicate)، ورموز VCS/SaaS (GitHub، Slack،
  Linear، Notion، npm، Postman، Discord)، ومفاتيح الدفع (Stripe، Square)، ومفاتيح
  الخدمات السحابية (مفتاح وصول AWS، Twilio، SendGrid، Mailgun)، والمفاتيح الخاصة / رموز JWT،
  وسلاسل الاتصال التي تتضمن بيانات اعتماد (`mongodb://user:pass@...`، إلخ)،
  ونمطًا عامًا لقيم ترويسات `Authorization`/`x-api-key`/`api-key`/`apikey`.
  تُحجب المفاتيح ذات هيئة الترويسات (`authorization`، و`x-api-key`، و`api-key`،
  و`apikey`) بنيويًا (القيمة فقط، مع الحفاظ على بادئة المخطط مثل
  `Bearer `/`Basic `) بدلًا من استخدام التعبير النمطي النصي العام.
- لا يحظر حاجز الحماية مطلقًا؛ بل يعيد الكتابة فقط (`modifiedPayload` /
  `modifiedResponse`) ويضيف بيانات وصفية (`meta.credentialsRedacted`، و`meta.count`).

أداة منع الانحدار: `tests/unit/credential-masker-guardrail.test.ts`.

## العقد الأساسي (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // تؤدي القيمة true إلى إيقاف السلسلة فورًا
  message?: string; // تظهر عند الحظر
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // تُرجعها preCall لإعادة كتابة الطلب
  modifiedResponse?: TValue; // تُرجعها postCall لإعادة كتابة الاستجابة
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

يشير حاجز الحماية إلى «عدم وجود تغيير» عبر إرجاع `void` أو `{}` أو
`{ block: false }`. يؤدي إرجاع `modifiedPayload`/`modifiedResponse` إلى استبدال
القيمة المتدفقة عبر السلسلة لحواجز الحماية اللاحقة.
يحمل `signal?: AbortSignal` دورة حياة المستدعي إلى حواجز الحماية. يُعد إلغاء الطلب استثناءً مقصودًا يسمح بالمتابعة عند الفشل: إذ تتوقف جسور الوسائط عن العمل وتُجري التنظيف دون استعادة الوسائط الخام إلى هدف معروف بأنه لا يدعمها.

## السجل (`registry.ts`)

يكشف `guardrailRegistry` الأحادي عن:

- `register(guardrail)` — يضيف (أو يستبدل بالاسم المعياري) حاجزًا و
  يعيد الترتيب حسب `priority` التصاعدي.
- `clear()` / `list()` — مساعدات إدارية.
- `runPreCallHooks(payload, context)` — يكرر الحواجز النشطة، يمرر
  الحمولة عبر `modifiedPayload`، ويتوقف عند أول `block: true`.
- `runPostCallHooks(response, context)` — نفس التدفق على جانب الاستجابة.
- `resetGuardrailsForTests({ registerDefaults })` — يمسح الحالة و
  يعيد تسجيل الإعدادات الافتراضية اختياريًا لعزل الاختبار النظيف.

يعيد كل من المشغلين `{ blocked, payload|response, results, guardrail?, message? }`
حيث `results` هي مصفوفة من سجلات `GuardrailExecutionResult` التي تتضمن
حقول `blocked`, `skipped`, `modified`, `error`, و `meta` لكل حاجز،
مفيدة للتتبع.

### تعطيل الحواجز لكل طلب

يقوم `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` بتجميع قائمة
غير مكررة لأسماء الحواجز التي يجب تخطيها للطلب الحالي. المصادر (جميعها اختيارية، وجميعها مدمجة):

- `apiKeyInfo.disabledGuardrails`
- نص الطلب `disabledGuardrails` (على المستوى الأعلى)
- نص الطلب `metadata.disabledGuardrails`
- الرأس `x-omniroute-disabled-guardrails` (أو القديم
  `x-disabled-guardrails`)

يمكن أن تكون القيم مصفوفات من السلاسل أو سلسلة مفصولة بفاصلة؛ يتم
تطبيع الأسماء إلى صيغة kebab-case بالأحرف الصغيرة (`pii_masker` ← `pii-masker`).
يتم تمرير النتيجة عبر `context.disabledGuardrails` إلى السجل، الذي يتخطى
الحواجز المطابقة (`skipped: true` في `results`).

## ترتيب التنفيذ

لكل طلب يمر عبر `src/sse/handlers/chat.ts` و `open-sse/handlers/chatCore.ts`:

1.  يقوم `resolveDisabledGuardrails(...)` بإنشاء قائمة التخطي من مفتاح API، والنص الأساسي، والرؤوس.
2.  يقوم `guardrailRegistry.runPreCallHooks(body, ctx)` بتشغيل الحواجز الأمنية بترتيب تصاعدي للأولوية:
    - يتم تسجيل الحواجز الأمنية المعطلة على أنها `skipped`.
    - قد يقوم `preCall` لكل حاجز أمني بإعادة كتابة الحمولة عبر `modifiedPayload`.
    - أول `block: true` يقطع السلسلة ويعيد المعالج استجابة رفض الحاجز الأمني.
3.  تتدفق الحمولة (التي قد تكون أعيدت كتابتها) إلى توجيه التحرير والسرد والإرسال الأولي.
4.  بعد تجميع الاستجابة، يقوم `guardrailRegistry.runPostCallHooks(...)` بتشغيل نفس السلسلة على الاستجابة. `block: true` هنا يسقط الاستجابة الأولية.

يتم تسجيل الحواجز الأمنية التي تثير خطأ بـ `error: <message>` ويتم تسجيلها عبر `logger.warn`، لكن السلسلة تستمر — تصميم يسمح بالفشل المفتوح.

## التكوين

متغيرات البيئة التي تقرأها الحواجز الأمنية المدمجة:

| المتغير | يستخدم بواسطة | التأثير |
| `INPUT_SANITIZER_ENABLED` | `prompt-injection` | تعيين `false` لتعطيل الكشف بالكامل. |
| `INPUT_SANITIZER_MODE` | `prompt-injection` | سياسة الحقن: `warn` (تحذير)، `block` (حظر)، أو `log` (تسجيل). القيمة القديمة `redact` لا تعيد كتابة نص الحقن. |
| `INJECTION_GUARD_MODE` | `prompt-injection` | وضع حماية الحقن؛ وهو أيضًا علامة ميزة قاعدة بيانات **تتجاوز** متغيرات البيئة (قاعدة البيانات > البيئة). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD` | `prompt-injection` | الحد الأدنى للخطورة الذي يرفضه `MODE=block`: `high` (مرتفع، افتراضي)، `medium` (متوسط)، أو `low` (منخفض). |
| `INJECTION_GUARD_BLOCK_THRESHOLD` | `prompt-injection` | اسم مستعار قديم لـ `INPUT_SANITIZER_BLOCK_THRESHOLD`. |
| `PII_REDACTION_ENABLED` | `pii-masker` | عندما يكون `true`، يتم تنقيح معلومات التعريف الشخصية (PII) للطلب (بصرف النظر عن وضع الحقن). |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (downstream) | يتحكم في سلوك قناع الاستجابة. |

تقرأ الحواجز الأمنية لـ Modality Bridge التكوين في وقت التشغيل من مخزن الإعدادات المدعوم بقاعدة البيانات (`getSettings()`)، وليس من متغيرات البيئة. المفاتيح الأساسية لـ Vision هي `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, و `modalityBridgeCacheMaxEntries`. يتم قبول المفاتيح القديمة `visionBridge*` فقط كخيار احتياطي للقراءة لمرة واحدة كما هو موثق؛ تستخدم عمليات الكتابة في لوحة التحكم المفاتيح الأساسية. توجد القيم الافتراضية ومحلل الاحتياطي في `src/shared/constants/modalityBridgeDefaults.ts`، مع الاحتفاظ بالثوابت القديمة في `src/shared/constants/visionBridgeDefaults.ts`.

يستخدم الصوت `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, و `modalityBridgeAudioMaxClips`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. لا يحتوي الصوت على خيار احتياطي للمفاتيح القديمة لأن هذه المفاتيح تم تقديمها مع مخطط Modality Bridge.

يستخدم الفيديو `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, و `modalityBridgeVideoTimeout`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. يتم تعطيله افتراضيًا لأن FFmpeg/ffprobe هي تبعيات تشغيلية اختيارية، وإضافة تسميات الإطارات تزيد من زمن الاستجابة وتكلفة النموذج.

## حواجز حماية مخصصة

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

الخطوات:

1.  أنشئ `src/lib/guardrails/myGuardrail.ts` يوسع `BaseGuardrail`.
2.  نفّذ `preCall` و/أو `postCall`.
3.  سجّل إما وقت الاستيراد (ادفع من `registerDefaultGuardrails`) أو
    استدعِ `guardrailRegistry.register(...)` في وقت التشغيل — يحل السجل محل
    أي حاجز حماية سابق بنفس الاسم المعياري.
4.  أضف اختبارات تحت `tests/unit/` (أمثلة موجودة:
    `tests/unit/guardrails-registry.test.ts`,
    `tests/unit/prompt-injection-guard.test.ts`,
    `tests/unit/guardrails/visionBridge.test.ts`).

## الاختبار

استخدم `resetGuardrailsForTests()` بين الاختبارات للبدء من حالة معروفة.
مرر `{ registerDefaults: false }` للبدء بسجل فارغ و
تسجيل حواجز الحماية قيد الاختبار فقط. يقبل Vision Bridge حقن التبعية
(`deps.getSettings`, `deps.callVisionModel`)؛ يعرض Audio Bridge
الوصلات المكافئة للإعدادات، والقدرات، واختيار نموذج STT، وفحوصات الاعتماد،
والنسخ. وبالتالي يمكن للاختبارات ممارسة كلا التدفقين بدون قاعدة بيانات
أو الوصول إلى الشبكة.

## تغطية مسار حماية الحقن والاختبار الأحمر (المرحلة 8 · الكتلة D)

يغطي حارس الحقن (`createInjectionGuard` / `withInjectionGuard`) جميع المسارات
التي تقبل مطالبات المستخدم. وهو يحترم `INJECTION_GUARD_MODE` (الافتراضي `warn` = تسجيل فقط؛
`block` = يعيد HTTP 400 `SECURITY_001`).

| النوع      | المسارات                                                                                                                                             | الوضع الافتراضي |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| نص (موجود) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| توليدي     | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| بيانات     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

تغطية استخراج النص (`extractMessageContents`) تشمل `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`.

**الفريق الأحمر (ليلي، `nightly-llm-security.yml`):** يتحقق promptfoo من أن كل مسار يحظر
مجموعة OWASP-LLM في `INJECTION_GUARD_MODE=block`؛ يقوم garak بتشغيل الفحوصات (يتخطى بدون سر).
يتم تضمين `moderations` من أجل الاتساق — يمكن للمشغلين في وضع الحظر إعفائها عبر
`resolveDisabledGuardrails`.

يحتوي سير العمل الليلي (`.github/workflows/nightly-llm-security.yml`، cron +
التشغيل اليدوي) على وظيفتين:

- **`promptfoo-guard` (حظر)** — يشغل `promptfoo eval -c promptfooconfig.yaml`
  مع `INJECTION_GUARD_MODE=block`. تؤكد كل حالة عدائية (مثل "تجاهل جميع
  التعليمات السابقة..."، اختراقات على غرار DAN) أن الاستجابة تحمل
  `error.code === "SECURITY_001"`، أي أن الحارس رفض الطلب بالفعل.
- **`garak` (استشاري)** — يشغل garak `--probes promptinject,dan,leakreplay`
  مقابل مثيل OmniRoute محلي (`http://localhost:20128/v1`). يتم التحكم فيه بواسطة
  سر مزود (`PROMPTFOO_PROVIDER_KEY`)؛ يتخطى بأمان ويتم إلحاقه بـ
  `|| true`، لذلك يتم الإبلاغ عنه دون فشل CI.

تغطية مساعد الحارس (`createInjectionGuard` / `withInjectionGuard`)
تمتد عبر كل مسار `/v1` يحمل مطالبة؛ يتم سحب نص المطالبة من
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` بواسطة
`extractMessageContents()` في `src/shared/utils/inputSanitizer.ts`.
