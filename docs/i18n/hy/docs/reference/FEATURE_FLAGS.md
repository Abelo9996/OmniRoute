## Ինչ են ֆիչր դրոշները (Feature Flags)

Ֆիչր դրոշը անվանական անջատիչ է (բուլյան կամ թվարկում), որի արժեքը կարող է փոփոխվել գործարկման ժամանակ և պահպանվել տվյալների բազայում՝ առանց գործընթացի վերատեղակայման անհրաժեշտության։ Յուրաքանչյուր դրոշ նկարագրվում է `FeatureFlagDefinition`-ով, որն ունի `key`, `label`, `description`, `category`, `defaultValue`, `type` և `requiresRestart` հուշում։

### Լուծման հերթականություն

Դրոշի **արդյունավետ արժեքը** լուծվում է
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ֆունկցիայի միջոցով՝ հետևյալ առաջնահերթությամբ (ամենաբարձրը հաղթում է).

1.  **DB-ի վերագրանցում** — `key_value` աղյուսակում `feature_flags` անվանատարածքում պահվող արժեք (սահմանվում է կառավարման վահանակի կամ REST API-ի միջոցով)։
2.  **Միջավայրի փոփոխական** — `process.env[<KEY>]`, եթե սահմանված է և դատարկ չէ։
3.  **Սահմանման լռելյայն արժեք** — `defaultValue` `featureFlagDefinitions.ts` ֆայլից։

Բուլյան դրոշը համարվում է **միացված**, երբ դրա արդյունավետ արժեքը `"true"`, `"1"` կամ `"yes"` է (տես `isFeatureFlagEnabled()`)։

> [!NOTE]
> Դրոշների մեծ մասն ունեն նաև համապատասխան միջավայրի փոփոխական՝ **նույն անունով**, որը փաստաթղթավորված է [`ENVIRONMENT.md`](./ENVIRONMENT.md) ֆայլում։ Դրոշի DB-ի վերագրանցումն ունի առաջնահերթություն այդ միջավայրի փոփոխականի նկատմամբ։ `requiresRestart: true` ունեցող դրոշն անմիջապես պահպանվում է, բայց նորից կարդացվում է միայն գործընթացի մեկնարկի ժամանակ. այն միացնելիս կառավարման վահանակում հայտնվում է **«Վերագործարկել սերվերը»** (Restart Server) պաստառ։

## Դրոշակների կատալոգ

86 դրոշակ՝ 6 կատեգորիաներում։ **Լռելյայնը** սահմանման լռելյայն արժեքն է՝ այն արժեքը,

> `INJECTION_GUARD_MODE`-ի `block` ռեժիմը, սակայն դրանք սովորական միջավայրի փոփոխականներ են, որոնք ընթերցվում են
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts)-ի կողմից,
> այլ ոչ թե գործառույթի դրոշներ. դրանք չունեն DB վերասահմանում կամ կառավարման վահանակի փոխարկիչ։ Տե՛ս
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication)։

> [!NOTE]
> `Վերագործարկում` սյունակը նշում է `requiresRestart: true` ունեցող դրոշները. արժեքը
> պահպանվում է անմիջապես, սակայն ուժի մեջ է մտնում միայն գործընթացի վերաբեռնումից հետո։ Թվարկման
> դրոշները մերժում են իրենց թույլատրելի բազմությունից դուրս ցանկացած արժեք (սերվերի կողմում վավերացվում է
> ինչպես `setFeatureFlagOverride()`-ում, այնպես էլ REST `PUT` մշակիչում)։

## Դրոշակների միացում/անջատում

### Կառավարման վահանակ

Անցեք **Կառավարման վահանակ → Կարգավորումներ → Ֆունկցիոնալ դրոշակներ**
(`/dashboard/settings/feature-flags`): Ցանցը
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
աջակցում է.

- **Որոնում** ըստ բանալու կամ նկարագրության, և **ֆիլտրում** ըստ կատեգորիայի (գումարած սինթետիկ
  **Պահանջում է վերագործարկում** տեսք):
- **Միացման/անջատման կոճակ** բուլյան դրոշակների համար և **ընտրացանկ** enum դրոշակների համար
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`):
- **Աղբյուրի նշան** յուրաքանչյուր դրոշակի համար՝ `DB`, `ENV` կամ `DEF`, որը ցույց է տալիս, թե որտեղից է եկել
  արդյունավետ արժեքը:
- **Վերակայման կոճակ** (ցուցադրվում է միայն `DB`-ից ստացված դրոշակների համար)՝ վերագրանցումը հեռացնելու համար,
  և **Վերակայել բոլոր վերագրանցումները** կոճակը ներքևում:
- **Վերագործարկել սերվերը** պաստառ, երբ `requiresRestart` դրոշակը փոխվում է:

### REST API

Բոլոր գործողությունները կատարվում են մեկ երթուղու միջոցով.
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts):
Յուրաքանչյուր մեթոդ պահանջում է վավերացված կառավարման վահանակի նիստ (`401` հակառակ դեպքում):

#### `GET /api/settings/feature-flags`

Վերադարձնում է յուրաքանչյուր դրոշակ իր արդյունավետ արժեքով, աղբյուրով և ամփոփագրով:

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Պահանջել API բանալի",
      "description": "Պահանջել API բանալի բոլոր մուտքային հարցումների համար",
      "category": "անվտանգություն",
      "type": "բուլյան",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "զգուշություն",
    },
    // ... բոլոր 77 դրոշակները
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Սահմանել կամ հեռացնել մեկ վերագրանցում: Մարմինը՝ `{ key: string; value?: string }`:
`value`-ի բացթողումը հեռացնում է վերագրանցումը (վերականգնելով env / default):

```bash
# Սահմանել DB վերագրանցում
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Հեռացնել վերագրանցումը (առանց "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Պատասխանը արտացոլում է նոր `effectiveValue`/`source`, `previousValue`/
`previousSource` և `requiresRestart`: Անհայտ բանալիները և միջակայքից դուրս enum
արժեքները մերժվում են `400`-ով:

#### `DELETE /api/settings/feature-flags`

Միանգամից մաքրում է **բոլոր** DB վերագրանցումները՝ վերականգնելով յուրաքանչյուր դրոշակ իր env / default
արժեքին: Վերադարձնում է `{ cleared: <count>, message: "..." }`:

> [!NOTE]
> `requiresRestart: true` դրոշակներն ուժի մեջ են մտնում միայն գործընթացի վերաբեռնումից հետո:
> Կառավարման վահանակի վերագործարկման հոսքը կանչում է `POST /api/restart` և այնուհետև հարցում է կատարում
> `GET /api/health/ping` մինչև սերվերը նորից գործի անցնի:

## Բյուջեի արտակարգ պահուստային տարբերակ

`OMNIROUTE_EMERGENCY_FALLBACK`-ը (`runtime` կատեգորիա, լռելյայն՝ `true`) կառավարում է արտակարգ անվճար պահուստային ուղին
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)-ում։
Երբ այն միացված է, իրենց բյուջեն սպառած հարցումները անմիջապես ձախողվելու փոխարեն ուղղորդվում են անվճար պահուստային մատակարար/մոդել։ Սահմանեք այն որպես `false` (կամ `0`)՝ կառավարման վահանակի փոխարկիչի, DB վերասահմանման կամ `OMNIROUTE_EMERGENCY_FALLBACK`
միջավայրի փոփոխականի միջոցով՝ այս վարքագիծն անջատելու և բյուջեն սպառած հարցումներին ձախողվելու հնարավորություն տալու համար։ (Կառավարման վահանակում ներկայացված է որպես փոխարկիչ PR-ներ #3741 / #3752-ում։)

Այս պահուստային տարբերակով սպասարկված պատասխանը պարունակում է
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, որպեսզի հաճախորդը կարողանա հասկանալ, որ հարցումը վերաուղղորդվել է՝ առանց `X-OmniRoute-Provider`-ը իր հարցման հետ համեմատելու։
Այս վերնագիրն առկա չէ որևէ այլ պատասխանում։
