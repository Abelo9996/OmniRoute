> **Ճշմարտության աղբյուր՝** `src/lib/guardrails/`
> **Վերջին թարմացումը՝** 2026-08-29 — v3.8.51 (Video Bridge-ի տրանսկրիպտի ծագումը հայտարարում է կանչողը,
> և այն դեռ չի ստուգվում սերվերի կողմից — հստակեցվել է ըստ #11661-ի)

Պաշտպանիչ սահմանափակումներն ապահովում են անվտանգությունը, քաղաքականությունների կիրառումը և բովանդակության փոխակերպումները
OmniRoute-ի ու վերին մակարդակի մատակարարների միջև ընկած սահմանագծում։ Յուրաքանչյուր պաշտպանիչ սահմանափակում կարող է ստուգել (և
ըստ անհրաժեշտության մերժել, փոխակերպել կամ ծանոթագրել) հարցման օգտակար բեռները (`preCall`) և
վերին մակարդակի պատասխանները (`postCall`)։

Համակարգը գործում է **fail-open** սկզբունքով․ եթե պաշտպանիչ սահմանափակման կատարման ընթացքում բացառություն է առաջանում, ռեեստրը
գրանցում է սխալը և հարցումը ձախողելու փոխարեն շարունակում է հաջորդ պաշտպանիչ սահմանափակմամբ։
Արգելափակումը միշտ բացահայտ որոշում է (`block: true`) և երբեք՝ պատահականություն։

## Ներկառուցված պաշտպանիչ սահմանափակումներ

Ներմուծման ժամանակ ռեեստրը առաջնահերթության կարգով ավտոմատ բեռնում է վեց պաշտպանիչ սահմանափակում
(տե՛ս `registry.ts` → `registerDefaultGuardrails()`).

| Առաջնահերթություն | Անուն               | Փուլ(եր)       | Ֆայլ                  |
| ----------------- | ------------------- | -------------- | --------------------- |
| `5`               | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`               | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`               | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`              | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`              | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`              | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

Առաջնահերթության ավելի փոքր թվերով սահմանափակումները գործարկվում են **առաջինը**։

### Տեսողական կամուրջ (`visionBridge.ts`) — Մոդալության կամուրջ PR-1

Ընդհատում է **տեսողական հնարավորություններ չունեցող մոդելներին** ուղղված՝ պատկերներ պարունակող հարցումները և կամ ամբողջ հարցումը վերաուղղորդում է տեսողական հնարավորություններով մոդելին, կամ վերին մակարդակի կանչից առաջ պատկերների մասերը փոխարինում է կարգավորվող տեսողական մոդելի ստեղծած տեքստային նկարագրություններով։ Սա թույլ է տալիս միայն տեքստ մշակող մատակարարներին թափանցիկորեն սպասարկել բազմամոդալ օգտակար բեռներ։

Ընթացքը՝

1. Բաց թողնել, եթե թիրախային մոդելն արդեն աջակցում է տեսողական տվյալներին (եթե այն ներառված չէ պարտադիր կամրջման `isVisionBridgeForcedModel` ցանկում)։
2. Արտահանել պատկերների մասերը `extractImageParts(messages)`-ի միջոցով
   (`visionBridgeHelpers.ts`), որն աշխատանքը փոխանցում է `open-sse/utils/mediaParts.ts`-ում գտնվող **միասնական մեդիա հայտնաբերիչ** `detectMediaParts()`-ին՝ combo համատեղելիության զտիչի հետ օգտագործվող ճշմարտության միակ աղբյուրին։
   Արտահանումը թույլատրող ցանկով սահմանափակված է վերին մակարդակի այն ձևերի մասերով, որոնք
   `replaceImageParts`-ը կարող է հետ տեղադրել (արտահանում↔փոխարինում պայմանագիր)՝ OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"` և Responses API `input_image`։ Ներդրված համընկնումներն ու
   միայն ցուցիչ պարունակող ձևերը նախատեսված են combo զտիչի համար և երբեք չեն արտահանվում։
   Բաց թողնել, եթե ոչինչ չի գտնվել։
3. Որոշել կատարման ժամանակի կազմաձևը `resolveVisionBridgeRuntimeSettings()`-ի միջոցով
   (`src/shared/constants/modalityBridgeDefaults.ts`)․ նոր `modalityBridge*`
   կարգավորումների բանալիները գերակայում են, իսկ հին `visionBridge*` բանալիները մնում են որպես
   **մեկ ցիկլի հետադարձ տարբերակ** (հետշրջման պատուհան)։ Եթե կամուրջն անջատված է, բաց թողնել՝ նախքան մեդիա տարրերով որևէ անցում կատարելը։
4. Ռեժիմի ընտրիչը (`modalityBridgeVisionMode`, տե՛ս ստորև բերված աղյուսակը) որոշում է՝
   վերաուղղորդել, թե նկարագրել։ Վերաուղղորդումը վերադարձնում է `modifiedPayload`, որտեղ փոխված է միայն `model`-ը, ինչպես նաև `{ rerouted, fromModel, toModel, imagesKept }` մետատվյալները։
5. Նկարագրման ուղի․ սահմանափակել պատկերների քանակը `maxImages`-ով, կազմել առաջադրանքը հաշվի առնող հուշումը,
   դիմել նկարագրությունների քեշին, տեսողական մոդելը կանչել **զուգահեռաբար**
   (`Promise.allSettled`) և դրանց տեղում ներարկել `[Image N]: <description>` տեքստային մասեր։
   Չհաջողված նկարագրման դեպքում ստացվում է `null`, իսկ պատկերի սկզբնական մասը
   **պահպանվում է** (#4012), բացառությամբ combo նկարագրման ուղու, երբ բոլոր նկարագրումները ձախողվել են․ այդ դեպքում հաստատված ոչ տեսողական վերին մակարդակի ծառայությունը ստանում է
   `(անհասանելի է — տեսողական հնարավորություններով որևէ մատակարար միացված չէ)` փոխարինիչը (#8430)։
6. Վերադարձնել `modifiedPayload`-ը և մետատվյալները (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`)։

#### Ռեժիմի ընտրիչ (`modalityBridgeVisionMode`)

| Ռեժիմ      | Լռելյայն | Վարքագիծ                                                                                                                                                                                                                                                                                                                                        |
| ---------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔        | Հին էվրիստիկան՝ անփոփոխ (#6640/#7204)․ ոչ combo/`auto/` մոդելները վերաուղղորդվում են լավագույն տեսողական մոդելին, եթե սկզբնական մոդելն արդեն չունի օգտագործելի հավատարմագրեր (այդ դեպքում կատարվում է նկարագրում)։ Combo թիրախները միշտ նկարագրվում են։                                                                                         |

| `reroute`  |          | Հարկադիր վերաուղղորդում․ հավատարմագրեր ունեցող մոդելը պահպանող ստուգումն անտեսվում է։ Վերաուղղորդման **թիրախի** հավատարմագրերի ստուգումը շարունակում է կիրառվել․ երբ օգտագործելի տեսողական թիրախ գոյություն չունի, հարցումն անցնում է նկարագրման ուղուն, որպեսզի չմշակված պատկերները երբեք չհասնեն միայն տեքստ մշակող հետին համակարգին (#8430)։ |

Հարկադիր ռեժիմները կարճ միացմամբ ավարտվում են **նախքան** ավտոմատ էվրիստիկայի գործարկումը․ `auto`-ի վարքագիծը բայթ առ բայթ նույնական է PR-1-ին նախորդող պաշտպանիչ սահմանափակման վարքագծին։

#### API բանալու տիրույթ (`visionBridgeKeyScope.ts`)

Երբ կանչողի API բանալին սահմանափակում է `allowedConnections`-ը, քվոտաների խմբերը
(`allowedQuotas`) կամ մոդելները (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`), կամուրջն ընտրում է միայն այն վերաուղղորդման և նկարագրման մոդելները, որոնք բանալուն թույլատրված է օգտագործել՝ բանալուն հասանելի միացումներով։ Այնուհետև նկարագրման կանչը միշտ անցնում է OmniRoute-ի ինքնահղման միջոցով՝
`x-omniroute-self-loop-key-id` վերնագրով, որպեսզի ընդունող չատի հարցումը կրկին կիրառի տվյալ բանալու միացումների և մոդելների քաղաքականությունը։ `enforceApiKeyPolicy()`-ն այդ վերնագիրը հաշվի է առնում միայն ինքնահղման bearer-ի հետ միասին, ուստի այն կարող է միայն նեղացնել հասանելիությունը, իսկ չլուծվող id-ն մերժվում է։

Եթե բանալու համար ոչ մի տեսողական մոդել թույլատրված չէ, նկարագրման ուղին չի միջամտում, և հարցումն անցնում է անփոփոխ՝ նույն fail-open վարքագծով, ինչ անջատված պաշտպանիչ սահմանափակման դեպքում (մետատվյալներ՝ `{ skipped: true, reason: "no_permitted_vision_model" }`)։
Առանց բանալու հարցումները և այս սահմանափակումները չունեցող բանալիները գործում են ճիշտ այնպես, ինչպես նախկինում։

#### Առաջադրանքը հաշվի առնող նկարագրման հուշում (`modalityBridgeVisionTaskAware`)

Լռելյայն՝ **true**։ `composeVisionPrompt()`-ը (`visionBridgeHelpers.ts`) հիմնական նկարագրության հուշմանը կցում է **օգտատիրոջ վերջին հաղորդագրության** տեքստը (կրճատված մինչև 500 նիշ)՝ նկարագրությունն ուղղորդելով դեպի այն, ինչ օգտատերն իրականում խնդրել է (codex-vision-proxy ձևանմուշ), և տեսողական մոդելին խնդրելով արտագրել տեսանելի տեքստը։ Եթե դրոշակն անջատված է, կամ օգտատիրոջ տեքստ չկա, հիմնական հուշումն օգտագործվում է անփոփոխ։

Նկարագրության ինքնաշրջանի սեփական OpenAI-ի հետ համատեղելի հարցումը (`callVisionModelSingle()`-ը `visionBridgeHelpers.ts`-ում) միշտ պահանջում է `image_url.detail: "high"`՝ առանց որևէ պայմանի, յուրաքանչյուր կանչողի/մատակարարի համար և անկախ հաճախորդի որևէ ազդանշանից։ Ցածր մանրամասնությամբ ընտրարկումը նվազեցնում է OCR-ի ճշգրտությունը հենց այն տեքստի արտագրման առաջադրանքի համար, որը պահանջում է այս հուշումը, ուստի նկարագրության կանչն ինքնին միշտ պահանջում է բարձր մանրամասնություն՝ անկախ նրանից, թե սկզբնական մուտքային հարցումը մանրամասնության ինչ մակարդակ է օգտագործել։ Սա ազդում է միայն ներքին նկարագրության հարցման մարմնի վրա և չի փոխում այն, թե OmniRoute-ն ինչպես է հիմնական հարցման մեջ փոխանցում կանչողի սեփական `image_url.detail`-ը․ այդ լռելյայն արժեքը կիրառվում է առանձին և միայն հայտնաբերված OpenCode հաճախորդների համար՝ `defaultImageDetail()`-ում (`open-sse/handlers/chatCore/upstreamBody.ts`)։ Նկարագրության ինքնաշրջանի Anthropic wire-format ճյուղը չունի `detail` դաշտ և չի ազդվում այս լռելյայն արժեքներից որևէ մեկից։

#### Նկարագրության ելքի սահմանաչափ (`modalityBridgeVisionMaxChars`)

| Բանալի                         | Լռելյայն | Միջակայք          |
| ------------------------------ | -------- | ----------------- |
| `modalityBridgeVisionMaxChars` | `0`      | `0` կամ 100–50000 |

`0`-ը (լռելյայն) նշանակում է **առանց սահմանաչափի**․ `callVisionModel()`-ի վերադարձած նկարագրությունը փոխանցվում է անփոփոխ՝ պահպանելով առկա վարքագիծը։ 100–50000 միջակայքի ցանկացած արժեք նկարագրությունը կրճատում է՝ ավելացնելով `…` վերջածանց, նախքան այն կրկին տեղադրվում է որպես `[Image N]: <description>` (`VisionBridgeGuardrail.preCall()`-ը `src/lib/guardrails/visionBridge.ts`-ում)։ Բարձրացրեք այս արժեքը մանրամասներով հարուստ OCR առաջադրանքների համար, երբ հաջորդ մոդելին անհրաժեշտ է ամբողջական արտագրությունը, իսկ չափազանց շատախոս տեսողական մոդելների թոքենների օգտագործումը սահմանափակելու համար՝ նվազեցրեք այն։ Վահանակի դաշտը գտնվում է Vision ներդիրի Advanced վահանակում (`modality-bridge-max-chars`-ը `ModalityBridgeVisionTab.tsx`-ում) և 1-ից 99-ի միջև ցանկացած արժեք բարձրացնում է մինչև նվազագույն 100-ը՝ միաժամանակ հստակ նշված `0`-ն անփոփոխ թողնելով․ `0`-ն ինքնին վավեր Zod արժեք է (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), այլ ոչ թե պարզապես «չսահմանված» լռելյայն արժեք։

#### Նկարագրությունների քեշ (`modalityBridge/bridgeCache.ts`)

Նկարագրությունների արդյունքների համար հիշողության մեջ պահվող LRU + TTL քեշ, որը համօգտագործվում է ամբողջ պրոցեսի մասշտաբով։  
Բանալի = `sha256(imageRef + composedPrompt + configuredBridgeModel)`՝ երկարության նախածանցով շրջանակմամբ (դաշտերի սահմանների բախումներ չկան)։ Մոդելի բաղադրիչը **կարգավորված** կամրջի մոդելն է, այլ ոչ թե փաստացի պատասխանած մոդելը․ `callVisionModel`-ը կարող է ներքին կերպով օգտագործել պահուստային տարբերակ, իսկ ըստ յուրաքանչյուր փորձի բանալիավորումը կբեկորի քեշը։ Չհաջողված նկարագրությունները երբեք չեն քեշավորվում։ Կարգավորումներ՝

| Բանալի                          | Լռելյայն | Միջակայք |
| ------------------------------- | -------- | -------- |
| `modalityBridgeCacheEnabled`    | `true`   | —        |
| `modalityBridgeCacheTtlMinutes` | `60`     | 1–1440   |
| `modalityBridgeCacheMaxEntries` | `200`    | 10–5000  |

#### Հեռակա պատկերների նորմալացում (ինքնաշրջանային նկարագրություն/base64 ներբեռնում)

Երբ կամուրջն ինքն է ներբեռնում **հեռակա** պատկեր՝ Anthropic նկարագրության ինքնականչի և claude-wire-format base64 փոխակերպման (`ensureBase64ImagesForClaudeWire`) համար, երկուսն էլ `visionBridgeHelpers.ts`-ի `fetchRemoteImageAsDataUri()`-ի միջոցով, ստացված տվյալների URI-ն փոխանցվում է `normalizeDataUri()`-ով (`open-sse/utils/imageNormalize.ts`)՝ նախքան տեսողական մոդելի հարցման մեջ ներդրվելը։ Չափազանց մեծ պատկերների չափը փոքրացվում է մինչև **2048px երկար եզր** (համապատասխանելով չափի այն սահմանաչափին, որն OpenAI-ը/Anthropic-ը արդեն կիրառում են սերվերային կողմում), ինչը նվազեցնում է վերբեռնվող բայթերի քանակը/ուշացումը՝ առանց փոխելու տեսողական մոդելի տեսածը։ Չափափոխման համար օգտագործվում է `sharp`-ը, որը բեռնվում է դինամիկ ներմուծմամբ․ այն հարթակներում, որտեղ դրա բնիկ բինար ֆայլը չի բեռնվում, `normalizeDataUri()`-ն **երբեք բացառություն չի նետում**․ այն պարզապես փոխանցում է սկզբնական բայթերը, որպեսզի նկարագրության/base64-փոխակերպման ուղին մշտապես շարունակի աշխատել։ Ոչ պատկերային բայթերը (երբ ներբեռնումը չի վերադարձրել վերծանելի պատկեր) նույնպես փոխանցվում են անփոփոխ։ Այս նորմալացումը սահմանափակված է այն պատկերներով, որոնք կամուրջը ներբեռնում է իր սեփական ինքնականչի համար․ այն երբեք չի կիրառվում կանչողի չմշակված, անմիջապես փոխանցվող բեռի նկատմամբ՝ համապատասխանելով միայն հստակ ընտրության դեպքում փոփոխելու սկզբունքին (Խիստ կանոն #20)։

#### Կարգավորումների սխեմա + միգրացիա

Նոր `modalityBridge*` բանալիները Zod-ով վավերացվում են `updateSettingsSchema`-ում (`src/shared/validation/settingsSchemas.ts`)՝ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` եռյակը և Audio Bridge-ի կողմից օգտագործվող `modalityBridgeAudio*` խումբը։ `141_modality_bridge_settings.sql` միգրացիան առկա հին `visionBridge*` արժեքները պատճենում է համապատասխան նոր բանալիների մեջ (իդեմպոտենտ է և երբեք չի վերագրում օպերատորի կողմից սահմանված `modalityBridge*` արժեքը)․ հին բանալիները մեկ թողարկման ցիկլի ընթացքում շարունակում են ընդունվել որպես ընթերցման պահուստային տարբերակ։

#### Թափանցիկության վերնագիր + վիճակագրություն

Նկարագրության միջոցով փոխակերպված պատասխանները պարունակում են `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` (`buildModalityBridgeHeader()`-ով ստեղծված՝ `modalityBridge/bridgeStats.ts`-ում և `withModalityBridgeHeader()`-ով ավելացված՝ `src/sse/handlers/chatHelpers.ts`-ում)։ Վերաուղղված հարցումները վերնագիր **չեն** ստանում․ բեռը չի փոփոխվել, իսկ մոդելի փոխարինումն արդեն տեսանելի է պատասխանի մարմնի `model` դաշտում։

`GET /api/modality-bridge/stats`-ը (կառավարման նույնականացում՝ նույն մակարդակով, ինչ
`GET /api/settings`-ը) վերադարձնում է հիշողության մեջ պահվող՝ ըստ մոդալության հաշվիչները՝
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }`՝ `vision`, `audio` և
`video` մոդալությունների համար։ `averageLatencyMs`-ը որպես հայտարար օգտագործում է
`latencySamples`-ը, այլ ոչ բոլոր փորձերը․ ժամանակաչափում չունեցող գործողության համար
զրո միլիվայրկյանանոց կեղծ նմուշ չի ստեղծվում։ `bridged`-ը մնում է հաջող
փոխակերպումների հետընթաց համատեղելի կեղծանունը․ ձախողված փորձերը չեն ավելացնում այն։
Հաշվիչները նախագծմամբ զրոյացվում են պրոցեսի վերագործարկման ժամանակ
(հեռաչափություն, ոչ թե հաշվառում)։

#### Կառավարման վահանակի կազմաձևում

Կառավարման վահանակի հատուկ էջն է
`/dashboard/settings/modality-bridge`։ URL-ով հասցեավորվող դրա `Vision`, `Audio`
և `Video` ներդիրները ներդիրները փոխելիս պահպանում են հարցման պարամետրերը՝ փոխելով
`tab` արժեքը։
Vision ներդիրը հասանելի է դարձնում միացումը, ռեժիմը, մոդելի ընտրությունը (ներառյալ
ավտոմատ լռելյայն տարբերակը), առաջադրանքը հաշվի առնող հուշումները, ժամանակի սպառման/
պատկերի/նկարագրության երկարության/քեշի ընդլայնված սահմանաչափերը, կատարման ժամանակի
հաշվիչները և պաշտպանված օրինակելի հարցումը։ Audio ներդիրը նույնպես գործուն է․ այն
հասանելի է դարձնում միացումը, միայն STT մոդելների ընտրիչը՝ Auto տարբերակով,
ժամանակի սպառման/հոլովակի առավելագույն սահմանաչափերը, աուդիո հաշվիչները և
`input_audio` օրինակելի թեստը։ Video ներդիրը գործունակ է․ այն հաղորդում է
FFmpeg/ffprobe-ի կատարման միջավայրի վիճակը՝ չորս հստակ UI վիճակներից մեկը
(`unknown`, քանի դեռ ստուգումն ընթացքի մեջ է կամ չի կարող ավարտվել,
`restricted`՝ ոչ loopback կառավարման վահանակի հոսթում, որտեղ ստուգումը բաց է թողնվում
հաճախորդի կողմում, `unavailable`՝ ստուգումից և բացակայության հաստատումից հետո,
կամ `available`՝ FFmpeg/ffprobe տարբերակներով), պահպանում է միացման/մոդելի/կադրի/
տեսանյութի/ժամանակի սպառման սահմանաչափերը, մոդելի ընտրիչը զտում է՝ թողնելով
տեսողություն աջակցող մոդելները, և հասանելի է դարձնում տեսանյութի հաշվիչները։

AI կարգավորումների ներքո գտնվող նախկին Vision Bridge քարտն այժմ նոր էջ տանող
համատեղելիության հղում է․ այն այլևս չի պարունակում ձևի երկրորդ օրինակը։ Media
Providers-ը նաև Image-to-Text և Speech-to-Text աշխատանքային հոսքերը կապում է
Modality Bridge-ի համապատասխան ներդիրներին՝ առանց գոյություն ունեցող Speech-to-Text
փորձադաշտը հեռացնելու։

**Ինքնահանգույցի ընդունման շրջանցում․** երբ նկարագրման կանչը երթուղավորվում է
OmniRoute-ի սեփական `/v1` ինքնահանգույցով (ոչ ստանդարտ մատակարարի մոդել), ենթահարցումն
ուղարկում է `x-omniroute-admission-bypass: internal` և նույնականացվում է լուծված
ինքնահանգույցի հավատարմագրով՝ տեղային ռեժիմում տեղային `sk_omniroute` sentinel-ով,
կամ օպերատորի կազմաձևած `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` միջավայրի բանալիով
(#1350), որպեսզի `REQUIRE_API_KEY=true` տեղակայումները նույնպես կարողանան կատարել
նկարագրման կանչը։ Շրջանցումն ընդունվում է միայն հենց այդ հավատարմագրերի համար,
ուստի արտաքին հաճախորդները չեն կարող օգտագործել վերնագիրը՝ ընդունումը շրջանցելու
համար։

Ժառանգական լռելյայն արժեքները գտնվում են
`src/shared/constants/visionBridgeDefaults.ts`-ում, իսկ նոր ռեժիմի/առաջադրանքը
հաշվի առնելու/քեշի լռելյայն արժեքներն ու կարգավորումների լուծիչը՝
`src/shared/constants/modalityBridgeDefaults.ts`-ում։ Պաշտպանիչ մեխանիզմը տրամադրում է
`deps` կոնստրուկտորի ընտրանք, որպեսզի թեստերը կարողանան ներարկել կեղծ `getSettings`
և `callVisionModel` իրականացումներ։

### Audio Bridge (`audioBridge.ts`) — Modality Bridge PR-3

Ընդհատում է աուդիո պարունակող զրույցի հարցումները՝ նախքան դրանք կհասնեն աուդիո
մուտք ընդունելու ունակ չհամարվող թիրախին։ Այն երբեք չի վերաերթուղավորում զրույցի
հարցումը․ աուդիո մասերը տառադարձվում են գոյություն ունեցող՝ OpenAI-ի հետ համատեղելի
բազմամաս վերջնակետի միջոցով, իսկ ընտրված զրույցի մոդելը շարունակում է աշխատել
տեքստային տառադարձումներով։

Հոսքը՝

1. Լուծել `supportsAudio`-ն `getResolvedModelCapabilities()`-ի միջոցով։ Մատակարարի
   ռեեստրի հստակ մետատվյալներն ունեն առաջնահերթություն, ապա՝ ստատիկ մոդելի
   մետատվյալները, իսկ հետո՝ համաժամացված `modalities_input`-ը։ Հայտարարված մուտքային
   ցանկը, որը չի պարունակում `audio`, համարվում է `false`, իսկ կարողության մասին
   ապացույցների բացակայությունը՝ `null`։ Թե՛ `false`-ը, թե՛ `null`-ը ակտիվացնում են
   պահպանողական կամուրջը, մինչդեռ `true`-ն շրջանցում է այն։
2. Լուծել `modalityBridgeAudio*` կարգավորումները և յուրաքանչյուր հաղորդագրությունից
   ընդհանուր `detectMediaParts()` հայտնաբերիչի միջոցով առանձնացնել վերակցվող
   վերին մակարդակի աուդիո մասերը։ Աջակցվող փոխանցման ձևաչափերն են OpenAI-ի
   `input_audio`, `audio_url` և `source.media_type: "audio/*"`։ Ներդրված աուդիոն
   հայտնաբերվում է երթուղավորման համար, սակայն չի հեռացվում վերակցման ուղու կողմից։
   Աշխատանքը սահմանափակվում է `modalityBridgeAudioMaxClips`-ով․ հետագա մասերը մնում
   են անփոփոխ։
3. Հաշվի առնել կազմաձևված `provider/model`-ը կամ թույլ տալ
   `selectAudioBridgeModel()`-ին կայուն կատալոգային հերթականությամբ անցնել
   `AUDIO_TRANSCRIPTION_PROVIDERS`-ով և ընտրել օգտագործելի ակտիվ մատակարարի
   հավատարմագիր ունեցող առաջին մոդելը։
4. `callAudioTranscription()`-ը base64/data-URI աուդիոն փոխակերպում է բազմամաս
   `file`-ի կամ ներբեռնում է հեռակա `audio_url`-ը՝ միայն հանրային ելքային
   պաշտպանիչի միջոցով, DNS ամրակցմամբ և 25 MB սահմանաչափով։ Այնուհետև այն POST
   հարցմամբ ֆայլը և ընտրված մոդելն ուղարկում է տեղային
   `/v1/audio/transcriptions` ինքնահանգույց՝ նույնականացվելով
   `resolveSelfLoopBearer()`-ով։ Գոյություն ունեցող տառադարձման երթուղին կատարում է
   հավատարմագրերի սովորական որոնում, սառեցման/հաճախականության սահմանափակման մշակում և
   մատակարարին փոխանցում։
5. Հաջող կանչերն իրենց մասերը փոխարինում են `[Audio N]: <transcript>`-ով։ Կանչերը
   կատարվում են `Promise.allSettled`-ով․ առանձին ձախողումը պահպանում է տվյալ սկզբնական
   աուդիո մասը (#4012 պայմանագիր)։ Եթե բոլոր կանչերը ձախողվում են, և ապացուցված է, որ
   թիրախի `supportsAudio === false`, մասերը դառնում են
   `[Audio N]: (անհասանելի է — STT մատակարար միացված չէ)` (#8430 պայմանագիր)։
   Անհայտ թիրախի (`null`) դեպքում ամբողջական ձախողման արդյունքը մնում է անփոփոխ։
   Ապացուցված՝ միայն տեքստ աջակցող և օգտագործելի STT հավատարմագիր չունեցող թիրախը
   ստանում է նույն հստակ փոխարինիչը՝ առանց ցանցային կանչ կատարելու։

Հաջող տառադարձումներն օգտագործում են ամբողջ պրոցեսի համար ընդհանուր Modality Bridge
LRU/TTL քեշը։ Բանալին համակցում է աուդիո հղումը, կայուն `audio-transcription`
գործողության պիտակը և ընտրված STT մոդելը․ ձախողումները երբեք չեն քեշավորվում։
Աուդիո փորձերը թարմացնում են ընդհանուր `bridged`, `cacheHits`, `failures` և
`lastUsedAt` հաշվիչները։ Փոխակերպված պատասխանները պարունակում են
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`․ անփոփոխ
հարցումները Audio Bridge հատված չեն ստանում։

Կատարման միջավայրի կարգավորումները պահվում են DB-ում և վավերացվում են Zod-ով․

| Բանալի                        | Լռելյայն | Միջակայք           |
| ----------------------------- | -------- | ------------------ |
| `modalityBridgeAudioEnabled`  | `true`   | —                  |
| `modalityBridgeAudioModel`    | `""`     | Ավտոմատ կամ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`  | 1000–300000        |
| `modalityBridgeAudioMaxClips` | `3`      | 1–10               |

Ընդհանուր քեշը շարունակում է կառավարվել `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes` և `modalityBridgeCacheMaxEntries` պարամետրերով։

### Տեսանյութի կամուրջ (`videoBridge.ts`, `videoBridgePipeline.ts`)

Ընդհատում է Chat Completions-ի `messages`-ում և Responses
API-ի `input`-ում վերին մակարդակի տեսանյութային մասերը՝ նախքան տեսանյութերի ներկառուցված
աջակցության հայտնի հնարավորություն չունեցող թիրախի կանչը։
Աջակցվող ձևաչափերն են `input_video`, `video_url`, `video_source`, HTTPS URL-ները

Տեքստային ֆոկուսը երբեք չի ենթադրում `start`/`end` և չի փոխում ժամանակային նմուշառիչը։

`segment_aware`-ն օգտագործում է մեկ սահմանափակ նախնական վերլուծության անցում՝ արդեն վավերացված տեղային տեսահոսքի նկատմամբ։ Ֆիքսված զտիչների շղթան նախ լայնությունը փոքրացնում է մինչև առավելագույնը 320 պիքսել, հայտնաբերում է տեսարանների փոփոխություններն ու սառեցված միջակայքերը, ապա մշուշվածությունը, միջին պայծառությունը և տարածական/ժամանակային տեղեկությունը գնահատելու համար նմուշառում է վայրկյանում 1 կադր հաճախականությամբ։ Անցումը սահմանափակված է 600 կառուցվածքային նմուշով, մեկ FFmpeg/զտիչ հոսքով, նույն՝ միայն `file` արձանագրության և կոնտեյներների թույլատրելի ցանկերով, պրոցեսի ելքի 1 MiB սահմանաչափով և բրոքերի ընդհանուր ընդհատման/վերջնաժամկետի ներսում առավելագույնը 30 վայրկյանով։ Այն հարցումից երբեք հրաման, զտիչ, ուղի կամ URL չի ընդունում։

Կառուցվածքային արժեքները դետերմինիստական նմուշառման վկայություններ են, ոչ թե տեսանյութի իմաստային ընկալում։ Դրանց միջոցով չեն որոշվում սուբյեկտները, գործողությունները, ենթագրերը, խոսքը կամ օգտատիրոջ մտադրությունը։ Տեսարանների և սառեցումների սահմանները կազմում են հատվածներ, իսկ սառեցման ընդգրկումը, մշուշվածությունը, լուսակայումը, տարածական մանրամասնությունը և ժամանակային փոփոխությունը միայն ազդում են այն բանի վրա, թե ինչպես է բաշխվում առկա 1–16 կադրի բյուջեն։ Լիովին սառեցված հատվածը սահմանափակվում է մեկ կադրով, մինչդեռ չսառեցված հատվածները մրցում են մնացած բյուջեի համար։ Երբ սահմանների քանակը գերազանցում է կադրերի քանակը, ժամանակագծի համաչափ ընդգրկումը պահպանվում է, որպեսզի սկզբի արագ անցումները չկարողանան թաքցնել երկար եզրափակիչ հատվածը։ Սառեցման սահմանից նախնական վերլուծության 1-վայրկյանանոց լուծաչափի սահմաններում գտնվող տեսարանների սահմանները միավորվում են։

Բացակայող զտիչների, սխալ ձևաչափված/դատարկ վկայությունների, հայտնաբերիչի սխալի կամ սահմանափակ նախնական վերլուծության ժամանակի սպառման դեպքում համակարգը բաց ռեժիմով վերադառնում է միջնակետերի ճշգրիտ համաչափ քաղաքականությանը։ Կանչողի ընդհատումը կամ բրոքերի վերջնաժամկետի լրանալը բաց ռեժիմով վերադարձ չի առաջացնում. այն դադարեցնում է ընթացիկ ենթապրոցեսը, կանխում կադրերի հետագա դուրսբերումը, իսկ մասնավոր ժամանակավոր ծառը հեռացվում է `finally`-ում։

`scripts/perf/video-bridge-fu07-eval.ts`-ը ստեղծում է դետերմինիստական իրական FFmpeg փորձանմուշներ՝ կրկնօրինակների հեռացումից հետո ենթագրավորման կանչերի խնայողության, խիտ շարժման դեպքում բյուջեի բաշխման, մշուշվածության/լուսակայման/SI-TI վկայությունների, երկար վերջնամասով արագ անցումների և աստիճանական մարումների կեղծ դրական արդյունքների համար։ Այն գրանցում է նախնական վերլուծության իրական տևողությունը և, երբ `/usr/bin/time`-ը հասանելի է, դուստր պրոցեսի CPU-ի օգտագործումն ու RSS-ի առավելագույն արժեքը։ Դրա որակի ստուգումները միայն կառուցվածքային չափանմուշներ են։ Իրական ենթագրավորման մոդելի որակը մնում է `HOLD`, քանի որ այս փորձարկման համակարգը չունի լիազորված վերջնակետ կամ սառեցված գնահատիչ։ Դրամական խնայողությունները նույնպես մնում են `HOLD`, եթե `--caption-cost-per-call-usd`-ը չի տրամադրում մեկ կանչի համար հստակ դրական ծախսի գնահատական. սկրիպտը երբեք չի հորինում այս արդյունքներից որևէ մեկը։

Յուրաքանչյուր կադր սահմանափակված է 4 MiB-ով, բոլոր չմշակված կադրերը միասին՝ 23 MiB-ով, իսկ բրոքերի սերիականացված պատասխանը՝ 32 MiB-ով։ Մասնավոր ժամանակավոր գրացուցակը հեռացվում է `finally`-ում։ OmniRoute-ը չի ներառում FFmpeg-ը և չի ընդունում գործարկվող ֆայլի անհատականացված ուղի։ Ենթագրավորումից առաջ կամուրջը կիրառում է պահպանողական տեսողական կրկնազատման անցում. յուրաքանչյուր JPEG փոքրացվում է մինչև 16×16 մոխրագույնի բուֆեր և համեմատվում է միայն վերջին պահպանված կադրի հետ։ Մեկ կադրից մեծ ենթագրավորման պահանջվող բյուջեի դեպքում դուրսբերումը տրամադրում է այդ բյուջեից առավելագույնը երկու անգամ մեծ, բայց երբեք 16 կադրը չգերազանցող թեկնածուների սահմանափակ հավաքածու։ Պահանջվող առավելագույնը կիրառվում է միայն կրկնազատումից հետո, իսկ երբ բյուջեն առնվազն երկու է, վերջնական նոսրացման ընթացքում պահպանվում են ընտրված առաջին և վերջին թեկնածուները։ Տարբերակավորված `grayscale-16x16-mean-cells-v2` քաղաքականությունն օգտագործում է միջին պայծառության տարբերությունից և այն մանրապատկերի բջիջների հարաբերակցությունից առավել մեծը, որոնց նորմալացված տարբերությունն առնվազն 0.05 է։ Կրկնօրինակի շեմը 0.04 հաստատունն է, որն ընտրվել է կանխատեսելիության համար, այլ ոչ թե որպես գործարկման ժամանակի կարգավորում հասանելի դարձնելու նպատակով։ Բարձր հակադրությամբ այս երկրորդային ազդանշանը պահպանում է փոքր շարժումներն ու տեսանելի տեքստի փոփոխությունները, որոնք միայն միջին արժեքի վրա հիմնված համեմատությունը կարող է թաքցնել։ Համեմատիչի կամ ապակոդավորիչի սխալների դեպքում համակարգը գործում է բաց ռեժիմով և պահպանում ընդգրկումը։ Ելքային մետատվյալներն առանձնացնում են դուրսբերված թեկնածուները, հաջողությամբ օգտագործված կադրերը և հեռացված տեսողական կրկնօրինակները։

Հստակ նշված տեսանյութի մասը կարող է պահանջել ժամանակադրոշմներով կոնտակտային թերթ։ Կամուրջը կառուցում է առավելագույնը 4 սյունակից և 16 կադրից կազմված JPEG ցանց։ 512-պիքսելանոց յուրաքանչյուր բջիջ իր աղբյուրի ժամանակադրոշմը տպում է բարձր հակադրությամբ ստորին շերտի վրա, մինչդեռ նույն ժամանակադրոշմները պահպանվում են տեքստային մետատվյալներում՝ հետագա կապակցման և աուդիտի համար։ Ամբողջական JPEG-ը շարունակում է սահմանափակված մնալ 32 MiB-ով։ Եթե `sharp`-ը չի կարող ապակոդավորել կամ կազմել ցանցը, կամուրջը վերադառնում է առանձին JPEG կադրերին, իսկ հաճախորդի ընդհատումը շարունակում է տարածվել թերթի գործողության միջով։

Առաջխաղացման վկայությունները միտումնավոր առանձնացված են սինթետիկ կազմման միկրոհենանիշից։ `scripts/perf/video-bridge-contact-sheet-eval.ts`-ը սահմանում է սխեմայի տարբերակով A/B փորձարկման համակարգ՝ իրական OpenAI-համատեղելի տեսողական մոդելների համար։ Այն չափում է մատակարարի հաղորդած թոքենները, ծայրից ծայր իրական ուշացումը՝ ներառյալ թերթի կազմումը, մոդելի կանչերի քանակը և մանիֆեստով սահմանված փաստերի պահպանումը։ Մոդելի չմշակված պատասխանները հաշվետվության մեջ չեն գրվում. պահպանվում են միայն SHA-256 ամփոփագրերը և համապատասխանեցված փաստերի ID-ները։ Փորձարկման համակարգը որևէ ցանցային կամ վճարովի մոդելի կանչ չի կատարում, եթե չի փոխանցվել `--execute-real`-ը և կարգավորված չեն `--model`-ը, `OMNIROUTE_BASE_URL`-ը և `OMNIROUTE_API_KEY`-ը։ Առանց այդ հստակ իրական գործարկման՝ դրա մեքենայաընթեռնելի վճիռը մնում է `HOLD`. միայն սինթետիկ օգտակար բեռի/կանչերի քանակի չափումները առաջխաղացման վկայություն չեն։

Կանչողները կարող են աջակցվող տեսանյութի մասին կցել կամընտիր `transcript.cues` զանգված, երբ արդեն ունեն համաժամեցված տեքստ։ Յուրաքանչյուր նշում պետք է պարունակի `text`, ստուգված տևողության ներսում գտնվող վերջավոր `start`/`end` միջակայք և թույլատրելի ցանկում ընդգրկված `source` (`client`, `embedded` կամ `audio-bridge`). `confidence`-ի լռելյայն արժեքը `1` է, և այն պետք է մնա `0`-ի ու `1`-ի միջև։ Ճշգրիտ կրկնվող նշումները միավորվում են։ OmniRoute-ը երբեք այս մետատվյալներից տառադարձում չի սկսում. վավերացված նշումները՝ աղբյուրով, վստահության արժեքով և միջակայքով, պատճենվում են նկարագրված արդյունքի մեջ և կադրերի ենթագրերի կողքին ցուցադրվում որպես անվստահելի դիտարկումներ։ Անվավեր, միջակայքից դուրս կամ ծագման տեղեկություն չունեցող տեքստը մերժվում է՝ ենթագրերի հոսքին խառնելու փոխարեն։ Հարցման մարմնի տառադարձման երկու ալիքներն էլ տրամադրված ծագումը նորմալացնում են որպես `client`, ներառյալ ինքնահայտարարված `embedded` կամ `audio-bridge` պիտակները։ Միայն սերվերին պատկանող ադապտերը կարող է այդ վստահելի պիտակները նշանակել միայն կոդի համար նախատեսված `trustedSource` արգումենտի միջոցով. հարցման JSON դաշտը չի կարող հասնել այդ արգումենտին։ Տառադարձման տեքստը շարունակում է մնալ մեդիայից ստացված անվստահելի բովանդակություն՝ անկախ դրա ծագումից, և երբեք չպետք է որոշի լիազորումը։

որը նաև նշում է տեքստը որպես մեդիայից ստացված անվստահելի դիտարկում և հաջորդող մոդելներին
հանձնարարում է չհետևել մեդիայում հայտնաբերված հրահանգներին։ Կադրերի մակագրությունների
քեշի բանալիները ներառում են JPEG բայթերը, հուշումը, ժամանակային նշիչը և գործող մոդելը.
քեշավորվում են միայն հաջողված մակագրությունները։ Քեշի գրառումները պահպանում են փաստացի
հաջողված արտադրող մոդելը՝ ներառյալ պահուստային մոդելը. երբ տարբեր կադրեր արտադրվել են
տարբեր մոդելներով, bridge-ը հաղորդում է `mixed`։ Քեշային համընկնումը կրկին օգտագործում է
այդ արտադրողի ինքնությունը՝ այն հարցված երթուղավորման պլանով վերապիտակավորելու փոխարեն։
Ամբողջ տեսանյութի արդյունքների քեշը բանալիավորվում է ելքը փոխող յուրաքանչյուր մուտքով՝
հուշմամբ, գործող մոդելով, նմուշառման քաղաքականությամբ, կադրերի քանակով, իմաստային
վերլուծության ռեժիմով, նորմալացված կենտրոնացման հուշման SHA-256 մատնահետքով,
կենտրոնացման պատուհանով, `transcript`-ով, `audioTranscript`-ով և կոնտակտային թերթի
դրոշակով, ուստի այդ չափումներից որևէ մեկի փոփոխությունը քեշի չհամընկնում է, այլ ոչ թե
հնացած արդյունքի վերօգտագործում։ Տեսողական ապակրկնօրինակման քաղաքականության տարբերակը,
շեմը և թեկնածու կադրերի սահմանափակված քանակը նույնպես բացահայտ ներառված են արդյունքների
քեշի բանալիում և մետատվյալներում. հետևաբար քաղաքականության փոփոխությունը չի կարող
վերօգտագործել ամբողջ տեսանյութի հնացած նկարագրություն։ Արդյունքների քեշի v4 մետատվյալները
պահում են ռեժիմն ու մատնահետքը, բայց երբեք՝ օգտատիրոջ չմշակված առաջադրանքը։ Պաշտպանական
մեխանիզմի մետատվյալները հայտնում են թե՛ հարցված, թե՛ գործող վերլուծության ռեժիմները.
օգտագործելի օգտատիրական տեքստի բացակայությամբ հարցված `focused` ռեժիմը ներկայացվում է
որպես փաստացի `full`։

Պաշտպանական մեխանիզմը դուրս է բերում տեսանյութի յուրաքանչյուր աջակցվող մաս, սակայն
նկարագրում է առավելագույնը `modalityBridgeVideoMaxVideos` հատ։ Այն թիրախի համար, որի
`supportsVideo === false` լինելն ապացուցված է, ձախողված և սահմանաչափը գերազանցող
տեսանյութերը դառնում են բացահայտ անվտանգ տեքստային նշիչներ, որպեսզի որևէ չմշակված
տեսանյութ չպահպանվի։ Երբ հնարավորությունը հայտնի չէ, այդ մասերը պահպանում են իրենց
տեսանյութային կրիչը. ցանկացած պահուստային վերծանում հետևում է վերոնշյալ սահմանափակված
տեքստային փոխակերպմանը։ `supportsVideo === true` ունեցող թիրախները շրջանցում են bridge-ը։
Հաճախորդի հարցման ընդհատման ազդանշանը տարածվում է ներբեռնման, broker-ի հերթի,
ենթագործընթացների և մակագրության կանչերի միջով. ընդհատումները կանգ են առնում տեսանյութերի
միջև և երբեք ձախողման դեպքում բաց չեն թողնում չմշակված մեդիան։

Կատարման միջավայրի կարգավորումները պահպանվում են DB-ում և վավերացվում են Zod-ով.

| Բանալի                              | Լռելյայն    | Միջակայք / վարքագիծ                                                                                                               |
| ----------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | Ընտրովի կատարման միջավայր, մասնակցությունը՝ ըստ ցանկության                                                                        |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full`-ը պահպանում է ընդհանուր ենթագրերը, իսկ `focused`-ն օգտագործում է սահմանափակ, անվստահելի՝ վերջին օգտատիրոջ համատեքստը       |
| `modalityBridgeVideoModel`          | `""`        | Ժառանգում է Vision Bridge մոդելը                                                                                                  |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                                                              |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`, `scene_aware` կամ համամասնական `segment_aware`. հայտնաբերիչի ձախողման դեպքում հետադարձ անցում է կատարվում `uniform`-ին |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                                               |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 մվ                                                                                                                    |

Նախկինում պահպանված՝ 120 վայրկյանից բարձր Video-ի ժամանակի սպառման արժեքները սահմանափակվում են
բրոքերի վերջնաժամկետով, իսկ այդ սահմանաչափից բարձր նոր կարգավորումների գրանցումները մերժվում են։
`GET /api/modality-bridge/video/runtime`-ը նույնականացումից կամ կատարման միջավայրի ստուգումից առաջ
պահանջում է վստահելի, դրոշմավորված loopback տեղայնություն, ապա պահանջում է կառավարման
նույնականացում։ Այն վերադարձնում է միայն `available`-ը, մաքրված FFmpeg/ffprobe տարբերակները և ֆիքսված
պատճառ, երբ կատարման միջավայրն անհասանելի է։ Ներքին արտահանման վերջնակետը
հանրային վերբեռնման API չէ. հերթի գերբեռնվածությունը վերադարձնում է `503`՝ `Retry-After`-ի հետ, կանչողի
անջատումը վերադարձնում է `499`, իսկ բրոքերի ֆիքսված վերջնաժամկետը՝ `504`։ Փոխակերպված պատասխանները կենտրոնական
`x-omniroute-modality-bridge` վերնագրին ավելացնում են
`video->text;model=<visionModel>;parts=<videos>`՝ առանց Vision կամ Audio հատվածները հեռացնելու։

### PII քողարկիչ (`piiMasker.ts`)

Գործարկվում է **երկու** փուլերում։

- **`preCall`**-ը կլոնավորում է օգտակար բեռը, շրջանցում `system`, `messages`, `input` և
  `prompt` դաշտերը (ներառյալ սովորական տողային տարրերը) և կիրառում `processPII()`-ն (`@/shared/utils/inputSanitizer`-ից)
  `content`/`text` տողային դաշտերի նկատմամբ։ Երբ
  `PII_REDACTION_ENABLED=true`, հայտնաբերված PII-ն խմբագրվում է ելքային
  օգտակար բեռում։ Սա կախված չէ `INPUT_SANITIZER_MODE`-ից (որը վերահսկում է միայն
  հուշումների ներարկման քաղաքականությունը)։ Երբ խմբագրումն անջատված է, կանչը գրանցում է հայտնաբերումների
  քանակը՝ առանց բովանդակությունը վերագրելու։
- **`postCall`**-ը խորը կլոնավորում է պատասխանը, գործարկում `sanitizePIIResponse()`-ը՝
  Responses API-ի կառուցվածքի քողարկիչի հետ միասին (`maskResponsesOutput` — ընդգրկում է
  `output_text` և `output[].content[].text`)։ Եթե որևէ խմբագրում է կատարվում,
  փոփոխված պատասխանը փոխարինում է բնօրինակին։

Պաշտպանիչ սահմանափակիչը երբեք չի արգելափակում. այն միայն նշումներ է ավելացնում (`meta.detections`,
`meta.redacted`) կամ վերագրում է։

### Հուշումների ներարկում (`promptInjection.ts`)

Հայտնաբերում է օգտատիրոջ տրամադրած բովանդակության հակազդող կառուցվածքները և կիրառում է
կարգավորված քաղաքականությունը։ Վարքագիծը որոշվում է միջավայրի փոփոխականներով և կոնստրուկտորի
ընտրանքներով.

| Կարգավորում      | Միջավայրի փոփոխական                                                                                        | Լռելյայն | Ազդեցություն                                                                                                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Միացված          | `INPUT_SANITIZER_ENABLED`                                                                                  | `true`   | Երբ `false` է, պաշտպանիչ սահմանափակիչը կարճ միացմամբ ավարտում է աշխատանքը։                                                                                                                                                   |
| Ռեժիմ            | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                            | `warn`   | Ներարկման քաղաքականություն՝ `block`, `warn` կամ `log`։ (`redact`-ն ընդունվում է հետադարձ համատեղելիության համար, բայց **չի** հեռացնում ներարկման տեքստը. հարցման PII-ի վերագրումը վերահսկվում է `PII_REDACTION_ENABLED`-ով։) |
| Արգելափակման շեմ | `blockThreshold` ընտրանք / `INPUT_SANITIZER_BLOCK_THRESHOLD` (այլանուն՝ `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`   | Արգելափակման համար պահանջվող նվազագույն խստությունը։ Լռելյայն դեպքում միջին մակարդակը նախատեսված է միայն դիտարկման համար։                                                                                                    |

**Ռեժիմի առաջնահերթություն** (`getMode`)՝ կանչողի `options.mode` →
`INJECTION_GUARD_MODE` **ՏԲ-ի գործառույթի դրոշակի գերակայում** (Dashboard → Settings →
Feature Flags) → `INJECTION_GUARD_MODE` միջավայրի փոփոխական → `INPUT_SANITIZER_MODE` միջավայրի փոփոխական →
`warn`։ Հետևաբար, կառավարման վահանակի գերակայումը գերակայում է միջավայրի փոփոխականներին, ուստի Feature
Flags միջերեսը կառավարում է գործող պաշտպանիչը իրական ժամանակում (առանց վերագործարկման)։ ՏԲ-ից ընթերցումը խափանումների նկատմամբ անվտանգ է.
եթե սխալ է առաջանում, պաշտպանիչը հետադարձ անցում է կատարում միջավայրի վրա հիմնված վարքագծին, իսկ երբ
գերակայում սահմանված չէ, վարքագիծը նույնական է միայն միջավայրի փոփոխականներով որոշվող տարբերակին։

Հայտնաբերման աղբյուրները.

1. `sanitizeRequest()`՝ `@/shared/utils/inputSanitizer`-ից (ընդհանուր հայտնաբերիչների
   հավաքածու, որն օգտագործվում է մշակման շղթայի այլ հատվածներում)։
2. Ներկառուցված `DEFAULT_GUARD_PATTERNS` (ներկայում՝ `system_override_inline` և
   `markdown_system_block`, երկուսն էլ՝ `high` խստությամբ)։
3. Կոնստրուկտորի ընտրանքների միջոցով փոխանցված կամընտիր `customPatterns` (տողեր, կանոնավոր արտահայտություններ
   կամ `{ name, pattern, severity }` գրառումներ)։

Երբ `mode === "block"` **և** առնվազն մեկ հայտնաբերում համապատասխանում է խստության
շեմին, `preCall`-ը վերադարձնում է `{ block: true, message: "Request rejected:
suspicious content detected" }`։ `warn`/`log` ռեժիմներում պաշտպանիչ շերտը գրանցում է դեպքը, բայց
թույլատրում է կանչը։ Համօգտագործվող `evaluatePromptInjection()` օժանդակ ֆունկցիան նույնպես արտահանվում է
այն կանչողների համար, որոնք պետք է գնահատեն հուշումները՝ առանց ռեեստրն օգտագործելու։

**Սկանավորման սահմանաչափ (v3.8.20).** հայտնաբերիչը ստուգում է միացված հուշման տեքստի միայն
**առաջին 16 KB-ը**՝ `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 բայթ)
`src/shared/utils/inputSanitizer.ts`-ում։ Թե՛ `detectInjection()`-ը, թե՛
`evaluatePromptInjection()`-ը կիրառում են `slice(0, MAX_INJECTION_SCAN_BYTES)`՝ նախքան
օրինաչափությունների ցիկլը գործարկելը։ Ներարկման հրահանգները սովորաբար գտնվում են մուտքային տվյալների սկզբի մոտ, ուստի սա
սահմանափակում է regex-ի CPU/GC ծախսը հարյուրավոր KB ծավալով ծանրաբեռնվածությունների դեպքում՝ առանց հայտնաբերման արդյունավետությունը նվազեցնելու (տես՝
#3932, #4041)։

### Հավատարմագրերի քողարկիչ (`credentialMasker.ts`)

Գործարկվում է **երկու** փուլերում էլ՝ լռելյայն շղթայում վերջինը (առաջնահերթություն՝ `95`)։ Քողարկում է
հայտնի API բանալիների / գաղտնի թոքենների օրինաչափությունները ելքային օգտակար բեռում (հաղորդագրության
բովանդակություն, գործիքի կանչի արգումենտներ, գործիքի արդյունքներ) **և** մատակարարի պատասխանում, որպեսզի
հուշման մեջ տեղադրված հավատարմագիրը (կամ գործիքի արդյունքով հետ վերադարձվածը) չարտահոսի
դեպի արտաքին մատակարար կամ հետ՝ հաճախորդին։

- **Միայն հստակ միացմամբ**, նույն սկզբունքով, ինչ PII-ի քողարկումը (կից Կոշտ կանոն #20-ին)․
  անջատված է, եթե `settings.credentialRedactionEnabled === true` **կամ**
  `CREDENTIAL_REDACTION_ENABLED=true` չէ։ Երբ այն անջատված է, պաշտպանիչ շերտը ոչինչ չի անում՝
  այն երբեք չի արգելափակում և երբեք չի վերագրում։
- `redactCredentials()`-ը շրջանցում է օգտակար բեռի/պատասխանի ամբողջ ծառը (`walkValue()`,
  պաշտպանված է prototype pollution-ից, ցիկլերից պաշտպանված է `WeakSet`-ի միջոցով) և համընկնումները փոխարինում է
  `[REDACTED:<type>]` տեղապահով՝ կլոնավորելով միայն փաստացի փոփոխված ճյուղերը։
- `CREDENTIAL_PATTERNS`-ը ներառում է LLM մատակարարների բանալիներ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS թոքեններ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), վճարային բանալիներ (Stripe, Square), ամպային
  բանալիներ (AWS մուտքի բանալի, Twilio, SendGrid, Mailgun), մասնավոր բանալիներ / JWT-ներ,
  հավատարմագրեր պարունակող կապի տողեր (`mongodb://user:pass@...` և այլն), ինչպես նաև
  ընդհանուր `Authorization`/`x-api-key`/`api-key`/`apikey` վերնագրի արժեքի
  օրինաչափություն։ Վերնագրի ձև ունեցող բանալիները (`authorization`, `x-api-key`, `api-key`,
  `apikey`) քողարկվում են կառուցվածքային եղանակով (միայն արժեքը, իսկ սխեմայի նախածանցը, օրինակ՝
  `Bearer `/`Basic `, պահպանվում է), ոչ թե ընդհանուր տեքստային regex-ի միջոցով։
- Պաշտպանիչ շերտը երբեք չի արգելափակում․ այն միայն վերագրում է (`modifiedPayload` /
  `modifiedResponse`) և ավելացնում է նշումներ (`meta.credentialsRedacted`, `meta.count`)։

Ռեգրեսիայի պաշտպանիչ թեստ՝ `tests/unit/credential-masker-guardrail.test.ts`։

## Հիմնական պայմանագիր (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true-ը անմիջապես դադարեցնում է շղթայի կատարումը
  message?: string; // ցուցադրվում է արգելափակման ժամանակ
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // վերադարձվում է preCall-ի կողմից՝ հարցումը վերագրելու համար
  modifiedResponse?: TValue; // վերադարձվում է postCall-ի կողմից՝ պատասխանը վերագրելու համար
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

Պաշտպանիչ սահմանափակումը ազդարարում է «փոփոխություն չկա»՝ վերադարձնելով կա՛մ `void`, կա՛մ `{}`, կա՛մ
`{ block: false }`։ `modifiedPayload`/`modifiedResponse` վերադարձնելը փոխարինում է
շղթայով դեպի հաջորդ պաշտպանիչ սահմանափակումներ փոխանցվող արժեքը։
`signal?: AbortSignal`-ը կանչողի կենսացիկլը փոխանցում է պաշտպանիչ սահմանափակումներին։ Հարցման ընդհատումը կանխամտածված fail-open բացառություն է․ մեդիա կամուրջները դադարեցնում են աշխատանքը և մաքրում ռեսուրսները՝ առանց չմշակված մեդիան վերականգնելու այն թիրախի համար, որը, ինչպես հայտնի է, չի աջակցում այն։

## Ռեեստր (`registry.ts`)

`guardrailRegistry` եզակի օրինակը տրամադրում է՝

- `register(guardrail)` — ավելացնում է պաշտպանիչ սահմանափակում (կամ փոխարինում է այն ըստ նորմալացված անվան) և
  վերադասավորում ըստ աճող `priority`-ի։
- `clear()` / `list()` — վարչական օժանդակ մեթոդներ։
- `runPreCallHooks(payload, context)` — հերթով մշակում է ակտիվ պաշտպանիչ սահմանափակումները, փոխանցում է
  payload-ը `modifiedPayload`-ի միջոցով և կանգ է առնում առաջին `block: true`-ի դեպքում։
- `runPostCallHooks(response, context)` — նույն հոսքը պատասխանի կողմում։
- `resetGuardrailsForTests({ registerDefaults })` — մաքրում է վիճակը և, ըստ անհրաժեշտության,
  վերագրանցում է լռելյայնները՝ թեստերի մաքուր մեկուսացման համար։

Երկու գործարկիչներն էլ վերադարձնում են `{ blocked, payload|response, results, guardrail?, message? }`,
որտեղ `results`-ը `GuardrailExecutionResult` գրառումների զանգված է, որոնք ներառում են
յուրաքանչյուր պաշտպանիչ սահմանափակման `blocked`, `skipped`, `modified`, `error` և `meta` դաշտերը,
որոնք օգտակար են հետագծման համար։

### Յուրաքանչյուր հարցման համար պաշտպանիչ սահմանափակումների անջատում

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })`-ը հավաքում է
պաշտպանիչ սահմանափակումների անունների կրկնազերծված ցանկ, որոնք պետք է բաց թողնվեն ընթացիկ
հարցման համար։ Աղբյուրները (բոլորն ընտրովի են, բոլորը միավորվում են)՝

- `apiKeyInfo.disabledGuardrails`
- Հարցման մարմնի `disabledGuardrails` (վերին մակարդակում)
- Հարցման մարմնի `metadata.disabledGuardrails`
- `x-omniroute-disabled-guardrails` վերնագիր (կամ հին
  `x-disabled-guardrails`)

Արժեքները կարող են լինել տողերի զանգվածներ կամ ստորակետերով բաժանված տող․ անունները
նորմալացվում են փոքրատառ kebab-case ձևաչափի (`pii_masker` → `pii-masker`)։ Արդյունքը
`context.disabledGuardrails`-ի միջոցով փոխանցվում է ռեեստրին, որը բաց է թողնում
համապատասխան պաշտպանիչ սահմանափակումները (`skipped: true`՝ `results`-ում)։

## Կատարման հերթականություն

`src/sse/handlers/chat.ts`-ով և
`open-sse/handlers/chatCore.ts`-ով անցնող յուրաքանչյուր հարցման համար՝

1. `resolveDisabledGuardrails(...)`-ը API բանալիից, հարցման մարմնից և
   վերնագրերից կազմում է բաց թողնման ցանկը։
2. `guardrailRegistry.runPreCallHooks(body, ctx)`-ը պաշտպանիչ սահմանափակումները գործարկում է
   առաջնահերթության աճման կարգով՝
   - Անջատված պաշտպանիչ սահմանափակումներն արձանագրվում են որպես `skipped`։
   - Յուրաքանչյուր պաշտպանիչ սահմանափակման `preCall`-ը կարող է վերագրել օգտակար բեռը՝ օգտագործելով `modifiedPayload`։
   - Առաջին `block: true`-ն անմիջապես ընդհատում է շղթան, և մշակիչը վերադարձնում է
     պաշտպանիչ սահմանափակման մերժման պատասխան։
3. Հնարավոր վերագրված օգտակար բեռը փոխանցվում է համակցված երթուղավորմանը և վերին հոսքի
   ուղարկմանը։
4. Պատասխանը կազմելուց հետո `guardrailRegistry.runPostCallHooks(...)`-ը
   պատասխանի վրա գործարկում է նույն շղթան։ Այստեղ `block: true`-ն հեռացնում է վերին հոսքի
   պատասխանը։

Սխալ արձակող պաշտպանիչ սահմանափակումներն արձանագրվում են `error: <message>`-ով և գրանցվում
`logger.warn`-ի միջոցով, սակայն շղթան շարունակվում է. նախագծմամբ կիրառվում է սխալի դեպքում թույլատրելու մոտեցումը։

## Կազմաձևում

Ներկառուցված պաշտպանիչ սահմանափակումների կողմից ընթերցվող միջավայրի փոփոխականները՝

| Փոփոխական                             | Օգտագործվում է             | Ազդեցություն                                                                                                                  |
| ------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`         | Հայտնաբերումն ամբողջությամբ անջատելու համար սահմանեք `false`։                                                                 |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`         | Ներարկման քաղաքականությունը՝ `warn`, `block` կամ `log`։ Հնացած `redact` արժեքը չի վերագրում ներարկման տեքստը։                 |
| `INJECTION_GUARD_MODE`                | `prompt-injection`         | Ներարկման պաշտպանիչի ռեժիմը. նաև ՏԲ-ի գործառույթի դրոշակ է, որը **գերակայում է** միջավայրի փոփոխականների նկատմամբ (DB > ENV)։ |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`         | Նվազագույն խստությունը, որը մերժվում է `MODE=block`-ի դեպքում՝ `high` (լռելյայն), `medium` կամ `low`։                         |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`         | `INPUT_SANITIZER_BLOCK_THRESHOLD`-ի հնացած այլանունը։                                                                         |
| `PII_REDACTION_ENABLED`               | `pii-masker`               | Երբ `true` է, հարցման PII-ը քողարկվում է՝ անկախ ներարկման ռեժիմից։                                                            |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ներքևի հոսք) | Կառավարում է պատասխանի կողմում քողարկիչի վարքագիծը։                                                                           |

Մոդալության կամրջի պաշտպանիչ սահմանափակումները կատարման ժամանակի կազմաձևումն ընթերցում են ՏԲ-ով ապահովվող կարգավորումների
պահոցից (`getSettings()`), ոչ թե միջավայրի փոփոխականներից։ Պատկերի մշակման հիմնական բանալիներն են՝
`modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`,
`modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`,
`modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`,
`modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`,
`modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` և
`modalityBridgeCacheMaxEntries`։ Հնացած
`visionBridge*` բանալիներն ընդունվում են միայն որպես փաստաթղթավորված՝ մեկ ցիկլի ընթերցման
պահուստային տարբերակ. կառավարման վահանակից գրանցումները կիրառում են հիմնական բանալիները։ Լռելյայն արժեքները և պահուստային
լուծիչը գտնվում են `src/shared/constants/modalityBridgeDefaults.ts`-ում, իսկ հնացած
հաստատունները պահպանվում են `src/shared/constants/visionBridgeDefaults.ts`-ում։

Ձայնի մշակումն օգտագործում է `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`,
`modalityBridgeAudioTimeout` և `modalityBridgeAudioMaxClips`, ինչպես նաև ընդհանուր
`modalityBridgeCache*` կարգավորումները։ Ձայնի մշակման համար հնացած բանալիների պահուստային տարբերակ չկա, քանի որ այս
բանալիները ներդրվել են Մոդալության կամրջի սխեմայի հետ։

Տեսանյութի մշակումն օգտագործում է `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`,
`modalityBridgeVideoModel`,
`modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`,
`modalityBridgeVideoMaxVideos` և
`modalityBridgeVideoTimeout`, ինչպես նաև ընդհանուր `modalityBridgeCache*` կարգավորումները։
Այն լռելյայն անջատված է, քանի որ FFmpeg/ffprobe-ը ոչ պարտադիր գործառնական
կախվածություններ են, իսկ կադրերի նկարագրությունների ստեղծումն ավելացնում է ուշացումն ու մոդելի օգտագործման արժեքը։

## Հատուկ պաշտպանիչ կանոններ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

Քայլեր՝

1. Ստեղծեք `src/lib/guardrails/myGuardrail.ts`՝ ընդլայնելով `BaseGuardrail`-ը։
2. Իրագործեք `preCall`-ը և/կամ `postCall`-ը։
3. Կամ գրանցեք ներմուծման պահին (`registerDefaultGuardrails`-ից ավելացնելով), կամ
   գործարկման ընթացքում կանչեք `guardrailRegistry.register(...)`-ը․ ռեեստրը փոխարինում է
   նույն նորմալացված անունն ունեցող ցանկացած նախորդ պաշտպանիչ կանոն։
4. Ավելացրեք թեստեր `tests/unit/`-ում (առկա օրինակներ՝
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`)։

## Թեստավորում

Թեստերի միջև օգտագործեք `resetGuardrailsForTests()`՝ հայտնի վիճակից սկսելու համար։
Փոխանցեք `{ registerDefaults: false }`՝ դատարկ ռեեստրից սկսելու և
միայն թեստավորվող պաշտպանիչ կանոնները գրանցելու համար։ Vision Bridge-ն աջակցում է կախվածությունների
ներմուծմանը (`deps.getSettings`, `deps.callVisionModel`), իսկ Audio Bridge-ը տրամադրում է
համարժեք միջերեսներ՝ կարգավորումների, հնարավորությունների, STT մոդելի ընտրության, հավատարմագրերի
ստուգումների և տրանսկրիպցիայի համար։ Հետևաբար, թեստերը կարող են ստուգել երկու հոսքերն էլ՝ առանց DB-ի
կամ ցանցային հասանելիության։

- `src/shared/constants/modalityBridgeDefaults.ts` — Vision/Audio-ի ընդհանուր գործարկման միջավայրի լռելյայն արժեքները

## Ներարկման պաշտպանիչ կանոնով երթուղիների ծածկույթ և red-team թեստավորում (Փուլ 8 · Բլոկ D)

Ներարկման պաշտպանիչ կանոնը (`createInjectionGuard` / `withInjectionGuard`) ընդգրկում է օգտատիրոջ հուշումներ
ընդունող բոլոր երթուղիները։ Այն հաշվի է առնում `INJECTION_GUARD_MODE`-ը (լռելյայն՝ `warn` = միայն գրանցել մատյանում,
`block` = վերադարձնում է HTTP 400 `SECURITY_001`)։

| Տեսակ        | Երթուղիներ                                                                                                                                           | Լռելյայն ռեժիմ |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Տեքստ (առկա) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn           |
| Գեներատիվ    | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn           |
| Տվյալներ     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn           |

Տեքստի արտաբերումը (`extractMessageContents`) ներառում է `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`։

**Red-team (ամեն գիշեր, `nightly-llm-security.yml`)․** promptfoo-ն ստուգում է, որ յուրաքանչյուր երթուղի արգելափակում է
OWASP-LLM կորպուսը `INJECTION_GUARD_MODE=block` ռեժիմում, իսկ garak-ը կատարում է ստուգումներ (գաղտնիքի բացակայության դեպքում՝ բաց է թողնում)։
`moderations`-ը ներառված է հետևողականության համար․ արգելափակման ռեժիմն օգտագործող օպերատորները կարող են այն բացառել
`resolveDisabledGuardrails`-ի միջոցով։

Գիշերային աշխատանքային հոսքը (`.github/workflows/nightly-llm-security.yml`, cron + ձեռքով
գործարկում) ունի երկու առաջադրանք՝

- **`promptfoo-guard` (արգելափակող)** — գործարկում է `promptfoo eval -c promptfooconfig.yaml`-ը
  `INJECTION_GUARD_MODE=block`-ով։ Յուրաքանչյուր հակառակորդային դեպք (օրինակ՝ «անտեսիր բոլոր
  նախորդ հրահանգները…», DAN ոճի jailbreak-ներ) հաստատում է, որ պատասխանը պարունակում է
  `error.code === "SECURITY_001"`, այսինքն՝ պաշտպանիչ կանոնն իսկապես մերժել է հարցումը։
- **`garak` (խորհրդատվական)** — գործարկում է garak-ը `--probes promptinject,dan,leakreplay`-ով
  տեղային OmniRoute օրինակի (`http://localhost:20128/v1`) նկատմամբ։ Պայմանավորված է
  մատակարարի գաղտնիքի (`PROMPTFOO_PROVIDER_KEY`) առկայությամբ․ դրա բացակայության դեպքում առանց սխալի բաց է թողնվում և վերջում
  ունի `|| true`, ուստի այն հաշվետվություն է ներկայացնում՝ առանց CI-ն ձախողելու։

Պաշտպանիչ օգնականի (`createInjectionGuard` / `withInjectionGuard`)
ծածկույթը տարածվում է հուշում պարունակող յուրաքանչյուր `/v1` երթուղու վրա․ հուշման տեքստը վերցվում է
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` դաշտերից՝
`src/shared/utils/inputSanitizer.ts`-ի `extractMessageContents()`-ի միջոցով։
