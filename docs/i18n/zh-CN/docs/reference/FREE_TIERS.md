## TL;DR — OmniRoute 实际汇总了多少免费推理额度？

这些数字代表整个目录中不同的第三方账户和资格条件。OmniRoute 不会授予这些额度：你必须获取所需的账户或凭据、连接符合条件的提供者，并遵守其限制。实际可用容量可能更低，包括在全新安装且没有可用路由时为零。标记为 `tos: avoid` 的提供者默认不会参与自动路由。

## 两种机制——统计与判定

OmniRoute 通过两种有意读取不同来源的机制来回答“它是否免费？”：

| 机制            | 事实来源                                                                                                                                             | 适用界面                                                                                              |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **统计 / 展示** | 解析后的目录——由 Radar 源叠加更新的随附基线目录（`getRadarCatalog`）                                                                                 | 免费层级总量、预算卡片、仪表板                                                                        |
| **判定**        | 仅使用随附目录（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`）以及本地启发式规则（`:free` 后缀、零定价、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用方：模型导入、`auto/*` 路由、`GET /v1/models` 和浏览器预览 |

只要有可用的数据源，统计结果就可以得到改进。判定则始终基于发布制品，因此浏览器与服务器上的答案完全一致，可离线复现，也能在没有数据库的情况下进行测试。如果让浏览器预览读取一个来源，而服务器导入读取另一个来源，就会导致预览结果与点击后实际发生的情况不一致——这种拆分是有意保留的。

## 方法与注意事项

- 这些数字是根据各提供者截至 **2026-06-17** 公布的免费层级限制，通过网络调研得出的**上限估算值**。免费层级经常变化——在依赖某个数字之前，请重新核实。
- **条目实际保证的内容。** 没有任何条目带有逐行置信度评级，API 也不会提供此类评级——应将上述每个数字都视为质量相同但未明确说明的估算值。不过，有两类事实有所不同，因为它们是人工整理的，而非推断得出：44 个条目带有独立记录的硬性停止保证（其中 39 个是 xKiro 条目，它们共用同一个每日限额），另有 13 个条目带有提示词训练披露。仅当提供者自己的条款明确说明超出免费限额后会拒绝请求，而不是在不提示的情况下开始计费时，才会设置 `hardStopGuaranteed`；来源会写在该条目旁边的注释中。该字段绝不会默认为 `true`，无人核实的条目会保持未设置状态。因此，缺少硬性停止标记表示“尚未证实”，而不是“已知会向你收费”。**STRICT 模式**（选择启用的 `freeAccessPolicy=strict` 路由保护机制）只信任带有该标记的条目；其他所有免费层级都会以 `no-hard-stop` 为由被排除（参见 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。当该保护机制过滤候选池时，面向运营人员的日志会同时报告排除数量及其中 `no-hard-stop` 所占比例。
- `estMonthlyFreeTokens` = 仅计算每月重复提供的 token。**一次性注册赠金不会重复发放**，因此按 0 计算。已停止的层级也按 0 计算。
- 每日 token 上限 → `monthly = daily × 30`。如果仅记录了 RPD → `RPD × ~800 个输出 token × 30`。如果仅有 RPM/TPM（没有每日上限）→ **无上限**（见下文）。
- **永久免费，但未公布 token 上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：这些是真实存在、持续提供的免费访问，但受到速率或并发限制。我们将其归类为 `recurring-uncapped`，并且**绝不计入总和**——用 `RPM × 24/7 × 30d` 计算会产生不切实际的理论上限（这正是我们拒绝采用的夸大方式）。列出它们只是为了让你知道其存在。
- **充值解锁提升：** 一次性进行少量充值，即可永久提高免费配额（OpenRouter：$10 → 1000 次请求/天 ≈ 每月增加 24M）。该数字单独报告，不计入稳定额度的主要统计数字。
- **受资格限制的配额**（`eligibilityGate: "regional-identity"`）：只有通过与地区绑定的身份验证后才会开放的真实持续配额（目前为中国大陆实名认证）。按照相同的池去重规则计入单独的数字（`gatedRecurringTokens`），绝不会计入稳定额度的主要统计数字。其机制（`freeType`）保持不变，因此路由行为也保持不变。
- **证据类别。** 规则是：目录中的数字必须在条目旁边的 `// evidence:` 注释中引用其来源——`public-page`（任何人都可以访问的提供者页面）、`api-public`（提供者无需身份验证即可访问的端点，例如 NaraRouter 位于 router.bynara.id 的公开套餐端点），或 `console-verified <date> por <who>`（该数字只能在账户控制台内看到；注释会记录查看者、查看时间，以及说明该上限存在的公开页面）。目前的状态是：在 2026-09-02 重新审核的五个区块带有此注释（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早于 2026-09-02 重新审核的条目会沿用此前的调研结果，直至它们被修改；任何**新增或变更**的数字如果没有证据注释，都属于缺陷。目前只有 `mistral` 经过控制台验证。

## 为什么我们的数字小于其他聚合器的数字

这一领域中大多数“每月免费 token”数字都是各模型标注额度的总和。我们特意没有这样计算：

- **每个共享额度池只计算一次。** Mistral 的免费计划是每个组织每月共享 1B 的额度；将它列在五个模型下并不会使其变成 5B。若按模型累加，我们自己的目录会显示为 **~7.4B**（于 2026-09-03 重新计算；此数字不受 CI 检查约束——每当目录发生变化时都应重新测算）——标题显示 **~1.47B**，因为这才是分别拥有每个提供者一个账户时实际可以使用的额度。
- **每日上限会换算，速率限制不会。** 有文档说明的 tokens/day 上限按 `× 30` 换算；有文档说明的 requests/day 上限按 `RPD × ~800 tokens × 30` 换算；如果提供者仅公布 requests-per-minute，则**不提供**月度数字，并将其列为_无上限_，绝不计入总和。将速率限制按 24/7 全天候使用进行换算，正是我们拒绝采用的夸大方式。
- **需要地区身份验证才能获得的配额会单独列出**（`+~6M behind regional identity verification`），因为大多数读者无法使用这些配额。
- **注册赠金仅适用于首月**，并作为第二个数字报告，绝不会混入稳定的月度数字中。
- **该数字由 CI 强制校验。** `npm run check:docs-counts` 会根据目录重新计算总额；当此文件、README 或预算卡片中的数字与计算结果不一致时，构建将失败。

## OpenCode 免费版：客户端契约限制（#14313）

无密钥的 `opencode` 提供者（公共端点 `https://opencode.ai/zen/v1`）会拒绝任何不符合 OpenCode 客户端契约的请求，并返回 **403 `FreeTierError`** 以及提示语 _“OpenCode 的免费层级只能在 OpenCode 内部使用”_。这是针对请求的拒绝（对于相同的请求结构，每个账户都会得到相同的判定），而不是模型封禁或连接冷却——OmniRoute 将其分类为 `project_route_error`，跳过模型锁定/冷却，并且（在合成的 `noauth` 路径上）在较短的 TTL 内暂停自动组合的重新选择。发送请求时需携带非空工具列表、`stream: true` 以及 OpenCode 会话/UA 标头（`opencodeFreeTierContract.ts`），否则会收到 403。

## 术语表

| 术语                | 含义                                                       |
| ------------------- | ---------------------------------------------------------- |
| **RPM / RPD / RPH** | 每分钟 / 每天 / 每小时的请求数                             |
| **TPM / TPD**       | 每分钟 / 每天的 token 数                                   |
| **明确记录的配额**  | 提供者公布的明确每日/每月 token 上限（可作为可靠预算依据） |
| **理论上限**        | `rate-limit × 24/7 × 30d`——最大值，而非授予的预算          |
| **Neuron**          | Cloudflare 计算单元（约等于 1 个输出 token）               |

> 根据 2026-06-05 针对各提供者的研究生成。请重新运行研究工作流（参见 `_tasks/features-v3.8.12`）以刷新。
