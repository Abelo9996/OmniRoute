## 兩種機制——計數與判定

OmniRoute 透過兩種刻意讀取不同來源的機制，回答「它是否免費？」：

| 機制           | 真實資料來源                                                                                                                                               | 適用介面                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **計數／顯示** | 解析後的目錄——以隨附的基準資料疊加 Radar feed（`getRadarCatalog`）                                                                                         | 免費方案總量、預算卡片、儀表板                                                                           |
| **判定**       | 僅使用隨附的目錄（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`），再加上本機啟發式規則（`:free` 後綴、零定價、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用端：模型匯入、`auto/*` 路由、`GET /v1/models`，以及瀏覽器預覽 |

只要 feed 可用，計數結果便能隨之改善。判定則固定依據發布成品，因此瀏覽器與伺服器上的答案完全一致、可離線重現，也能在沒有資料庫的情況下測試。若讓瀏覽器預覽讀取某個來源，伺服器匯入卻讀取另一個來源，就會造成預覽結果與點擊後的實際行為不一致——這項區隔是刻意保留的。

## 方法與注意事項

- 這些數字是根據截至 **2026-06-17** 各提供者所記載的免費方案限制，透過網路研究得出的**上限估計值**。免費方案經常變動——依賴任何數字前，請重新驗證。
- **每個項目實際保證的內容。** 任何項目都沒有逐列的信賴度評級，API 也不提供此資訊——請將以上每個數字都視為品質相同但未明示的估計值。有兩類事實不同，因為它們是人工整理，而非推斷得出：44 個項目具有獨立記載的硬性停止機制（其中 39 個是 xKiro 項目，皆共用同一每日額度），另有 13 個項目附有提示詞訓練揭露。只有當提供者自身條款表明，超出免費額度時會拒絕請求，而非悄悄開始計費，才會設定 `hardStopGuaranteed`；來源會寫在項目旁的註解中。此欄位絕不會預設為 `true`，尚未經任何人驗證的項目會維持未設定狀態。因此，缺少硬性停止旗標表示「尚未證實」，而不是「已知會向你收費」。**STRICT 模式**（選用的 `freeAccessPolicy=strict` 路由防護）只信任帶有此旗標的項目；其他所有免費方案都會以 `no-hard-stop` 為由排除（請參閱 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。當此防護機制篩選資源池時，操作人員可見的日誌會同時回報排除數量，以及其中 `no-hard-stop` 所占的比例。
- `estMonthlyFreeTokens` = 僅計算每月週期性提供的 token。**一次性註冊點數不會重複提供**，因此計為 0。已停止的方案也計為 0。
- 每日 token 上限 → `monthly = daily × 30`。若僅記載 RPD → `RPD × ~800 output tokens × 30`。若僅有 RPM/TPM（沒有每日上限）→ **無上限**（見下文）。
- **永久免費，但未公布 token 上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：這些確實是持續提供的免費存取，但受速率／並行限制。我們將其分類為 `recurring-uncapped`，而且**絕不將其加總**——以 `RPM × 24/7 × 30d` 相乘只會產生不切實際的理論上限（我們拒絕這種膨脹算法）。列出它們是為了讓你知道這些方案確實存在。
- **儲值解鎖加成：**一次性的小額儲值，可永久提高免費額度（OpenRouter：$10 → 1000 req/day ≈ +24M/mo）。此數字會單獨回報，不計入穩定額度的主要數字。
- **資格限制額度**（`eligibilityGate: "regional-identity"`）：確實存在的週期性額度，但只有完成地區限定的身分驗證後才能啟用（目前為中國大陸實名認證）。採用相同的資源池去重規則，計入單獨的數字（`gatedRecurringTokens`），絕不計入穩定額度的主要數字。其機制（`freeType`）維持不變，因此路由行為也不變。
- **證據類別。** 規則如下：目錄中的數字必須在項目旁的 `// evidence:` 註解中引用其來源——`public-page`（任何人都能閱讀的提供者頁面）、`api-public`（提供者不需驗證即可存取的端點，例如 NaraRouter 位於 router.bynara.id 的公開方案端點），或 `console-verified <date> por <who>`（該數字只能在帳戶主控台內看到；註解會記錄查看者及查看日期，並附上說明此上限存在的公開頁面）。目前狀態：於 2026-09-02 重新稽核的五個區塊都帶有此資訊（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早於 2026-09-02 重新稽核的項目，在下次修改前會沿用先前的研究結果；任何**新增或變更**的數字若沒有證據註解，即屬錯誤。目前只有 `mistral` 經過主控台驗證。

## 為什麼我們的數字比其他彙整平台小

這個領域中大多數「每月免費 token」的數字，都是將各模型標示的額度加總而得。我們刻意不這麼做：

- **每個共用額度池只計算一次。** Mistral 的免費方案是每個組織每月共用 1B 額度；將它列在五個模型下並不會使其變成 5B。若按模型加總，我們自己的目錄會顯示為 **~7.4B**（於 2026-09-03 重新計算；此數字不受 CI 閘門控管——每當目錄變更時都應重新測量）——標題顯示 **~1.47B**，因為這才是各提供者的一個帳號實際可以使用的額度。
- **每日上限會換算，速率限制則不會。** 有文件記載的每日 token 上限會換算為 `× 30`；有文件記載的每日請求上限會換算為 `RPD × ~800 tokens × 30`；若提供者只公布每分鐘請求數，則**不會**提供每月數字，並會列為_無上限_，絕不納入加總。將速率限制乘以 24/7，正是我們拒絕採用的灌水方式。
- **需要通過地區身分驗證才能取得的額度會分開顯示**（`+~6M behind regional identity verification`），因為大多數讀者無法使用這些額度。
- **註冊贈送額度僅適用於第一個月**，並會以第二個數字另行呈現，絕不混入穩定的常態數字中。
- **此數字由 CI 強制驗證。** `npm run check:docs-counts` 會根據目錄重新計算總額；當本檔案、README 或預算卡片中的數字與計算結果不一致時，建置便會失敗。

## OpenCode Free：用戶端合約限制（#14313）

無金鑰的 `opencode` 提供者（公開的 `https://opencode.ai/zen/v1`）會拒絕任何不符合 OpenCode 用戶端合約的請求，並傳回 **403 `FreeTierError`** 以及 _「OpenCode 的免費方案只能在 OpenCode 內使用」_ 這段訊息。這是針對請求範圍的拒絕（對於相同的請求格式，每個帳戶都會得到相同判定），而非模型封鎖或連線冷卻——OmniRoute 會將其分類為 `project_route_error`、略過模型鎖定／冷卻，並且（在合成的 `noauth` 路徑上）暫停自動組合的重新選擇一小段 TTL。請傳送包含非空白工具清單、`stream: true`，以及 OpenCode 工作階段／UA 標頭（`opencodeFreeTierContract.ts`）的請求，否則預期會收到 403。

## 詞彙表

| 術語                | 含義                                                          |
| ------------------- | ------------------------------------------------------------- |
| **RPM / RPD / RPH** | 每分鐘／每日／每小時的請求數                                  |
| **TPM / TPD**       | 每分鐘／每日的 Token 數                                       |
| **明文授予額度**    | 提供者公布明確的每日／每月 Token 上限（可作為合理依據的預算） |
| **理論上限**        | `rate-limit × 24/7 × 30d` — 最大值，而非授予的預算            |
| **Neuron**          | Cloudflare 運算單位（約等於 1 個輸出 Token）                  |

> 根據 2026-06-05 針對各提供者的研究產生。若要更新，請重新執行研究工作流程（請參閱 `_tasks/features-v3.8.12`）。
